# 章节与场景设计工作台（C-06）

把一章当成"入场状态 → 行动／观察／交流 → 离场状态"的单位来设计、诊断和修订。有效变化可以是事件、关系、道德责任、期待、读者所知或意象的重复与变形，不必然是追逐、打斗或硬反转。

## 1. 何时触发／何时不要触发

**触发**（任意一条成立即可进入）：

- 要新建一章、一节、几个场景或一份章纲；需要在"这一章断在哪里"上做决定。
- 手上已有章节文字，用户想问它为什么慢、为什么空、为什么转换生硬、为什么读起来像说明书。
- 用户给出"我想改这个场景"并提供了至少一段正文或明确的改动意图。
- 用户问某条写作惯例（"长谈要不要删""每章要不要留悬念""必须要有反派吗"）在本场景里是否适用。

**负触发**（不要接管，转对应工具或直接说明）：

- 纯语法、标点、用词校对 → 语言精修类任务，本 Skill 不做逐句润色。
- 整本书的题材定位、卷数规划、商业连载节奏 → 长篇规划类任务。
- 非叙事文本（说明书、论文、报告）的结构重排。
- 要求把五幕、三幕、梵剧五要素、64 个转接分支当作必须齐备的清单——本 Skill 明确拒绝；来源自己也说这类分类"没有实质价值"（PG74314 L10870-10871）。
- 用户只要"把这段字幕式对白改成 xx 作家的味道"而没有给出"要达成什么效果"——先按 §4 的 INPUT_MISSING 出口处理。
- 现实技术、医学、法务事实的准确性核查。

## 2. 输入契约

**必备（缺一即走 §4 的 INPUT_MISSING）**：

1. 媒介与体裁：小说章 / 剧本场 / 其他叙事；目标读者体验的一句话描述。
2. 要我做的动作：`设计` / `诊断` / `改写`（改写还必须给授权范围）。
3. 本单位的边界：这一章（场）从哪里开始、到哪里结束，或在整本书里的位置。

**强建议提供**（没有就按 §4 的降级路径走）：涉及的人物与其目标、视角限制、上一场结束时发生的事、World rules 与禁改条件、现有正文或概要。

**不能自己补的东西**：未给正文时，不得声称"已逐行诊断"；未给目标时，不得替作者决定主题、结局或价值判断。

## 4. 执行步骤（按序，不许跳）

1. **先判输入**：对照 §2。缺项 → 立即输出 `INPUT_MISSING` 与需要补充的清单，**不得**先生成一堆"可能是你的第 3 章有问题"的猜测。
2. **跑 S0（效果优先）**：问"这一章要的效果是什么、现在达没达成"。来源给了硬依据：Bernhardt 的 Camille 效果极强而"手段明显不合艺术"，《李尔王》"作为剧作技艺是很差的实例，其效果却正是它追求的效果"（PG63188 L381-385）。效果已达成且读者侧无异常 → 输出"保留，记录为有意破例"，到此为止；只有效果没达成才进入第 3 步。禁止输出"违反规则 X，因此必须改"。
3. **定单位边界**：这一章（场）解决什么约束——时空跳换、信息量、阅读喘息，还是一次完整行动？来源证据：幕／场划分的用途就是"便于处理情节、换景的急需，以及给观众宜人的喘息"（PG32433 L157-161）；形式往往是制作约束的解（PG76555 L7442-7452）。断在这里说不出理由 → 边界本身就该重定。
4. **写场景卡**：按 `references/scene-design.md` 的 S1–S4 逐项填。填不出"入场／离场差值"、也填不出它引发的下一场依赖时，标记为待定而不是硬编一个反转。
5. **排信息**：按 S5 填三列知情关系；按 S6 给每组对白过三关；按 S6a 给每个描写细节标功能。
6. **接上一章与下一章**：按 S8 出章链表；按 S9 选章末出口并给出第二种候选。
7. **出稿或出诊断**：对我写的样例必须标 `DESIGN_EXAMPLE`；对用户的稿给出修订 A/B 两版并写明各自损失。
8. **收尾核对自己**：每个结论后面要能追到来源编号与行号（格式 `PGxxxxx Lxxxx-xxxx`）、或标 H/P、或标 NOT_PROVEN。三样都没有的话，这句话不许写在输出里。

## 5. 输出合同

**场景卡**（每个场景一份）：ID｜时间/地点/POV｜入场条件｜目标或观察对象｜约束来源（不必是人物）｜行动与代价｜新信息与视角限制｜离场状态差（六个维度中哪一项变了）｜下一场依赖｜证据等级（F 行号 / H / P / NOT_PROVEN）。

**章链表**（多章任务必出）：章节｜前章已承诺｜本章兑现与转移｜仍悬置并计划在哪章回收｜时空与视角桥｜下章因此受到的事件约束。每一次跳接都要能说出它依赖哪条可见因果、或明确标注这是本作契约（超现实/梦境/非线性）。

**诊断表**：文本定位（无正文写"缺稿"）｜观察到的症状｜可能机制 A/B｜各自的 F 依据或 H 标记｜修订 A/B｜各自会失去的气氛与伏笔｜必须由作者裁决的点｜退出码。

**修改样例**：必须带 `DESIGN_EXAMPLE` 标记。凡与原稿比较，必须写清改动前后哪一项状态变了，并且不得把我自己生成的虚构案例说成原文证据。

## 7. 失败出口

- 输入不够 → `INPUT_MISSING` + 明确列出要补什么。
- 多种处理都能达成目标，需要作者用自己的价值取舍拍板 → `AUTHOR_DECISION` + 选项与差异。
- 想用古典戏剧形式推断散文小说的效果 → `NOT_PROVEN` + 说明缺的是什么类型的证据。
- 用户只授权静态建议 → 出文本，不写文件。
- 出现"所有章都必须这样写"式的普遍化要求，或要求把一部作品的具体处理当通则 → 拒答该普遍化，改给出适用范围与成立条件。
- 引用规则时写不出来源编号+行号、也不肯标 H/P 的，按未支持内容处理，从输出里删掉。

## 8. 边界声明

本 Skill 的九本来源全部是戏剧研究与剧评，没有一个字是关于"如何写网络小说/类型小说"的。所有可执行的写作动作都由本 Skill 从 F 观察类比或推导而来，因此：

- 来源里的舞台实例只能说明"在这个演出条件下成立"，迁移到散文前必须重新识别约束（`references/conflicts-and-exceptions.md` 的 K6）。
- 任何"读者会更投入／更紧张／更想翻页"的判断都要带 NOT_PROVEN 标签；本地 P4 自检不是读者实验，也不是 P5 宿主验证。
- 用 `examples/worked-example.md` 走一遍正常输入与边界输入，确认每个分支都真的能落地。
