# 工作流实跑：全部为虚构 DESIGN_EXAMPLE，非 PG 原文

本文件的作用是让一个只读本 Skill 的 Agent 能自检"我到底该怎么走"。三个用例分别对应：正常输入、边界输入（缺稿且目标不明）、负触发（把历史戏剧格式当通则）。

---

## 用例 1｜正常输入：灯塔停电的三个场景

**用户输入**："第一人称港口报务员，深夜灯塔停电、同事失踪；想写惊疑但不揭示怪物；设计三场景及章末分支，勿改原文。"

输入检查（§2）：媒介（第一人称小说）、动作（设计）、边界（一个章、三场景）齐备 → 进入。
**做法不是历史 Skill 那样从 S1 开始**，而是先过 S0。

1. **S0 效果优先**：要的效果是"惊疑但不解释"。虚构样例：场景 C 里主角始终没有确认回声来自谁——这在"必须有明确状态差"的读法下像缺陷，但它正是用户要的效果。 → 判定为**有意破例并保留**，不因任何后续规则把它改成"看清海怪"。
2. **S1 入/离状态**：入场时主角认为只是例行检修；离场时他怀疑同事留下的报警时间异常。读者所知从"困惑"到"警惕"，但不知道同事去向。六个维度里变的是**读者所知**与**期待**——不是在胜负维度上。合要求。
3. **S2 约束**：此处的压力不是人，而是雾（空间）、沟通失效（制度/技术条件）、以及"必须先恢复信号才能去找人"的承诺顺序。按 PG43490 L2136-2138 那类"背景即施压者"的用法，不虚拟一个反派。
4. **场景卡**：

| 场／POV | 目标与约束 | 行动 | 读者新知与后果 |
|---|---|---|---|
| A 23:05／报务室／我 | 恢复信号；无人回电 | 核对两张抄报纸，钟声迟半拍 | 记录与时间矛盾，引出档案室 |
| B 23:20／档案室／我 | 找同事；门锁着 | 从窗台取钥匙、翻昨日报时纸 | 求救纸的时间比现在晚五分钟，去确认钟源 |
| C 23:35／灯塔外／我 | 判断报警真假；雾遮视线 | 呼叫、听到相同呼号 | 无法确认回声来自何人，章末决定追查 |

5. **S3/S4**：同事失踪的过程放场外（物证：抄报纸、门的钥匙位置），记录与求证的环节在场内。跳接留了物证通道，不是"幕后进行了一个奇迹"（PG68853 L3554-3558 那种缺点）。
6. **S5 三列知情**：读者知道同事不在、钟不准；行动者知道同样多；叙述者不得提前透露同事动机。悬疑类型 → 允许读者落后。
7. **S9 结尾两候选**：A 门锁从外面响了（立即追逐）；B 主角发现所有记录都比潮水慢一拍（余韵）。用户要惊疑、不揭示 → 推荐 B，并写明它降低动作速度。
8. **S12 退出**：无原文 → 不声称做过文本修改或读者试读；技术细节只是虚构叙事，不代表真实通讯流程（`NOT_PROVEN`）。

## 用例 2｜边界输入：一章只有散步，没有冲突

**用户输入**："六千字散步，没有敌人、反转，我没贴正文，要不要删？"

**正确做法**：不得把"没有冲突"当作必删信号。

1. 缺正文 → `INPUT_MISSING`。先给一张可填写的空表 + 需要补的输入清单（散步前后人物的心境、象征意象、与下章选择的关系）。
2. 不生成"已读诊断"；不修改原文件。
3. 若用户明确要写意识流，则采用 S1 的"观察型"模式。依据见 PG19028 L5338-5348：来源作者明说结构是他最不强的一项，作品仍能成立——这正是"不是每章都要行动"的来源侧许可。
4. 候选留在 A/B 两层：A 减少重复景物（若用户嫌长）；B 保留缓慢观察但改变信息视角。选哪一个属 `AUTHOR_DECISION`。
5. 全程不得暗示"读者一定会觉得无聊"——那是效果断言，标 NOT_PROVEN。

**边界通过的判据**：没有产出任何装作针对其正文的具体诊断。

## 用例 3｜负触发：历史戏剧格式当通则

**用户输入**："梵剧有五个转接、五幕和 64 个分支，是不是每章都要照着做一套？"

**正确做法**：拒答普遍化，给适用范围与条件。

- 直接回答：**不是**，并且是本 Skill 明确列出的负触发。
- 给依据（必须带行号）：PG74314 L10860-10862（为符合规则而硬插情节是 Veṇīsaṁhāra 的缺点）；PG74314 L10870-10871（这些定义与分类"没有实质性的兴味或价值"）；PG36790 L1607-1620（五幕法出自罗马 Horace，产生在戏剧已被角斗表演排挤出舞台的时代）；PG32433 L2206-2209（把三幕当终极形式是"迂腐而愚蠢的"）。
- 给替代动作：走 S7——先写下本章要解决的约束（时空跳换／信息量／阅读喘息／一次完整行动），再决定怎么组织；把"你选了哪一个组织方式"写进交付物。
- 保留适用情形：用户如果是**刻意**要写一个模仿古典戏剧结构的中篇小说这种自选题材，那它是本作自选的形式契约，照 S3/S7 登记"这是本作契约"即可——但"因为它古典所以必须"永远不接受。

## 用例 4｜S0 的否决演示（本轮新增，历史版本没有）

**用户输入**："这一章整章是对白，一个动作都没有，按规则是不是废了？我把正文贴给你了，读下来效果很沉、很准，读者反馈也说最难受的就是这章。"

**正确做法**：

1. 效果已达成且读者侧反馈一致 → **S0 生效，输出"保留，记录为有意破例"，停止**。不再往下跑"没有动作=废场"的检查。
2. 引用依据是 PG63188 L381-387：Bernhardt 的《茶花女》效果极大却"手段明显不合艺术"、《李尔王》作为剧作技艺很差的实例效果却正中目标、"执着于僵硬理论的批评不仅徒劳而且极不公平"。
3. 若用户仍要改，才进 S10 找机制，并同时说明这么改会失去什么。
4. 禁止出现"但按 S1 它没有状态差，建议加一个反转"这种句式——这是历史版本最容易犯的错，本轮由 S0 堵住。
