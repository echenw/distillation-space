# Sci-Fi Novum World Forge — 科幻新奇点与异质世界锻造术

> **使用第一原则**：这份 Skill 里的每一条规则都是从**小说里发生了什么**（F）推导出的**设计推断（H）**和**可执行建议（P）**，没有一条是原作者在教写作方法——28 份来源全部是虚构作品。凡本 Skill 说"应该"，请先问：**这部作品的合同（类型、年代、读者、悬念来源）是否允许它成立**。不允许就不套。

## 触发 / 负触发

**用我**：
- 用户在写或改一部科幻/未来题材小说（含行星传奇、太空歌剧、技术讽刺、反乌托邦、末世、工程师主角的硬科幻、接触题材）；
- 用户要诊断一个"说不清哪里不对"的科幻设定或情节骨架；
- 用户要为一个新奇点（novum）设计后果链，或为自动机/外星文明写规则与边界。

**别用我**：
- 真实工程、航天、AI 安全、技术可行性评估或科学预测（本 Skill 的"可计算"是**叙事内部自洽**，不是物理正确）；
- 1970 年后的赛博朋克、后人类、气候小说等本批次不覆盖的语料——只能给明确标为 H 的结构类比；
- 非虚构技法、论文写作、游戏数值平衡；
- 用户没有原创意图、只要复述某部作品情节时（那属于资料查询，不是写作任务）。

**负触发的处置**：命中负触发时直接说明不能支持，并给出"若仍要结构类比，可类比什么 + 它未被本批次证明"，不假装覆盖。

## 输入契约（先拿全，再动手）

必须显式拿到；拿不到就走 §失败出口 的最小补料清单，不臆造：

1. **任务类型**：`设计 / 诊断 / 改写 / 世界观补全` 四选一；
2. **作品合同**：类型档（硬科幻／行星传奇／技术讽刺／反乌托邦／末世／接触）、目标读者与媒介（短篇／长篇／连载）；
3. **已定事实**：主角、核心新奇点、世界规则、已发生的情节（诊断与改写**必须**拿到原稿；没有原稿就不能给"第几段有问题"的定位诊断）；
4. **允许改写的范围**（改写类任务）；
5. **用户真正想解决的那一个问题**（一句话）。

用户没给原稿时可以无稿原创；**不能**虚构"你原文第 X 段"这类定位结论。

## 执行步骤

1. **归类**：确认类型档与读者，判断是否有本批次不覆盖的部分（有则标出，不冒充支持）。
2. **选簇**：按上表选 1 个主簇 + 至多 1 个辅簇；两个以上说明用户的问题不是一个问题，先拆。
3. **取规则**：从该簇的"条件规则"里挑**适用条件与用户作品相符**的条目；每条规则都带"不适用条件"，不符就跳过。
4. **回源核验**：把要用的规则对应的行号从 `references/sources.md` 抄进输出，让用户可以回原文核对；本 Skill 不允许给出无法回源的"来源"。
5. **产出方案 + 反方案**：给出可执行方案，并给出**一个明确的反方案**（走另一条路会长成什么样），让用户能选。
6. **交付**：按 §输出合同 输出；效果未经真实用户任务验证的一律标 `NOT_PROVEN`。

## 输出合同（每次必交七项）

```
任务路由   → 选中主簇/辅簇，以及为什么不是别的簇
输入事实   → 用户给了什么；仍缺什么（缺就列，不猜）
选择的规则 → 规则 ID（如 C3-2）+ 它成立的前提条件
证据       → 来源 PGID + 行号 + 那一行的原意（F 层）
可执行方案 → 具体到场景/句子层面的动作（P 层），含替代的反方案
交付物     → 场景卡 / 设定补丁 / 诊断清单 / 改写稿（按任务类型）
未验证风险 → 标 NOT_PROVEN 的部分，以及本 Skill 覆盖不到的部分
```

## 失败出口

- **关键剧情信息缺失**：给最小补料清单（最多 5 问）+ 两条可选方向，不硬写。
- **用户目标互相冲突**（例如既要"硬科幻严密"又要"法术不可解释"）：保留两个条件分支并写清取舍，**不伪造统一结论**。
- **规则在本批次只有单一来源**（孤证）：必须标注"单书机制，未证明为题材定律"，禁止升级为普适规则——这是本 Skill 的元规则。
- **超出本批次的类型/年代/媒介/读者条件**：说明不支持，必要时只给标为 H 的结构类比。
- 详见 `references/failure-exit.md`；已驳回的旧铁律清单见 `references/rule-adjudication.md`。
