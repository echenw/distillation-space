# Plot Architecture（情节架构）

## P4 直接执行示例（优先读）

**例：用户说“我的双主线中段散，帮我诊断，别改正文”。** 先把用户给出的章纲标识与已读范围填进 `templates/diagnosis-report.md` 的 DR-01；从 `references/diagnosis.md` 取症状“多线失焦”，在 `references/rules.md` 的 RC-01/RC-08 间选择：若两线因一个结算事件相互影响，走因果汇合；若只共享主题问题且各自闭合，走对照并置；若既没有共享事件也没有可陈述的共享问题，输出“并列故事，不足以证成副线”。以证据行和未读范围交付 DR-02，不在用户未授权时重写。

**例：用户只有一个悬疑点子。** 填 `templates/plot-canvas.md` 的 PA-02（三要素）→ 确定开篇读者要等待的“问题”而非预先泄露“答案”（RC-09）→ 由作者决定是否锁终点（RC-02）。缺人物动作或阻碍就停止在素材层，不伪称已有情节。

操作顺序：**文本证据 → 条件分型 → 可选方案及代价 → 填表 → 失败出口**。`references/source-index.md` 中的历史出版时间、戏剧或短篇行业数值不能变成当代市场硬标准；P5 实际宿主任务仍 `NOT_PROVEN`。


## 本轮返工后的优先裁决（P4）

先读 [decision-rework.md](references/decision-rework.md)：旧版 RC-01/02/04/05/08 过硬化部分已经直接修复在 `references/rules.md`。**单线终点、第一段人物欲望、B 型同框结尾均非通用硬门**。规划/诊断/修订输出必须包含“用户目标与证据范围、条件分支、另一方案代价、失败出口”；若尚无可判断文本，只给空表，不模拟案例当真实结果。旧版重要元数据见 [historical-provenance.md](references/historical-provenance.md)；P5 宿主效果 NOT_PROVEN。

## 0. 这是什么

一个**人工填表 + 条件判断**的 workflow，不是自动引擎。

- 输入：用户提供的真实文本、章节、大纲、场次表或明确口述的素材。
- 输出：结构判断、条件分支、可回读的表（主行动/挂线/时点/容器/开篇/信息差/承诺/判断权/场景/诊断/修订工单），以及在授权范围内的修改建议或可选最小改写。
- 不做：不写整本小说、不评分、不预测销量/留存、不自动改稿、不建状态机、不含 scripts。
- 不能替代：作者对故事与道德立场的选择、编辑对市场的判断、真实读者数据。

**证据底座一句话**：规则来自 1609–1929 年（核心 1808–1922）的英语/英译戏剧、小说作法、短篇市场与讲述手册；以闭合型、单卷/短篇为主。长篇多线、影视/互动、非西方叙事、当代平台数据**证据薄或零覆盖**，相关判断标 H / NOT_PROVEN。

## 1. 触发 / 负触发

**触发是给显式调用的路由，不是宿主自动加载。** 宿主是否加载、何时加载由宿主决定；`agents/openai.yaml` 声明 `allow_implicit_invocation: false`。下列“满足任一”只用于用户或宿主**已经调用本 Skill 之后**的任务分流。

**适用**：长篇小说、短篇、舞台剧剧本、类型小说、散文虚构的分章连载（分章/分幕）的情节规划、诊断与修订。**长篇多线/跨卷结构只作保守默认，标 H；**“剧本”默认指舞台剧剧本；影视剧本、分镜、网文平台机制不在适用范围内。

### 触发（满足任一）

- 要开新作：只有点子/素材/人物/一句新闻，需要决定从哪写起、主线是什么、几线并行、写多长。
- 已有初稿/大纲：开篇无契约、中段塌、多线失焦、章末无力、结尾拖沓或欠账、巧合解结、场景无功能。
- 要修订：超长、压缩、删支线、改结局、改开篇、跨媒介移植（只做结构类比；影视/游戏部分标 H / NOT_PROVEN）。
- 要判断“这个点子能不能写成故事”，或“这条副线跟主线什么关系”。

### 负触发（不要用）

- **非虚构**（报道、纪实、回忆录、评论、学术）：本 Skill 不处理事实核验与论证结构。
- **影视剧本、分镜、影视改编的镜头/场景设计**：本包没有影视样本；只能借结构问句作类比，标 H / NOT_PROVEN，不给“影视规律”。
- **网文平台算法、追读/推荐机制、榜单与流量运营**：不在范围；本 Skill 只处理文本结构，不处理平台机制。
- **互动叙事引擎、分支剧情引擎、游戏任务/关卡设计**：没有直接证据，不覆盖；引擎与状态机不是本 Skill 的接口。
- **纯文字润色/校对/翻译**：句子、标点、用词、译笔不在范围；请用语言精修类流程。
- **排版、出版、印刷、封面、投稿格式**：不在范围。
- **角色声音专项、对白腔调、POV 声音设计**：本 Skill 只处理 POV 的结构功能，不教声音。
- **世界观设定专书、设定集**：没有直接证据，不覆盖。
- **要求保证爆款/自动评分/自动写全文/预测读者反应**：超出证据与工具边界，直接说明做不到。
- **只有一句“帮我写个故事”且不愿给素材**：只能给检查清单与空白模板，不代编情节。

## 2. 输入权限

| 用户给了什么 | 可以做什么 | 不可以做什么 |
|---|---|---|
| 真实文本/章节/场次，带范围 | 诊断、填表、给分支与严重度 | 诊断未读部分；把推测写成文本事实 |
| 逐章大纲/场次表 | 结构诊断、规划、挂线、时点判断 | 假装读过正文；编造对白/细节 |
| 只有点子/素材/一句新闻 | RC-16 三要素、入口判断、空白画布 | 虚构人物、事件、结局；声称“已规划完成” |
| 只有“帮我改好” | 先要范围与目标；给诊断清单 | 代写全文、覆盖原稿、越权改视角/结局 |

- **没有原文时**：只给检查清单与空白模板（`templates/`），不虚构诊断。
- **不自动改稿**：默认输出“定位 + 建议 + 可选最小改写”；改整场/整章/整条线需用户明确范围与目标（见 `references/revision.md` §0）。
- **不覆盖原稿**：所有试删/改写只在副本；原稿只读。

## 3. 任务路由

先判任务类型，只读对应文件；不要一次读完所有 reference。

| 任务 | 首要 reference | 补读条件 | 缺少输入时的出口 |
|---|---|---|---|
| **规划新作** | [planning.md](references/planning.md) | 多线 → `rules.md` RC-08；分章连载 → RC-10；判断权 → RC-12；容器 → RC-13 | 只填 `PA-02` 三要素 + 空白画布；不编情节 |
| **诊断现有稿** | [diagnosis.md](references/diagnosis.md) | 按症状查 `rules.md` 对应 RC；填 `templates/diagnosis-report.md`；场景多 → `templates/scene-table.md` | 只给检查清单；不诊断未读文本 |
| **修订超长/中段塌/开篇** | [revision.md](references/revision.md) | 先诊断；结构改动 → RC-01/03/08/11/13；因果/巧合 → RC-05/06；工序 → RC-15；场景 → RC-07 | 只给定位与建议；不重写全文 |

**任务判据**（避免把“诊断”做成“重写”）：

- **规划**：还没有本稿，或只有素材/大纲；输出表，不评判未写的文字。
- **诊断**：有已写文本；先证伪再判，输出严重度与最小验证动作，不改稿。
- **修订**：已有诊断或明确问题，且用户给了改动范围；按“结构/场景/句段”分层，做最小改动 + 回归。

## 4. 最小工作流（3 步内开始）

1. **判任务**：规划 / 诊断 / 修订（上表）。任务不清 → 先做诊断；没有文本 → 只给清单。
2. **收范围**：文本标识、版本、章/场/行、未读范围、目标（字数/结构/优先级）。缺范围 → 严重度降级，不诊断未读部分。
3. **打开首要 reference 的第一张表，填第一行**：
   - 规划：`PA-02` 三要素 + 矛盾句；
   - 诊断：`DR-01` 范围 + `DR-02` 第一条文本证据；
   - 修订：`ST-20` 候选段/场的删场测试。

之后按 reference 的顺序走；不要从“写一句更抓人的开头”开始，也不要在结构未定时润色句子。

## 5. 输出与 Owner

### 本 Skill 负责

- 结构判断：主行动、副线挂载、终点/时点、容器、开篇契约、信息差、章末、结尾、判断权、多线汇合、场景功能、因果与巧合。
- 条件分支：按 `rules.md` 的 A/B/C/D 选择，给出“为什么选这个、不选那个”的信号与代价。
- 修改建议：定位 + 结构关系 + 最小改动；在授权范围内给“可选最小改写”。
- 可回读的表：`plot-canvas`、`scene-table`、`diagnosis-report`。

### 本 Skill 不负责（交回用户/其他流程）

- 作者的道德立场、结局善恶、读者群选择（RC-12 只检查一致性）。
- 市场判断、销量/留存预测、平台算法、合同与排期。
- 句子润色、校对、翻译、排版、出版流程。
- 角色声音、对白腔调、POV 声音设计。
- 世界观设定、设定集、游戏/互动叙事。
- 作品质量保证：规则是检验器，不是生成器。

**Owner**：结构选项与表由本 Skill 产出；**故事决定权在作者**，编辑/用户决定是否采纳。本 Skill 不替作者选故事，也不把“表填完”当成“作品完成”。

**接口**：本 Skill **不依赖其他 Skill、Registry 或状态机**，也没有 provider/回调接口；§5 的“交回用户/其他流程”只是转介建议，不是自动调用。所有表由人填写，结论可被作者/编辑推翻。

## 7. 失败 / 退出

| 情况 | 能做的 | 不能做 / 退回 |
|---|---|---|
| **材料不足**（无文本/只有一句点子） | 给检查清单、空白画布、三要素问句 | 不虚构诊断、不代编情节、不声称已规划 |
| **目标冲突**（又要开放又要闭合；又要 3/4 精确又要自然；又要删一半又要保留所有线） | 列两个方案 + 代价，让作者选；标冲突项 | 不平均、不偷偷替作者选 |
| **类型不适配**（非虚构/影视剧本/分镜/网文平台算法/互动叙事引擎/纯润色/翻译/声音/设定集） | 说明边界，转其他流程 | 不硬套情节规则 |
| **规则冲突未决**（框架/离题 C-08） | 给安全出口：闭合型默认不用；若坚持，先写“单篇自足 + 读者契约 + 不闭合承担主题” | 不写成“框架应当收/不应当收”的规则 |
| **权限不足**（未授权改稿/改结局/改视角） | 只给定位、建议、可选最小改写 | 不重写、不覆盖原稿 |
| **证据范围外**（1945 后、影视/游戏/互动、非西方、长篇多卷、当代平台数据） | 标 H / NOT_PROVEN；用通用结构问句，不给“规律” | 不假装有覆盖、不编样本 |
| **作者拒绝任何删改** | 改走场景修订（加变化/并场/移信息）；结构问题标“未解决” | 不硬删、不表面压缩 |

**冲突时的默认顺序**（只在没有硬约束时）：**已定的故事承诺 > 因果可信 > 场景功能 > 节奏/篇幅 > 局部文采**。若两个方案都可行，输出“方案 A/B + 代价”，让作者选。

## 8. 证据边界与验证状态

- **时间**：1609–1929；核心方法证据 1808–1922；**没有 1945 年后的材料**。
- **语言/地域**：英语原文或英译；英、美、法、德、西班牙、古希腊；无非西方一手诗学。
- **媒介**：舞台剧、小说、短篇、口述、报纸、书籍生产；**无电影（除默片一句）、广播、电视、流媒体、游戏、互动叙事、网文样本**。因此“剧本”默认指舞台剧剧本；影视/网文/有声书只作结构或载体类比，标 H / NOT_PROVEN。
- **长篇多线**：没有一本以长篇多线/多卷系列为对象；跨卷弧线、章群节奏、POV 轮换、时间跨度处理无直接方法证据。相关判断只作保守默认，标 H。
- **单来源参数**：“3/4 主结”“中点照面”“章末 curtain”等只作默认值/可选，不作硬门；详见 `scope-and-conflicts.md` §3.3。
- **来源类型**：METHOD / CRITICISM / FICTION_CASE（H）/ REFERENCE 已逐条标注；不把评论反推写成“作者们一致同意”，不把作品现象写成作者方法。
- **验证状态**：本包为**静态交付**；真实任务未运行（**NOT_RUN**），规则效果未证明（**NOT_PROVEN**）。没有 scripts、没有自动校验、没有状态机；所有表人工填写，所有结论可被作者/编辑推翻。
