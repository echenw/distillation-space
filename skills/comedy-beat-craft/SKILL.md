# Comedy Beat Craft（喜剧节拍工艺）

人工读稿 + 条件判断的**审计/设计**流程，不是自动生成器，也不是笑点预测器。
它做的事只有一件：把"这段好不好笑"这个无法回答的问题，换成"这段的笑点在谁身上、
靠什么机制供给、按什么节拍排列、末位落在哪一句"这四个**可以逐条核对**的问题。

## 0. 来源与可信边界

- 来源批次：`16-类型小说专项/07-喜剧幽默/批次-02`，任务 `B-04-B02`，**24/24 来源全文覆盖**，
  阅读版 200,248 行、2,231,747 o200k token，逐本 SHA-256 与批次清单一致。
- **作者高度集中**：Wodehouse 11 本、Twain 8 本，占 19/24。跨本"共识"必须先按作者族去重。
- 本批**只有 1 本**是规范性（作者明说"应当怎么做"）来源：PG5328《Writing for Vaudeville》
  （1915，Brett Page）。其余 23 本只能给出"作者这么写过"，是描述性的。
  因此**本 Skill 中一切可执行参数都来自 PG5328，且必须标注它讲的是 1915 年美国杂耍舞台。**
- 本批有 3 本的主体不是喜剧：PG3186（道德哲学寓言）、PG5231（社会讽刺长篇，主角自尽）、
  PG3191（在美华人受迫害的纪实讽刺）。它们被判为反例/不适用，不进规则。
- 无读者数据、无笑果实验。**"读者会笑"永远不在可输出范围内。**
- 逐来源角色判定、行号与逐字引文全部落在
  [04 来源索引](references/04-source-index.md)；逐条裁决过程在轮次 `notes/source-synthesis.md`。

标记：**F** = 原文可按行号定位的观察；**H** = 从 F 推出的机制解释；**P** = 可执行动作。

## 1. 触发

- 已有幽默长篇/短篇集稿件，想知道"笑点是从谁身上出的、靠什么机制持续供给"。
- 稿子"好笑但读着累"：需要定位机制重复的位置。
- 笑点密度不均：某几章密、某几章空，需要按场景重新排。
- 已有喜剧前提（premise），要把它摊成可执行的节拍序列。
- 讽刺与幽默混写：需要分开两类笑点的归属，避免互相抢戏。
- 舞台短剧 / one-act 喜剧的笑点与收尾编排。

## 2. 负触发（遇到了不要硬套，直接说不适用）

- **单句笑话 / 段子集合**：无节拍结构需求。
- **情景剧脚本**：媒介的笑点密度与场面节奏规则不同。
- **纯恶搞/戏仿**：本体是靶文本，机制不在本 Skill 范围。
- **要求"保证读者笑"/"提高好笑程度"**：超出证据边界，见 §7 失败出口。
- **要求预测笑点命中率或给笑果打分**：无数据，不做。
- 用户手上只有"想写个喜剧"而没有文本或可陈述的前提：见 §7。

## 3. 输入（缺一项就先问，不要替用户填）

| 输入 | 必需 | 说明 |
|---|---|---|
| 文本或前提 | ✅ | 已有稿（全部或节选），或一句话可陈述的喜剧前提 |
| 形态 | ✅ | 长篇 / 短篇集 / 独幕短剧 / 独白段子 |
| 叙述形态 | ✅ | 第一人称 / 第三人称 / 剧本（决定 §5 G2 的保密分支） |
| 笑点目标 | ✅ | 角色驱动 / 情境驱动 / 讽刺驱动 |
| 目标媒介 | 建议 | 出版小说 / 连载 / 舞台（决定是否启用 PG5328 的时长参数） |
| 篇幅 | 建议 | 字数或场景数。**只在舞台短体下用于换算节拍密度**；长篇没有密度参数，只用于决定审计粒度 |

## 5. 执行步骤（5 个动作，2 个门）

### G1 形态门（先做，决定后面所有参数能不能用）

> 问：**这是舞台短体，还是长篇小说/短篇集？**

- **舞台短体（独幕/one-act/独白）** → 启用 PG5328 的可计量参数：
  独白 10–15 分钟、每 115–140 词约 1 分钟（PG5328 L2404-2421）；
  one-act 控制在 20 分钟内（L3775-3783）；35 分钟音乐喜剧的九段配比（L8597-8652）。
- **长篇/短篇集** → **参数不可用**，只能借用三条结构原则：笑浪三拍（B1）、
  末位落最强（B2 修订版）、好笑的事必须被看见（B8）。理由：小说没有"下场"这个节拍容器。
- **单句笑话 / 段子** → 负触发，停在这里。

### G2 归属门

> 问：**笑点主要由谁制造？**（逐场景/逐章登记，不整体回答）

三格，逐场景只准填一个：

| 归属 | 判据 | 典型 |
|---|---|---|
| 角色搭档 | 一个人制造，另一个人反应；被反应者的冷静本身就是节拍 | Bertie/Jeeves（PG10554）、comedian/straight（PG5328 L3338-3425） |
| 叙述者 | 叙述者自己既出丑又解说，读者比他先知道 | Twain 第一人称（PG5783、PG5785、PG7101） |
| 世界 | 无人制造笑，荒谬来自制度/器物/他人 | 自动售货机（PG68809 L7349-7367）、世仇循环（PG7103 L826-851） |

- 填"角色搭档"时，启用 **B3**：给反应者的笑必须立刻用更大的笑顶回去
  （PG5328 L3419-3421）；单叙述者作品**不适用** B3。
- 同一场景两格同时出现 = 疲劳的主要来源，在节拍表上标红。

### A1 机制盘点

拿 [02 机制库](references/02-mechanism-library.md)，逐场景勾已在用的机制 ID。
一个场景最多勾 1 个主机制 + 1 个副机制，勾不出来就写"未知"。

### A2 节拍审计（核心动作）

按 [01 §3](references/01-attribution-and-beats.md) 的节拍表逐场景/逐章登记，
每行必填：机制 ID、上一场是否同机制、三拍是否递升、末位句。

### A3 出表

产出 §6 的三件东西。所有空列写"未知"，不猜。

## 6. 输出合同（三件，缺一件不算完成）

**1）归属判定**（1 段）
- 形态（G1 结论）+ 参数是否可用。
- 逐场景/逐章的归属三格分布，点出两格撞车的场景。

**2）节拍表**（逐场景/逐章一行）

| 场景/章节 | 归属 | 主机制 | 副机制 | 上场同机制? | 三拍递升? | 末位句 | 舞台时长(仅短体) | 待作者决定 |
|---|---|---|---|---|---|---|---|---|

**3）分支选择记录**（见 [03 §1](references/03-branches-and-prohibitions.md)）
逐条写明本次选了哪一侧、为什么，**没有选的那一侧也要写明为什么不选**：

- 省略 vs 铺陈
- 保密对象（B4a 戏剧式 / B4b 第一人称式）
- 可开玩笑的对象（社交做派侧 / 身体与制度暴力侧）
- 终点（和解 / 不和解）
- 题材行情提醒（误认身份等）是否采纳

结尾必须附这一句：
**本输出只描述文本的节拍结构，不承诺读者会笑；无读者数据支撑。**

## 7. 失败出口（遇到就照着说，不要绕过去）

| 情况 | 输出 |
|---|---|
| 用户要求"保证好笑"/"提升好笑度" | 直接拒绝并说明：无读者数据，本 Skill 只处理可核对的节拍结构。改为给节拍表与重复标记。 |
| 读者疲劳（"读着累"）是主诉 | 给得出**机制重复标记**，但疲劳本身是 `NOT_PROVEN`：本批没有读者疲劳数据，只有"机制可被模仿而贬值"（PG7230 L5757-5762）这类市场证据。给自查项，不给结论。 |
| 只有"想写喜剧"没有文本/前提 | 停下，按 §3 要输入，先不谈机制。 |
| 要把舞台参数套到长篇 | 明确换算关系缺失：分钟/词数参数在长篇无对应容器，只保留 B1/B2/B8 三条。 |
| 用户问"这段好笑吗" | 不给判断，给节拍行 + 机制 ID + 重复标记，把判断交回作者。 |
| 引用的规则出处被质疑 | 指到 [04 来源索引](references/04-source-index.md) 的 PG + 行号，由用户回原文复核；无法回源的规则本 Skill 不收录。 |

## 9. 禁止项

- **不许承诺笑果**，不许给笑点打分，不许声称"读者一定会笑"。
- 不许把单独一本小说的情节设计当成所有作品必须遵守的规则。
- PG3186（道德寓言主体）、PG5231（讽刺长篇主体）、PG3191（迫害纪实主体）
  只能作为**反例/不适用**出现，不得作为喜剧机制的正向证据。
- 舞台市场行情（如"误认身份已陈"，PG5328 L4803-4818）只能作为市场提醒，
  不得写成机理禁令。
- 不声称有自动化节拍检测器；本 Skill 是人工读稿 + 表格。

## 10. 与邻近批次成果的关系

同题材 `07-喜剧幽默/批次-04` 已交付 `comic-engine-craft`（搭档引擎/讽刺引擎 C1–C10）。
本 Skill 用本批 24 本独立复核了那 10 条：**9 条 KEEP、1 条 REVISE（C9 的后场知情差需按
叙述形态拆分）**。两者分工：`comic-engine-craft` 管**引擎配置**（笑点从谁出、靠什么持续供给），
本 Skill 管**节拍排布**（这些笑点按什么顺序、多大间隔、末位落在哪里）。
需要引擎配置时先读它；需要把配置摊成可核对的节拍序列时用本 Skill。
