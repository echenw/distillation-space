# 08 卷、弧线、章节与生产反馈的依赖边界（Wave4）

本文件解决系列规划中不能由单本结构代表的**卷间依赖**。F 是用户提供的已发生情节和固定旧源定位，H 是候选推断，P 是建议操作；不得根据原著统计伪造现代平台效果。

## 1. 层级：一个核心故事承诺可跨越多个出版单元

| 层级 | 首要问题 | 下层依赖 | 应输出什么 |
|---|---|---|---|
| 系列/项目 | 读者和作者承诺持续探讨什么、发行是否连续 | 多卷主线与系列正典 | 核心问题、必要边界与可退出条件 |
| 卷/季/分册 | 本卷读者会得到什么答案、是否承诺下一卷 | 横跨多个章节和人物弧 | 卷前状态、主线承诺、卷末已兑现/未兑现 |
| 角色/关系弧 | 谁在什么条件下改变、哪些选择有代价 | 可跨章甚至跨卷 | 起点、触发、决定、关系后果、未决张力 |
| 章/期 | 读者本章看见谁完成哪项行动 | 场景行动、可选章末期待 | 章内变化与对上层承诺的贡献 |
| 场景 | 谁有什么信息，选择改变了什么 | 角色位置/目标和时间事实 | 可定位的 F、触发、可见结果 |

**禁用错误替代**：一章章末钩不等于整卷收束；卷末任务结账不等于整个系列主题结账；新卷开放线数量不能用某书的二条限额衡量百万字长篇。

## 2. 权威和状态来源

- **已发表/作者锁定正典**是现实文本事实 F 的权威；规划草稿、书友反馈、内部备忘是候选，不得变成第二权威。
- **现有章节原文**提供可见事件，设定和正文冲突时列出版本、谁修改过、影响哪些消费者，交作者裁决；不擅自 retcon 或双写两个“最终正确”版本。
- **关系线与开放线台账**是对原文的投影，不独立创造剧情事实；章节改动后依据新正典更新索引，不能让陈旧表格覆盖正文。

## 3. 开放线生命周期与必要校验

逐条记录：line_id / 谁的目标 / 初次出现的卷章 / 当前状态 / 人物当时所知 / 真正的下一个可选行动 / 条件依赖 / 实际兑现处 / 最晚必须决定的节点 / 事实来源版本。

可用状态：候选（未发表）→ 已开启 → 推进中 → 已兑现；或已开启 → 有意延后；或作者明确决定放弃/转化。任何状态变动必须有真实文本或作者明确决定的依据；**没有新情节只是未观察，不能伪装为已回收**。

- **F**：卷 1 已给失踪信物、卷 2 将交代持有人；须定位实际出现的章节。
- **H**：卷 3 若增加追查者可能延长悬念，但可能过载。
- **P**：检查卷 2 的读者承诺是否真涉及此信物，如果不涉及可延期并标原因；不是“已有两条不得再开”。

## 4. 跨卷变更影响检查（最低必要范围）

改动前卷的伏笔时，沿如下链路检查：

1. **入口事件**：前卷哪句话/行动首次建立读者预期？用户锁定版本是什么？
2. **角色认知**：下卷人物是否以尚未出现的消息作出选择？
3. **公开后果**：关系、组织、物品归属、身体状态、时间是否已变化？
4. **承诺与回收**：哪一卷应该回应，是否需要新章，能否用现有场景自然兑现？
5. **出版边界**：原卷若已发表且不能回写，改为在后卷解释或调整未来提案，不擅自覆写历史。
6. **回归**：结局改动是否让先前章节的情绪与代价失效？仅追踪直接依赖节点，不默认全书重写。

## 5. 排期、作者产能与外部反馈

- 容量/时间是生产约束，故事弧和人物选择是内容约束。先确认哪个真实已锁定，再提供拆卷、合并、改变节奏或延长交稿的方案，不伪造可行性。
- 反馈来源分为作者自己的观察、编辑合同需求、读者评论/行为数据；评论情绪不能等同精确留存。记录反馈与版本、候选改法、影响范围、作者最终采纳决定。
- 预备存稿或备用结局是风险管理备选；Trollope 个人有 1–3 部完成稿的经历不证明其他作者必须库存，不隐含付费、资源或额外工作。
- 无现代真实读者测试时，不对“更爽、更耐追、更卖座”给定量结论。

## 6. 可用的实际诊断反例

- **一条主案延续 4 卷**：M02 不应每卷强行结案；只要明确每卷阶段成果、角色变化与读者承诺的兑现情况。
- **同一章没有悬念**：人物在安静完成重要决定时，M03 不强加钩子；章末回望下章动机即可。
- **有五条开放线**：M13 不按二条阈值删掉三条，先核每条是否真实独立、是否在同一人物/时限可承受、哪些可延期/合并。
- **世界没有复位**：革命事件使组织结构永久改变，M04 应继承变化而非复位。
- **读者评论要求杀配角**：M12 先记录为意见候选，作者核关系弧后有权拒绝，不直接修改故事权威状态。

## 7. 失败与退出
前后卷版本相冲突且不能确定哪个为正式正典 → 暂停对应链路，只给冲突与需作者裁决。尚未发表的提案可在授权内调整，已发表历史的追认和大量 retcon 须由作者决策。没有实际用户原文时输出样表与 NOT_OBSERVED，不称实审。引用的 PG 结构样本只供历史比较，真实性和现代效果 NOT_PROVEN。
