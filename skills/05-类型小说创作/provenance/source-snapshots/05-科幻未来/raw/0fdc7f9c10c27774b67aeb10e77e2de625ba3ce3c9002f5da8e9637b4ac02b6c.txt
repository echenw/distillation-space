# 科幻未来：设定论证与推演锻造箱

29 部英语科幻/未来小说全文实读（Verne 1865 → Leinster 1961，1,160,319 o200k Token），蒸馏出 **30 个规则族**、404 条文本现象（F）、149 条升格推断（H）。每条规则给出触发情境、判断信号、操作、输出、失效条件与来源锚点；锚点为 `PG ID + 行号 + 逐字短引文`，全部经 152 条原文回读核验。核验记录 `notes/quality/quote-check.txt` 与 `materials/…/manifest.json` 属同轮审计留痕，仅供追溯；使用本 Skill 不依赖它们。

**证据口径（使用前必读）**：全部来源是 `FICTION_CASE`（小说），不是写作教程。本 Skill 的规则是**从文本现象升格的推断（H）**，不是"作者明确教授的方法"。同作者/同系列按来源族降权；单源规则随条标注 `[单源]`，不得当普适规律。

## 输入权限

- **可用**：科幻/未来长篇的规划、诊断、改稿；novum 规则设计；技术/社会推演；信息释放与视角选择；乌托邦/反乌托邦收束；第一接触与异族设计；尺度/时间结构。
- **禁用**：真实科学、工程、医学、法律、核安全、公共卫生的事实咨询——源文本的"科学"是 19–20 世纪文学装置，不可当知识使用（例：PG32079 的核热室防护、PG29448 的病毒方案、PG24707 的反重力）。
- **禁用**：现实未来预测、政策建议、投资判断。
- **禁用（时代红线）**：把源文本的殖民话语、种族本质论、性别本质论、优生学、反犹阴谋论、殉葬浪漫化迁移进新作。这些只作为历史文本登记，见 `counterexamples.md` §3。
- **口径限制**：不要把小说人物的做法写成"作者教的方法"；本 Skill 只提供"文本里这样写有效/失效"的推断与条件。

## 快速决策表（先选型，再查规则）

### 表 1：novum 四型（先判断你的核心装置属于哪型）

| 型 | 读者的核心问题 | 首选族 | 配套 |
|---|---|---|---|
| 规格/工程型（发射、造城、改造星球） | 这要多少钱、多久、多重，数字能不能闭合 | R19 工程规格 | R01 倒计时、R14 公平反转 |
| 限制/装置型（全能 AI、无敌护盾、任意门） | 既然能这样，为什么不那样 | R20 限制型 novum | R17 道具三用、R04 机器成长 |
| 制度/资格型（发明、建国、时间旅行） | 社会接不接、谁批、归谁管 | R21 机构折射 + R22 资格阻力 | R05 制度恐怖、R30 乌托邦双轨 |
| 物种/他者型（外星人、异族、换身、信仰） | 谁算人、谁被承认、谁的身体归谁 | R02 第一接触 + R03 身体交换 + R27 信仰逻辑 | R07 冒充、R18 偏见产业链 |

## 触发与负触发

- **触发**：用户说"设计一个科幻设定/世界观""写硬科幻长篇""设定怎么不显得假""中段没戏了""结尾怎么收""外星人/机器人怎么写才不像人""反乌托邦怎么写""时间旅行/尺度怎么写"。
- **负触发（应排除并说明）**：
  - "帮我核对这个物理/医学/法律设定是否真实" → 拒绝，指向"输入权限"的禁用条；可改做"文学可信度"诊断。
  - "预测 2050 年会怎样" → 拒绝，本 Skill 只处理虚构叙事。
  - "给我一份太空歌剧设定清单（不需要因果）" → 只用 R20/R17 的装置条目，社会推演族不启用。
  - "把某族/某性别写成天生如此" → 拒绝，指向 `counterexamples.md` §3 的时代红线。

## 分支路由（按任务类型）

1. **从头规划**：表 1 定 novum 型 → 表 2 定信息档 → 表 3 定社会阻力 → 用 `references/novum-and-rules.md` 写规格与限制 → 用 `references/world-and-institutions.md` 搭社会 → 用 `references/structure-and-endings.md` 排四段权力与收束。
2. **诊断已有稿**：先跑 `failure-modes.md` 的七问 → 命中哪族失效条件 → 跳到对应 references 的"失效"栏取修法 → 用 `examples.md` 示例 2 的回归清单复验。
3. **单点设计**（只要一个装置/一场戏）：按表 1–4 直达规则条目；每条含触发/操作/输出/失效四件套。
4. **世界观改造**（已有设定，想加深）：先用 R19 补规格，再用 R20 加限制，最后用 R21/R22 让社会接住它；不要先加新地图。

## 输出契约

每次应用须交付四项：

1. **选用的规则 ID**（R01–R30，可多选，须说明主/辅）。
2. **每条规则在本作的具体化**：触发事件、操作改写、输出的表/清单（至少填一项）。
3. **剩余风险**：该规则的失效条件在本作设定下是否闭合；未闭合的写"已知缺口"。
4. **证据强度**：`[单源]` / `[同型]` / `[反例]` 标注；不得把单源规则写成普适规律。

设计新装置时必须回答两个问题：读者能否复述"这条规则限制了什么"；结尾所需事实在前文以什么别的用途出现过。

## 失败出口

- **族外案例**：无法归入 R01–R30 → 标"族外"，不硬套；记录到项目 notes 供下轮蒸馏。
- **规则冲突**：如"技术乐观"（PG5155 开场）与"技术恐怖"（同书自杀屋）并存 → 按 P3 冲突裁决拆成 R01/R05 两条，不合并为"技术中性"大原则；冲突明细见 `counterexamples.md` §1。
- **单源规则**：只有一本书支撑 → 输出中标 `[单源]`，并给"若换设定则失效"的条件。
- **时代偏见**：源文本的殖民/种族/性别/优生段落 → 不迁移，只在 `counterexamples.md` §3 登记；用户要求"照那个年代写"时，须明确标注这是历史话语再现，不是价值主张。
- **超出虚构边界**：现实科学/医学/法律咨询 → 触发"输入权限"禁用条并说明。
