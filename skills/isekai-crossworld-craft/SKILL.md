# 异世界与穿越：机制核账与写作检查

基于 27 份公版长篇（PG10337、PG10368、PG1076、PG11、PG11499、PG11573、PG1267、PG13508、PG234、PG3055、PG37270、PG4092、PG4637、PG47030、PG51115、PG54708、PG55505、PG58784、PG67652、PG69394、PG69737、PG70002、PG7401、PG783、PG86、PG9488、PG9663）全文阅读台账蒸馏；每一条规则都能在 `references/` 里按 `PG号 + 行号` 回源。

## 1. 触发与负触发

**触发**（满足任一）：
- 用户在写/改一部"主角离开原世界进入另一个世界"的小说：门径、时间位移（过去或未来）、转生与前世、传送点、飞地与邻近异界、失落世界。
- 用户问穿越设定的**一致性**问题：机制要不要交代、能不能回家、异界规则怎么定、真实性要不要留白。
- 用户要一份异世界设定的**检查清单 / 审稿意见 / 大纲体检**。

**负触发**（不要用本 Skill，直接说明原因并给替代路径）：
- 只是古风、中世纪或伪历史罗曼司，没有跨界机制 → 本批 PG234、PG47030、PG9488、PG9663 已验证：背景不等于机制。请改用该题材自身的浪漫/传奇写法。
- 只是社会乌托邦或社区改造小说（无外来者、无世界跨越）→ 见 PG69737、PG54708；制度设计可借，外来者视角不可借。
- 只是民俗怪谈/异界接触（主角未曾旅行到另一世界）→ 见 PG13508。
- 纯语言润色、情节节奏、人物对白打磨 → 不属于本 Skill 范围。

## 2. 输入（缺什么先问什么，不要猜）

必须拿到：
1. **跨界型**（见 §3 六型；用户说不清就让他选最接近的一型）。
2. **归途状态**：开放 / 关闭 / 不可判定（三选一，不允许"还没想好"）。
3. **不可逆锚点**：有没有一处"回不去了"的硬证据（对应规则 R3/H3）。
4. **读者被要求的能力**：读制度 / 读地形 / 读情感禁忌（对应 H2）。
5. 待检文本或设定条目（能给原文最好；没有就按 §4 的清单逐项口头核对）。

## 3. 任务路由

| 用户情境 | 走哪条 |
|---|---|
| "这个设定行不行 / 帮我体检" | §4 六型检查表 → §5 规则裁决表 → §6 输出合同 |
| "我想写穿越，从哪开始" | §3 六型选择 → 该型的必备锚点 → §4 |
| "能不能不解释穿越机制" | 规则 R1（REVISE）：不给机制必须换成替代锚 |
| "要不要让他带回现代技术" | 规则 R2（REVISE）：可选亚型 + 必须写代价 |
| "结尾要不要说是一场梦" | 规则 R5（KEEP，带条件）+ 冲突 C1 |
| "他能不能回家" | 规则 R4（REJECT 硬规则）→ 先定归途三态 |
| "异界的人要写得多奇怪" | 规则 R7（REVISE）：奇观化会反噬 |
| "他必须是被选中的人吗" | 规则 R8（REJECT） |

**六型**（`references/mechanism-taxonomy.md` 有逐型代表来源、行号与该型专属检查项）：
① 门径型（PG3055、PG11）｜② 时间位移型（PG86、PG67652、PG7401、PG58784）｜③ 前世/返祖型（PG70002、PG11499）｜④ 飞地/邻近异界型（PG37270、PG783）｜⑤ 失落世界型（PG783、PG55505）｜⑥ 传送点/悖论型（PG51115）。

## 4. 执行步骤

1. **定型**：按 §3 六型判定；跨型设定取主导型，其余按"附加约束"处理。
2. **查该型的必备检查项**：读 `references/mechanism-taxonomy.md` 中对应小节，逐项打 PASS / FAIL / N-A。
3. **过规则裁决表**：读 `references/rule-verdicts.md`，对 §5 列出的 14 条逐条判定"适用于我 / 不适用 / 我主动违反"，主动违反必须写出理由。
4. **查反例与冲突**：读 `references/conflicts-and-exceptions.md`，确认你的做法没有踩到已记录的反例（尤其 R7、R8、R9）。
5. **回源抽检**：挑 2–3 条你准备采用的规则，用 `references/source-index.md` 给出的行号回到原文核对一次；**引用行号前必须真的核对过**。
6. **出报告**：按 §6 输出合同写。

## 5. 规则裁决表（摘要，完整依据见 references/rule-verdicts.md）

| # | 主张 | 裁决 |
|---|---|---|
| R1 | 穿越必须交代机制 | REVISE：给机制，或给"不可追问"的替代锚 |
| R2 | 穿越者应当改造异世界 | REVISE：可选亚型，必须写代价 |
| R3 | 异界必须有自洽可复用的规则 | KEEP |
| R4 | 一定要有回家目标 | REJECT（硬规则）→ 开局即定归途三态 |
| R5 | 真实性可留白（梦/异象） | KEEP（带条件：留白须与物证并存或明确二选一） |
| R6 | 异世界可作讽刺/论政装置 | KEEP（亚型，注意说理压叙事） |
| R7 | 异界居民应被奇观化 | REVISE：奇观化会反噬作者自己的世界 |
| R8 | 穿越者是被选者/拯救者 | REJECT |
| R9 | 古风/中世纪背景＝穿越 | REJECT |
| R10 | 变形/跨 species 并入穿越 | REVISE：只共享"不可逆＋亲历者视角" |
| R11 | 长生/跨时代见证＝穿越 | REVISE：归为补充 |
| R12 | 异域自治必生私刑与合法性危机 | KEEP |
| R13 | 必须有"回到现实后无法解释"的收束 | NOT_PROVEN（样本不足） |
| R14 | 异界命名必须由主角完成 | NOT_PROVEN |

**保留未统一的冲突**（不要强行调和）：C1 真实性留白 vs 物证（PG70002 两者并存、PG58784 不留白）；C2 归途开放 vs 关闭；C3 决定论 vs 改造欲（PG67652 内部即并存）。

## 6. 输出合同

每次交付必须包含以下五段，缺一段即未完成：

1. **型别判定**：六型之一 + 一句话理由。
2. **检查表**：该型必备检查项逐项 PASS / FAIL / N-A（附检查项编号）。
3. **规则裁决**：适用到本作的规则逐条给出"遵守 / 主动违反 + 理由"；涉及 R13/R14 的写 NOT_PROVEN，不许给出确定建议。
4. **修改建议**：每条建议写明"改哪里 → 改成什么 → 依据哪条规则（R#）→ 可回源的例子（PG号 L行）"。至少 3 条；没有可改的就写"本轮无修改建议"并说明依据。
5. **未决与风险**：列出本作落在冲突 C1/C2/C3 上的取向，以及任何 NOT_PROVEN 项。

**引用纪律**：所有 `PG号 L行` 必须在本次任务中核对过（台账或原文）；写不出行号就写"概述（不带引号）"，不许编造引文。

## 7. 失败出口

- 用户给的是古风/乌托邦/民俗题材 → 触发负触发：明确说"这不是穿越题材"，并说明本批哪份来源支持这一判定（如 PG234、PG69737、PG13508）。
- 用户要求"给一个所有穿越都必须遵守的规则" → 拒绝：本批 27 份明确不支持统一规则（R4、R8、R9 被推翻，C1–C3 不可调和）。改为给"型别 + 取向"的选择表。
- 用户要求"把某部小说的情节设计直接变成通用规则" → 拒绝：见 `references/conflicts-and-exceptions.md` §3 明确不通用化的四项。
- 待检文本缺失且用户不愿补 → 只出"输入缺口清单"，不出建议。
- 引用行号无法回源 → 立即降级为概述并标注，不得保留引号形式。
