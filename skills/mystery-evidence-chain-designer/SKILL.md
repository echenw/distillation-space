# 推理悬疑刑侦小说·证据链设计与审查

来源：29 份公版侦探/悬疑/刑侦小说全文实读（任务 A-03-B02，`16-类型小说专项/01-推理悬疑刑侦/批次-02`），覆盖 29/29 FULL。本 Skill 的每条规则都能回源到具体 PG ID + 行号，见 `references/source-ledger.md`。

**首要约定**：这些来源是**虚构文本**。文本里侦探的做法是**人物行为**，不是作者讲授的写作教程，也不是可照搬的现实执法或鉴识规范。凡本 Skill 说"应做"，其含义是"在虚构叙事内这样做可使推理链自洽且可回读"；凡涉及现实取证，一律降级为叙事设计问题。

## 1. 触发 / 负触发

**触发**（用户问题命中任一即加载）：
- 写或改推理/悬疑/刑侦小说，需要设计谜面、线索布置、不在场证明、密室手法、毒杀或伪装自杀。
- 已有草稿，要求检查"推理链是否成立/是否公平/读者能否回推/有没有作弊"。
- 需要在多个嫌疑人/动机/时间线之间做收束，或要写结案解谜章。
- 视角选择困难：第一人称助手、侦探视角、全知、多证人档案式，不确定哪种会泄露或失效。

**负触发**（不要用本 Skill）：
- 要现实刑侦流程、法医/法证结论、法律可采性意见 → 明确说明本 Skill 不提供，并建议咨询专业来源。
- 要写非推理类型的犯罪小说（纯黑帮、纯惊悚无解谜）→ 只有"证据链"相关章节能用，其余不适用。
- 要做文本校对、润色、排版 → 不相关。
- 用户只是要一句话灵感/书名推荐 → 用 `references/checklists.md` 的反套路清单即可，不必跑全流程。

## 4. 执行步骤（按顺序，不要跳）

1. **定类**：把用户的谜面归到 §3 表中一到两个问题类；同时确认视角与篇幅。
2. **取规则**：按路由加载对应 reference 小节，取规则（每条规则自带：触发情境 / 判断信号 / 操作步骤 / 输出 / 失效条件 / 来源锚点）。
3. **跑规则**：对用户的文本逐条执行，把每条的**判断信号**在稿子里找到或标记为"缺失"。
4. **查反例**：对每条命中的规则，到 `references/counterexamples-conflicts.md` 取它的失效条件与反例出处，确认用户稿件是否踩中失效条件。
5. **做公平性自检**（结案章必做）：跑 `references/checklists.md` 的负向排除清单；任何"读者不可能回推"的环节必须补线索或改写法。
6. **出结果**：按 §6 输出合同输出，不许只给一句评价。
7. **失败出口**：若稿子缺关键信息（如无法确定案发时刻、密室边界未交代），走 §7。

## 5. 适用边界（写在动手之前）

- **篇幅**：短篇（PG71589 751 行、PG72197 442 行）靠单一反转 + 极小封闭集；长篇（PG74210 8338 行、PG155 20995 行）靠程序戏 + 多线索交叉 + 延迟回收。不要给短篇排长篇的多线索结构。
- **体裁**：科幻推理（PG71589、PG72197）用"设定律"代替物证（机器人不能伤人、瞳孔定死时±10 分钟）。这类机制**只在设定内成立**，不得当作现实型推理的可迁移技法。
- **时代技术**：保留"用时代前沿技术建立识别链"的**结构**（PG74441 L3778-3804 的 X 光识别链），拒用其**结论**；颅相学、"血统性情论"、笔迹判性别（PG63340 L4249-4254）等时代侧写术一律不采纳。
- **族去重**：跨书规则的支持度按"族"计不按"本"计。本批至少四族：女性/职业卧底族（PG54273、PG62824、PG63340）、足迹与现场时序族（PG73711、PG74441、PG63340）、时间锚与文书伪造族（PG70964、PG74441）、同作者同年族（PG73597 与 PG74210）。

## 6. 输出合同（每次交付固定六段）

1. **判定**：用户的谜面归到哪一类，用的是哪几条规则（写规则编号）。
2. **检查清单结果**：逐条列"已具备 / 缺失 / 踩中失效条件"，每条写清对应稿子的哪一段。
3. **改写方案**：按优先级给出最少 2 条可执行修改（加什么线索、删什么误导、哪个时间点必须交代）。
4. **来源锚点**：每条建议至少附 1 个 `PGxxxxx L行号` 锚点，指向同类写法样本。
5. **风险与反例**：本方案最容易失效的地方，附反例出处。
6. **未决项**：无法从现有信息判断的部分，明确写"待补信息：…"，不要靠猜补完。

## 7. 失败出口

- **信息不足**（不知道案发时刻、不知道谁在现场、不知道视角是谁）→ 停止跑规则，列出缺哪几项，让用户补。不要替用户设定关键事实。
- **要求现实取证/法医结论** → 明确拒绝并说明本 Skill 只处理虚构叙事内部的自洽性。
- **稿件踩中失效条件且无法修补**（例如密室边界从未交代、唯一证人是不可考的传闻）→ 给出两条路：改设定使边界可交代，或把该环节降级为"未解扣"并在文本里明写为未解。
- **公平性自检不通过**（读者无法回推）→ 必须补线索或改写，不允许用"侦探后来发现"搪塞；这是硬性失败出口，不是可选建议。
