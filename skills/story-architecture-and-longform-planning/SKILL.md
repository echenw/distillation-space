# 故事架构与长篇规划

管两层：**一作品的骨架**（主线在推进什么、终点在哪、从哪开始、每一段为什么存在、几条线怎样收到一起、在哪里停），和**一部要分次发表的长篇怎么拆成一卷一卷**（每卷收在哪、下一卷从哪接、跨卷的线怎么记、字数和排期怎么定）。单本结构的规则是 PL 卡，分卷连载的规则是 SV 卡。

## 1. 适用与转介

用：
- 开新作：只有点子、素材、人物或一条新闻，要定主线、从哪写起、几条线、写多长。
- 已有初稿或大纲：开篇抓不住、中段塌、多线失焦、巧合解结、场景没有作用、章末无力、结尾拖沓或欠账。
- 修订：超长要压缩、删支线、改开篇、改结局、调整多线。
- 开一部连载或系列：分几卷、每卷写什么、卷末怎么收、下一卷怎么接。
- 已经在连载：卷末像完结了，下一卷没有入口；新读者进不来；坑挖太多收不回；套路重复；每卷都在加码；配角一成不变。
- 跨卷的连续性检查；开载前排产（单章字数、更新频率、存稿、断更风险、备用结局）；读者或编辑的反馈来了，要不要改。

转给别的 skill：

| 问题 | 转给 |
|---|---|
| 伏笔怎么埋、悬念怎么写、章末钩子的写法和兑现、场景里的冲突与节奏、对白、打斗 | `scene-conflict-and-rhythm` |
| 人物动机和心理、人物弧（以一个错误的信念为轴）、谁来讲、视角越界、信息控制、非线性时间 | `character-and-narrative-control`（哪一卷加入或收掉一条视点线，在本 skill 的卷表里排） |
| 选题定位、读者契约、说教和设定堆砌、注水的成稿自检、资料核验、读者反馈分析、不确定用哪个 | `fiction-planning-and-diagnosis` |
| 句子、用词、标点、AI 腔、校对 | `line-editing-and-proofreading` |
| 某一题材的写法（推理、言情、武侠仙侠、科幻等） | `genre-fiction-craft` |
| 改编成舞台方案或分场稿 | `cross-media-drama-adaptation` |
| 把规划、卷纲、章纲或结构方案写成推进模式卡、文风卡、表达约束卡给模型用；给模型的上下文怎样分层；按推进／文风／表达三轴审章节 | `preset-card-generation` |

重叠请求的归属：

| 请求 | 归属 |
|---|---|
| 「帮我规划一本书」 | `fiction-planning-and-diagnosis` 做入口并定赛道；单本结构、分卷和章纲交给本 skill |
| 「规划一卷／排章纲」 | 本 skill（产物是规划文档）；要写成给模型的推进卡时交给 `preset-card-generation` |
| 「这一章节奏拖」 | 单元内的问题交给 `scene-conflict-and-rhythm`；跨章、跨卷的问题归本 skill |

从 `preset-card-generation` 转入本 skill 的：单本结构、分卷、排章纲，且产物是规划文档、不是给模型的卡。
从 `genre-fiction-craft` 转入本 skill 的：全书主线、多线汇合、分卷、连载排期。
从 `character-and-narrative-control` 转入本 skill 的：主线、多线、因果、删场、分卷和连载的规划。

### 负触发（不要用本 skill）

- **非虚构**（报道、纪实、回忆录、评论、学术）的事实核验与论证结构：不在范围；要核验现实断言转 `fiction-planning-and-diagnosis`。
- **影视剧本、分镜、影视改编的镜头/场景设计**：本 skill 只借结构问句作类比，转 `cross-media-drama-adaptation`。
- **网文平台算法、追读/推荐机制、榜单与流量运营**：不在范围；本 skill 只处理文本结构，不判断平台机制。
- **互动叙事引擎、分支剧情引擎、游戏任务/关卡设计**：不在范围。
- **纯文字润色、校对、翻译**：句子、标点、用词、译笔转 `line-editing-and-proofreading`。
- **排版、出版、印刷、封面、投稿格式**：不在范围。
- **角色声音专项、对白腔调、POV 声音设计**：本 skill 只处理 POV 的结构功能，转 `character-and-narrative-control`。
- **世界观设定专书、设定集**：不在范围。
- **要求保证爆款、自动评分、自动写全文、预测读者反应**：超出边界，直接说明做不到。
- **只有一句“帮我写个故事”且不愿给素材**：只给检查清单与空白模板，不代编情节。

### 跨 Skill Owner

- **全书/卷级结构**：本 Skill 的 PL 负责主行动、因果、多线、全书承诺和整体场景库存；SV 负责分卷闭合、卷末入口、跨卷开放线、容量和连续性。
- **场景/章节内写法**：`scene-conflict-and-rhythm` 负责单场冲突、现场呈现、动作写法、悬念措辞、钩子强度和单章兑现。PL-07 只做全稿/大纲层面的场景库存与删并，不替代单场诊断；PL-10 只决定分次交付是否需要章末问题及其分布，不接管钩子写法；PL-10 输出的章末问题清单中“属主线或副线”一栏只作分布登记，单章兑现记录归 SU-16。
- **人物与视角**：`character-and-narrative-control` 负责人物心理、叙述者、单场视角许可和全篇信息控制；本 Skill 只在卷表记录视点线的加入/退出，不裁决单场 POV。
- **题材契约**：`genre-fiction-craft` 负责推理公平、言情/恐怖等题材承诺及专门机制；本 Skill 只负责通用结构，不把题材惯例升级为所有作品的规则。
- **项目与读者诊断**：`fiction-planning-and-diagnosis` 负责项目定位、载体选择、读者契约、资料核验和读者反馈分析；本 Skill 把已确定的载体转换为情节/分卷容量与排期，记录连载反馈并评估结构影响，不从单条评论或单一指标推断市场效果。

短篇、单章没有卷级边界，SV 卡不适用；分期发表的短篇仍可用 SV-09、SV-10 的期级规则，章末取舍用 PL-10。

## 2. 使用方式

- 宿主规定了输出格式就按宿主格式交付；没有规定时用 §7 的产物，空白模板在 `templates/`。
- 普通任务读完本文件就能做。需要条件分支、反例或失败出口时，读 §10 列出的文件，只读用得到的部分。PL 卡的权威正文在 `references/plot-rules.md`，SV 卡在 `references/serial-rules.md`。
- 给了稿子就按稿子诊断，写明章号、段落和短引文，不编造“稿里有”的问题；没读到的部分（包括前卷）标“未读”，不下诊断。
- **只给一句想法也能做**：把缺的参数（主行动、终点、形态、卷数、篇幅、下一卷定没定、更新节奏）补成合理假设并标“假设”，先给草案，再列出最多三个要作者拍板的问题。
- 要求写大纲、卷纲、章纲、场景或改写，就写，标“草案”，写完列出用到的规则和假设。
- 候选方案不写成作者已定的事实。两个方案都成立时，写方案和各自的代价，作者定。
- 规划、诊断、修订的输出都含四件：目标与已读范围、条件分支、另一方案的代价、失败出口；还没有可判断的文本时只给空表，不拿模拟案例充当真实结果。
- 改动另起版本，不覆盖原稿。已发表的内容不回头改设定，用后文接住。
- 文中的数字（四分之三处、章数、字数、线数、回顾长度）都是起点，不是门槛。用到中文网文时先看 `references/serial-zh-webnovel.md`；涉及跨平台迁移时再读 `references/serial-platform-migration.md`。
- 不承诺追读、订阅、完读或销量。

输入与权限：

| 作者给了什么 | 可以做 | 不做 |
|---|---|---|
| 正文、章节或场次，带范围 | 诊断、填表、给分支与严重度 | 诊断未读部分；把推测写成文本事实 |
| 逐章大纲、卷表、场次表 | 结构诊断、规划、挂线、时点判断 | 假装读过正文；编造对白或细节 |
| 只有点子、素材、一句新闻 | 三要素卡、形态判断、空白画布 | 虚构人物、事件、结局并当成已定事实 |
| 只说“帮我改好” | 先要范围与目标；给诊断清单 | 代写全文、覆盖原稿、越权改视角或结局 |

## 3. 最短路径

### 第一步：定形态（SV-01）

写下两项：这是单本闭合、系列卷、一部书分卷连载，还是连续追捕；下一卷定了没有。

- 单本闭合：用 PL 卡，加 SV-03（分部）和 SV-13（容量）。
- 系列卷、分卷连载、连续追捕：每一卷内部用 PL 卡定骨架，卷与卷之间用 SV 卡。
- 下一卷没定：按单本处理，不对读者许下跨卷的承诺。

### 单本或单卷规划（从点子到骨架）

1. **三要素**（PL-16）：行动者要什么、做什么、在什么条件下；素材里有没有一个真正的矛盾或反转。
2. **主行动**（PL-01）：一句话写“谁要什么、被什么挡、最后在哪个不可逆事件上结算”。
3. **工序**（PL-15）：作者是写大纲、心里有数，还是边写边发现。
4. **终点**（PL-02）和**时点**（PL-03）：终局事件、故事从哪一刻开始、结打在哪里、何时解开。
5. **容器**（PL-13）：篇幅折成预算，分配到起、中、收。
6. **开篇契约**（PL-04）；多条线定汇合方式（PL-08）；分章交付定章末（PL-10）；定判断权（PL-12）。
7. 交付情节画布（`templates/plot-canvas.md`）。

### 分卷规划（开书或规划新卷）

1. 容量（SV-13）：合同、平台或更新节奏先定了长度，先填容量表，再由容量推章数。
2. 卷表（SV-02）：每卷一行，写卷名、主事件、篇幅、闭合度、下一卷第一步、节点。
3. 卷界（SV-03）：按主线类型选切法。
4. 每卷的收法（SV-04、SV-05）：选闭合度；定本卷要结的账和要开的口。
5. 跨卷的线（SV-08）：建台账，数活动线。
6. 套路与变化（SV-11、SV-12）：定固定骨架、每卷换什么、要不要加码。
7. 每一卷的骨架按上面的单本规划走；起草时逐章用 SV-09、SV-10。
8. 使用旧刊、分册、合集或电子刊作为载体时，另做单期载体审计（SV-16），区分原始出版物与后续转写/校勘层。

### 写到卷末

1. 先结账，再开口（SV-05），过卷末四问。
2. 复位四问（SV-06）：世界回到能继续用的状态，角色的变化留下。
3. 入口还是全闭合（SV-04），看下一卷定没定。终卷和单本的结尾用 PL-11。
4. 更新台账（SV-08）。
5. 下一卷开头的前情（SV-07），按读者隔多久回来定长短。

### 诊断已有稿子

1. 写清范围：读了哪些章节、哪几卷，没读哪些。
2. 按 §4 的症状找规则；每条发现都要有文本位置作证据，先试着推翻它（作者是不是有意这样写），推翻不了再下判断。
3. 定严重度：动到主行动、终点、因果的是结构问题，先修；场景和章末其次；句子不在本 skill。
4. 已在连载的，先建台账（SV-08）和卷表（SV-02），再过卷末四问（SV-05）、复位四问（SV-06）、章末（SV-09）、拖沓（SV-10）、套路疲劳（SV-11）、容量复核（SV-13）；涉及历史期刊/分册/版本边界时再做 SV-16。
5. 交付诊断报告（`templates/plot-diagnosis-report.md`），每条带最小的验证动作。定修的窗口：没发表的可以改稿；已发表的只在后文接。

### 修订（已有诊断或明确的问题）

1. 先确认作者给的改动范围和目标（字数、结构、优先级）。
2. 分层改：结构（PL-01、PL-03、PL-08、PL-11、PL-13）→ 场景（PL-07）→ 段落（PL-14）。
3. 删场测试：删掉它，后文的因、回声、节奏或对照受不受损（PL-14）。
4. 每处改动写最小过渡，改完回读：主落点还被挣得吗？开篇的承诺都结算了吗？

### 开载前排产

容量表（SV-13）→ 开载路线与存稿（SV-14）→ 反馈日志、人物退场预案、备用结局（SV-15）→ 开载检查表。开写以后，每次写完记一行：下一场要写什么、卡在哪里（做法见 `fiction-planning-and-diagnosis` 的 FC-18）。

## 5. 规则卡

每条：规则 → 怎么判 → 适用条件与例外。PL 卡的分支细则与反例在 `references/plot-rules.md` 同编号的条目里；SV 卡的完整规则在 `references/serial-rules.md`，细则在各 `serial-*.md` 文件里。

### 单本结构：生成与骨架

**PL-16 三要素齐备，入口自由**
- 从人物、事件、情境、新闻素材任何一个入口起手都可以（人物入口：先有欲求和缺点；事件入口：先有一个异常事件；胚情节入口：先有一条带反转的新闻或画面）。进入结构设计之前，把行动者（要什么）、行动（做什么）、环境（在什么条件下）三项写成具体的一句话，并确认素材里有一个真正的矛盾或反转。
- 写不出矛盾句时，回到素材，给两三个候选请作者选。

**PL-01 一句主行动，副线挂到同一个落点**
- 写一句“某人想要 X，因为 Y 受阻，最终在 Z 事件上结算”。每条副线写一句“它把 X 推进或阻断了哪一步”；标不出的，先试改挂（换人物动机、换时序），不行就删、并或降为过场。
- 检查：删掉任一副线，主落点是否仍然“被挣得”；不成立，说明这条线是承重墙。
- 例外：集锦和框架故事的主行动只是容器；以“生活流”为效果的作品不强行单终点；短篇强戏剧故事是否保留副线，按当前作品的阅读目标判断。
- 需要时给主行动一个期限（倒计时、季节、仪式日），让选择变得紧迫；日常向作品可以没有外部期限，但要有内在的时机。

**PL-15 先判断作者的工序**
- 外部大纲（闭合型、多线、硬容器、新手、多人协作）、心中大纲（有成熟直觉、能口述终点和中点的作者）、发现式（以人物或语言为驱动、过程即目的）都成立，不宣布唯一正确的工序。
- 起点：动笔前能说出“终点”和“中点转折”两句话，答不出先补答案，再选工序。发现式允许边写边找，完成初稿后强制补一次事件与原因的对照（PL-05）。连载和多人合写往往定不了全书终点，先定本卷的终点。

**PL-02 终点先行**
- 闭合型故事（悬念与揭晓、罪与罚、追求与成败）：动笔前用一句话写定不可逆的终局事件，逐段倒推“读者必须先知道什么”；倒推不出的段落是删除候选。
- 开放型、探索型故事（流浪汉、成长、以语言为目的）：终点不是单一事件，改为写定“最后的状态”和读者合上书时的感受；改稿时补一次因果审计（PL-05）。

**PL-03 高潮与解结的时点：先分型，再定位**
- 先判观众已知多少、要看的是事件还是后果，再决定故事从哪一刻开始、结打在哪里、什么时候解开。不要把“起点”“打结点”“解结点”混成一个“高潮”。
- 四型：观众已知结局、要看怎么做完的（从最接近结局的地方开始）；读者关心“之后怎样”、需要清算与余波的散文虚构；以“成不成”为悬念的商业故事；转折前置、全篇演必然后果的命题推演。
- “主要的结打在大约四分之三处”只作为有限经验形成的可选起点，不是门槛；须按作品的起点、后果需求和载体调整。

**PL-13 容器先行**
- 动笔前定容器：字数、页数、场数、章数、时长，折成总预算，按起、中、收或幕、章分配。容器只改变粒度（副线数、配角数、场景密度），不改变因果的脊梁。
- 没有硬容器时自定预算并标“假设”。不要把历史上的数字（某类刊物的字数惯例之类）当规范。分章、分期的容量表见 SV-13。

### 单本结构：开篇、信息与结尾

**PL-04 开篇契约**
- 在开篇可感知的时间范围内（首段、首场或首章），让读者能复述“谁想要什么、被什么挡住、这是什么类型的故事”，并定下情绪基调。动作开场、人物开场、环境开场都可以；环境开场允许晚一两段接上人与欲求，把不确定记下来；背景可以后置，契约不能缺席。不设“第一段必须交代目标”的硬阈。前几章就让读者知道这本书的核心乐趣是什么，并尽快给第一次兑现；慢热作品靠简介和开篇的语气先建立预期。

**PL-09 问题早给，答案晚给**
- 先决定读者知道什么、在等什么。主线用悬念（早给问题，晚给答案）；单场可以用惊奇（藏起答案，留下线索）；反讽是观众知道而人物不知道。同一条线索里不要混用悬念和惊奇。
- 知识表和三种方式的细则见 `scene-conflict-and-rhythm` 的 SU-03、SU-04。

**PL-10 分章钩子：章末抛真问题，不是切断句子**
- 只在分次交付的载体里设钩子（连载、分幕、日更：读者在两次阅读之间离开文本）。每章、每幕末留一个未解的真问题或僵局，事件分布均匀，不按字数机械埋点。单行本连续阅读时，章末不需要硬钩子。
- 章末断在哪、下一章怎么接见 SV-09；钩子怎么写、怎么兑现见 `scene-conflict-and-rhythm` 的 SU-15、SU-16。

**PL-11 结尾两步**
- 第一步，把开篇许下的承诺逐条结算：谁要什么、谜题、威胁。第二步，找到“效果完全达成”的那一句，试删其后全部，能删就删。
- 判型：欠账（承诺没兑现，读者还在问“后来呢”）、余赘（承诺已兑现，还在写）、多线长篇（需要逐线交代，交代要短）。中间卷的卷末用 SV-04、SV-05。

**PL-12 先定判断权在谁手里**
- 结局的评价由谁来做：叙述者明说（儿童故事、寓言、通俗连载）、事件后果承担（成人文学）、读者自己判断（反讽、现代主义）。全篇保持一致，不把三种混用。本 skill 只检查一致性，不替作者决定道德立场。

### 单本结构：场景、因果与删改

**PL-05 因果验收：不是“可信”，是“不得不发生”**
- 对承重的转折与结算逐件问：它是被前文哪一条已经成立的人物事实或世界规则推出来的？答得出是内部必然（充分可解释的路径之一即可，不要求唯一）；答不出就是作者意志，要改因或改果。偶然可以触发麻烦，不能白拿解结；主题性荒诞、神话奇迹按作品的读者契约另判。

**PL-06 巧合可以开局，不能白拿解结**
- 巧合把人物推进麻烦（开局、加压）可以；巧合替人物解决麻烦（解结）时，必须三选一：前文付过账、同量级的异常配平、世界规则明示。都不满足，改因或改果。高潮的结果由主角的选择决定；喜剧和荒诞作品可以让巧合解决问题，但要有贯穿全篇的规则撑着。

**PL-07 场景功能表**
- 给每场、每章填：谁要什么、阻力、场末局面变没变、功能类型。推进（场末局面与场初不同）保留；不推进但有功能（铺垫后文要用的东西、揭示人物或世界）写清功能；无功能（删掉后无一处需要补写）删或并。只有功能没有变化的，改写或降为过场。已写成的稿子，这张表就是反向大纲：逐场一句“这场改变了什么”，找出没有变化、重复和顺序错位的场景。

**PL-08 多线汇合：先判因果汇合，还是对照并置**
- 问：有没有一个动作能同时结算两条线？有，是因果汇合：定共同落点，倒推两条线的起点。没有，但两线共享同一个问题，是对照并置：写一句共享问题，各自收束（可分章分场收，不要求同框）；中点照面可选，不是成立条件。两者都不是（只是“同时发生”），是伪多线：合并为一条线，或改成“同时性编织”。跨卷的线进 SV-08 的台账。

**PL-14 修订用“可删除性”删，不用“舍得”删**
- 逐段问：删掉它，后文的因、回声、节奏或对照是否受损？不受损即删（余赘）；受损的是承重段，保留。压缩时保留能总括情境的特征段，即使它长，删掉繁复的清单。已发表的部分不删，只在后文接。

### 分卷连载：形态与分卷

**SV-01 先定形态，再谈分卷**
- 动笔前回答两问：哪种形态？下一卷定了没有？单本闭合只用 SV-03、SV-13。系列卷每卷能单独读，班底跨卷。一部书分卷连载（多数网文）全书连续，卷是剧情阶段，卷末是否留入口、续卷回顾多长，按下一卷计划和读者阅读间隔决定。连续追捕一条主案跨多卷，不要求每卷结主案，但每卷要结一笔局部账。下一卷没定，按单本处理。

**SV-02 卷表先于故事**
- 卷是排期或售卖单位，或者作者要按计划交稿时，先填卷表：卷号、卷名（同一句式换关键词）、本卷主事件、篇幅、闭合度、下一卷第一步、节点、状态。没定的卷只写卷号，不填入口；已写的卷只改状态，不改历史。多视点作品加一列“本卷视点线”。作品简介先写人物和困境，再写钩子，不写成设定百科（`references/serial-zh-webnovel.md`）。

**SV-03 卷界按主线类型切**
- 连续时间线按关系或危机阶段切，下一卷接着上一卷的那一夜写；旅行和任务按地点、阶段切，换地点、跳时间、交代谁跟来谁留下；系列卷按结账和开口切（SV-04）。先选一种主导切法；需要混合时，写清本卷边界改变的原因。不追求等长，阶段完整就行。叙述者在终卷死去、换人续写，是终卷手法，中间卷不用。

### 分卷连载：卷末与卷首

**SV-04 闭合度看“下一卷定没定”和“本卷许诺了什么”**
- 全闭合、半开、全开都有成立的例子，不是一条升级路线。下一卷已定：留一个入口；没定：全闭合；连续追捕：可以全开，新读者靠下一卷的回顾进来（SV-07）。宿敌可以活着离场而本卷照样全闭合。作者问“哪种更好”：都成立，看合同和下一卷，没有读者数据。

**SV-05 先结账，再开口**
- 卷末先让读者核对本卷的账（比分、破案、追回的钱、获救的人、抵达的地方），再开下一步。口只开一个，而且是一个动作：密令、委任、实物、坐标、一张纸条，不是一个新组织或“新的危险正在逼近”。结账和开口之间隔一个收束动作（一段对话、一次结算、一个人物的选择），不必单独留一章。卷末四问有一问不过，先修本卷，不留给下一卷补。

**SV-06 复位世界，不复位角色**
- 卷末把能继续干活的基线还原：据点、组织、载具、班底；机构的决定可以“暂缓”，不撤销。角色的能力、关系、声望、伤亡留下来。检查角色是否留下有意义的状态变化；不可逆变化是设计选项，不为满足清单强加，也不要求必须落在配角身上；本卷刻意保持稳定时，写明原因。两种毛病：每卷回到同一基线、同一种救法（复位过度）；上一卷的伤和债消失（复位不足）。

**SV-07 续卷开头：先落当下，再补前情，再回当下**
- 续卷第一章先给一个现在时的场景（谁、在哪、在做什么），再用一段回顾补前情（人物点名、上一卷结了什么、现在要做什么），然后回到当下。长短按读者隔多久回来：可跳读、隔得久用长版；连续追读用一两句能力或关系句。章与章之间同理：新章开头不要复述前情，由人物当前的行动带出来；长时间停更后回归，用一章之内的行动把关键状态带回来，不写长篇回顾。

### 分卷连载：跨卷的线、章与期

**SV-08 开放线记账：少、可回收、每卷推进**
- 每条跨卷线写清：是什么、哪卷开、下一卷必须推进什么、最晚哪卷收、怎么收。只开写得出下一步动作的线：在逃的人、被关的人、身世和财产、半张地图或坐标。两三条活动线只作小型项目的初始提醒，不是硬上限；篇幅越长可以越多，先看容量、台账和每卷兑现能力，再决定是否开新线；超载时先收或关旧线。台账和容量比数字重要（起点）。线可以转性：旧反派变成客户或朋友，转性后不再记为债。无名组织、没有执行者的预言，先落到一个具体的人或物再开。新增设定前，先和已有设定、已发布的章节核对一遍；没发布的草稿可以改旧设定，但要记下改了什么。

**SV-09 章末落幕，下章落地**
- 分次读的章，末尾把动作推到一个点上收住，四种收法：来了一个人或一个声音（得是本章的线上的，不是凭空闯入）；提出一个要回答的问题；判定一个新事实；场景收束（人物离开、任务完成或进入新地点）。下一章第一句交代时间、地点或谁在动，不复述上章。同一种收法连续出现时，若读者已能预判且没有新变化，再换收法或改成场景收束；次数只作提醒，不设硬门。最后一章让位给卷末入口（SV-05）。一次读完的书、同一场景连着写的章可以平收。每章至少推进一条线（主线、感情线、成长线、悬念线中的一条）；章节标题保持一种风格，不剧透关键揭示。

**SV-10 每一期都不能拖**
- 分期发表，每一段都要单独站得住，至少推进一件事。写的人自己觉得长了，是一个检查信号，不等于读者必然有同样感受；回看是否重复、绕行或解释过量。对话可以推动行动、关系和信息；事件不必不断增加，重复事件若改变代价、关系或理解，也可以保留。篇幅有下限而材料不够时，讲比例、让情节在更多人物身上展开、加帮着说明主线的副线，不灌离题的内容。

### 分卷连载：套路、升级与生产

**SV-11 套路：固定骨架，每卷只换一两样**
- 固定主角、班底、事件类型和篇幅，让读者认得出；每卷换一两样（场景、道具、对手、代价、盟友的作用），分到不同的章，不在同一章里一起换（起点）。同一节拍再次出现时，检查代价、关系或结果是否变化；连续重复而没有新功能时，考虑删掉、合并，或写明这次重复不可替代的理由。

**SV-12 升级不是必选，先定系列承诺**
- 要不要加码，先问读者买的是什么：同一个主角去新地方？更高的代价？身份和位置的翻转？经营和产权？四种都有例子，没有证据说哪种更好，作者定。选定后检查：换地图会不会让每段都从零开始；加代价会不会拿走主角自己动手的机会。赌注要配得上篇幅。

**SV-13 容量先于情节**
- 合同、版式或更新节奏先定了长度，先填容量表：载体、每章字数、总章数、总字数、钩位、交稿节点、缓冲章、备用结局，再由容量推章数。按固定周期对照实际字数，周期由更新频率、合同节点和作者产能定。超了先删从属线、并章，不挪主线终点。容量表是计划，不保证写得完；别人的数字不照搬。

**SV-14 开载路线按条件选，有存稿再开**
- 完稿再发，保留“让开头配合结尾”的余地；写完若干章就开载，可能借助固定截稿节奏维持产出，代价是已发布部分难以回改。按三个条件选：首发能不能推迟？是不是靠截稿日才写得完？故事依不依赖前期埋下的伏笔？边写边发，开载检查表里写清存稿能撑几期。

**SV-15 反馈先进日志，不直接进稿**
- 连载中记反馈日志：日期、反馈渠道、具体要求、影响什么、代价、决定、复核日期。单条反馈先记录和评估；是否需要更多信号，取决于风险、样本质量和合同要求，不设统一票数。日志里按三类分流：可核的错误可以直接改正（涉及已发布设定的用后文接住）；读者看不懂的，查是不是表达出了问题；口味分歧只记录，不跟着改。常驻人物预先想好退场方式；合同允许时，留一个能提前收束的备用结局。

## 8. 冲突时

- 单本的默认顺序（没有硬约束时）：**已定的故事承诺 > 因果可信 > 场景功能 > 节奏与篇幅 > 局部文采**。
- 分卷连载的默认顺序（没有合同硬约束时）：**合同和已定的下一卷 > 本卷主线结账、系列卷能单独读 > 套路的变化 > 排期好看**。
- 目标互相冲突（又要开放又要闭合；又要删一半又要保留所有线）：列两个方案和代价，标出冲突项，作者选。
- 作者的要求和卡冲突（“每卷必须留大钩子”“每章必须断在生死关头”“我要开五条线”）：照作者的意思做出方案，同时写出代价和一个更省的替代方案，作者定。
- 作者拒绝任何删改：改走场景修订（加变化、并场、移信息）；结构问题标“未解决”。
- 框架故事要不要在结尾收回框架：闭合型作品默认不用框架；坚持用时，先写清单篇自足、读者契约、不闭合承担主题。
- 三项设计选择都有条件分支：闭合度（SV-04）、要不要升级（SV-12）、先完稿还是边写边发（SV-14）。不存在脱离读者契约、合同和作者产能的统一答案，按条件选。
- 证据范围外（影视、游戏、当代平台）：用结构问题作类比，标“推断”，不给“规律”。
- 有限经验形成的参数（约四分之三处打主结、中点照面、重复收法的检查点、活动线初始数量、卷末变化）只作可调整的默认值或诊断提示。单本部分的清单见 `references/plot-scope-and-conflicts.md` §3.3；该文件 §2 还有 13 条看法冲突的细则。

### 主要操作的失败出口

| 操作 | 缺料或受挫时 |
|---|---|
| 规划 | 缺素材只做三要素卡，不进结构（PL-16）；缺容器自定预算并标“假设”（PL-13）；缺读者契约判断权只列选项（PL-12）；工序三问答不出先补答案，仍答不出且作品闭合才默认外部大纲（PL-15） |
| 诊断 | 只给梗概时只做梗概层诊断，列出还需要哪些正文；没有文本只给检查清单与空白模板，不虚构诊断（`references/plot-diagnosis.md`） |
| 修订 | 没有目标先做诊断并按严重度给三个可选目标及代价；作者拒绝删改改走场景修订（加变化、并场、移信息），结构问题标“未解决”；未授权改稿只给定位、建议与可选最小改写（`references/plot-revision.md`） |
| 排产 | 容量参数先问合同与更新节奏；拿不到就按假设排并标“假设”，不编造平台标准（SV-13） |
| 作者不答或只回“你看着办” | 按最小改动处理，逐条列出所做的假设，不擅自扩大改动范围；两可的取舍列成方案等作者选，选定前哪一版都不落稿 |

## 9. 交付前自查

- 形态和“下一卷定没定”写了吗？
- 读了哪些、没读哪些写清了吗？每条判断有章号或短引文吗？没读到的标了“未读”吗？
- 补的假设列出来了吗？要作者拍板的问题不超过三个吗？
- 改了结构之后：主落点还被挣得吗？开篇的承诺都结算了吗？
- 已发表的部分是不是只在后文接，没有回改？
- 有没有把有限经验形成的数字当成门槛？有没有承诺追读、订阅或销量？
- 套用到网文时，平台和合同的参数是作者给的，还是自己编的？

## 11. 规则适用与验证边界

- 单本结构（PL）以闭合型、单卷和短篇的检查为主；用到开放式长篇时，按本作的读者契约、容器和实际正文检验。
- 分卷连载（SV）处理容量、卷末结算、套路变化和连续性；具体字数和比例只是可调整的默认值，不是行业标准。
- 同一案例在多个文件重复出现，不构成多次独立验证。人物自述、文本中发生的事、创作者说明和真实读者效果属于不同证据层级。
- 规则的适用条件、失败出口和验证限制写在 `references/plot-rules.md` 与各 `serial-*.md` 中。置信较高表示条件和边界较清楚，不表示读者效果已实证；反馈日志、活动线数量和不可逆变化的数量仍是建议。
- 网文迁移是设计建议；平台政策、合同条款、当前留存/订阅/销量数据需独立核验。
- 这些规则没有在真实写作任务上完成效果验证。规则是检查工具，不是生成器：表填完不等于作品完成，也不保证读者效果。

## 12. 交付状态词

对作者交付只用三个状态词；依据不是状态词，作附件逐项附上：

| 状态词 | 含义 |
|---|---|
| **已完成** | 检查已执行，且有可核的证据支持 |
| **未能核实** | 检查已执行，但结论依赖未核实的判断、设计假设或缺失的输入，不能记作已完成 |
| **待作者决定** | 存在冲突 / 取舍 / 锁定内容矛盾，由作者裁决，不擅自覆盖 |

依据随每项附证据或可核位置（不是固定答案，也不是来源背书）。

三个状态词用于对作者交付；「假设」「未读」「未知」「不适用」「待登记」是资料状态值，不是状态词，交付时按三个状态词报告该项状态，不把「假设」写成「已完成」。
