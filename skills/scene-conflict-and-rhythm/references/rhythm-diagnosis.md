# 诊断、修改单与节奏审计（SU-19）

返回 [SKILL.md](../SKILL.md)。

## 1. 诊断流程

1. 确认用户给出的文本范围、目标媒介、目标读者和本次要解决的问题。
2. 先取样开篇、中段、结尾；若有视角切换或关键转折，再取该处及相邻段落。没有稿件时停止定位式诊断，不编造段落问题。
3. 标出每个样本的主驱动：事件/情节、人物/关系或氛围/语调；混合时标主次。
4. 记录实际变化：目标、信息、关系、风险、资源、体验或语调。
5. 区分缺少必要信息、节奏太快、节奏太慢、场景功能重复和有意留白。
6. 提出最小修法，并说明可能损失；不把个人偏好写成唯一标准。

## 2. 修改单格式

| 位置 | 触发条件 | 当前效果/问题 | 最小修改 | 可能损失 | 回归检查 |
|---|---|---|---|---|---|
| | | | | | |

每条建议必须能回到文本位置。没有原稿或定位时，标「无法核对」。

本表是按 §1 流程做节奏与伏笔诊断时用的修改单。按症状出发的诊断（场景、动作、章末症状）用另一套修改单，格式见 [scene-and-action-diagnosis.md](scene-and-action-diagnosis.md) §6；两套按诊断入口选用，不互相替代。

## 3. 节奏审计表（SU-19）

| 单元 | 主驱动 | 强度变化 | 新信息/新关系 | 是否有缓冲 | 结束状态 | 需要回归的条件 |
|---|---|---|---|---|---|---|
| | | | | | | |

数字等级只作当前项目的相对标记，不是行业统计。审计重点是变化是否可辨、铺垫是否充分、后果是否兑现。

**表下另加一条检查（上面的 7 列不变）：象征／暗线在收束处出现一次。** 用作暗线的意象或物件，是否在收束处（单元末、卷末或全书结尾）落到具体画面上？中途有没有被解释句提前说破？逐单元回看，结果记在表下备注或修改单里；本单元不用暗线时标「不适用」。对应 SU-18，检查的是「出现一次且不被提前说破」，不是给暗线规定出现次数。

表承载的是单元级的变化；SKILL.md §5 的 SU-19 清单五项按下面方式核对：主峰几个、在哪，看「强度变化」列；结尾在效果达成后还写了多少，看「结束状态」列；阶梯每级升了什么、母题出现几次且语境变没变、钩子都有没有兑现章，这三项在表内没有对应列，按清单逐项另数，结果记在表下备注或修改单里。

## 4. 作者坚持某种风格时

如果作者坚持长谈、静态场景、开放结尾、密集解释、反复母题或不可靠叙述，不先把它判为缺陷。先问它要完成什么功能，再检查是否兑现该功能、是否与其他承诺冲突。保留风格不意味着免于检查；检查也不意味着必须改成主流写法。

## 5. 修订后的三项回归检查

当修订影响场景功能、视角、信息控制或时间顺序时，至少回查以下三项；与本次改动无关时标「不适用」。

1. **知识权限：** 每个判断、动作和信息披露是否符合当前聚焦者实际能看到、听到、记得或推断的内容？切换视角是否有清楚标记？
2. **时间与空间：** 事件顺序、经过时间、移动、等待、回忆和同时发生的行动是否连贯？人物是否在不可能的时间/地点获得信息？
3. **人物行动：** 人物选择是否符合当时目标、已知信息、关系压力和能力边界？心理变化是否通过行动、反应或可理解的叙述呈现？

记录格式：改动位置 → 触发的回归问题 → 实际复读的相邻段落/章节 → 观察结果 → 未解决项。

## 6. 复杂操作：判断标准、步骤、诊断到修订的闭环

适用：峰值冲突、跨章重排、伏笔与兑现一起改、多线强度这类不能一眼看出答案的操作。单场、单症状的检查按对应规则卡做即可，不走这一节。完整自创难例（含 A/B 分支与失败出口）见 [scene-cases.md](../examples/scene-cases.md) 用例 5。

### 判断标准

动笔前先判三件事，任一判不出就停在问题清单，不开始改：

1. **落在哪一层**：单元内的强度、伏笔、悬念、章末由本 skill 做；全书主线、分卷、跨卷开放线转 `story-architecture-and-longform-planning`；视角与全篇信息控制转 `character-and-narrative-control`；句子措辞转 `line-editing-and-proofreading`；卡片请求转 `preset-card-generation`。
2. **输入够不够**：有没有正文、章节或场次日、作者的目标与不能改的东西；缺哪样就先要，不凭空补。
3. **有没有冲突或取舍**：两条要求互相矛盾、两读都成立、已锁定的章节与新判断冲突、需要补写事实，都算冲突，走 A/B 分支。

### 步骤

1. 先判负触发 → 2. 定范围（目标、不能改的东西、读过的章节）→ 3. 建逐编号台账（`templates/scene-workbook.md` §7）→ 4. 按 §1 取样与对症状 → 5. 每条改法立刻复查 → 6. 冲突项走 A/B 两版，停在待作者决定 → 7. 按三个状态词交付 → 8. 负面回归。

### 诊断 → 修订闭环

每条修改都走一圈：`诊断（位置 + 症状 + 依据哪条规则）` → `修订（最小可回退改动，写明代价）` → `复查（因果、知情、伏笔可回看、强度不倒挂、章末有回应、声口未改）` → `不通过就回退，改为建议`。任一项说不清，不进入下一层，也不带着疑问落稿。修改单每条写「位置 / 触发条件 / 当前问题 / 最小修改 / 可能损失 / 回归检查」，回归检查一栏不齐全的不落稿。

### 状态词

状态词定义见 SKILL.md §9。

不把「未能核实」「待作者决定」写成「已完成」；不把未验证的效果判断写成通过。

### 负面回归

- 通读所有改过的句子与场次日，确认没有把作者有意保留的静章、静场或开放式结尾改成惯例写法，没有给中段注水，没有添出原稿没有的人物、物件或事件。
- 把「不能改」的部分遮住，确认本轮所有改动都落在允许改的范围里；落进去的撤销。
- 逐条核对降级后的场次仍保有因果必要性、信息量、人物动机；峰值冲突没有变成二次高潮；伏笔删掉所在句后当下场景仍成立。
- 把这一轮暴露出来的新误判写进下一轮的复查项；没有依据的地方按作者判断。

## 7. 失败出口

失败出口与 SKILL.md §10 同一张表，按那边的情形与出口执行；本节不再另列，避免两表行数漂移。
