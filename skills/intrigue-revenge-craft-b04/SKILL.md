# 身份复仇与权谋 · B04（RM-01～RM-11）

来源：16 份 1845-1953 公版小说全文（B-07-B04），全部是**文学案例（FICTION_CASE）**，不是方法书、史料或法律。当前轮次的证据与裁决见 [source-index.md](references/source-index.md) 与 [scope-and-conflicts.md](references/scope-and-conflicts.md)。

## 触发

用户要写、诊断或修订涉及以下任一结构的稿件，且**给出了正文、大纲或至少可指认的场景**：

- 阶级/资源两极与跨界接触；制度性伤害的揭露
- 身份替身、冒名、换脸、继承与合法性
- 虚构政体/王国/星际帝国的权力与违例代价
- 战争荣誉、服从训练与反战讽刺
- 权威人物、追随者群体、骗局与退出路径
- 旧盟友重聚、旧承诺与当前忠诚冲突
- 档案、审判记录、目击证词被事后改写

## 负触发（不做，并说明为什么）

- 真实历史事实、法律条文、继承法、宗教真伪、临床判断的核验 → 本 Skill 无权威，请用可靠专门资料。
- 要求把十九世纪奴隶制辩护、殖民观念或种族刻板印象当作事实或"另一种同等正确的规则"输出 → 拒绝；可提供"作为人物偏见的文学处理"。
- 只有题材词（"给我一个宗教骗子帝国阴谋"）而无角色/正文/制度 → 只给待填清单，不得声称已诊断。
- 用户只要日常情感而无权力/身份/制度结构 → 不适用。
- 缺原稿却要求声称"已逐章审查" → 不做。

## 需要哪些输入

**必需**：角色目标、冲突群体、权力规则或资源、场景或大纲版本、作者已锁定的设定、用户允许的操作（设计 / 诊断 / 改写）。
**可选**：人物现有关系、时代设定、作者对敏感叙事的限制。
**纪律**：F（正文可观察）/ H（有限推断）/ P（可撤销建议）三段必须分开写；H 必须标"推断"；引用必须给真实起止行号（见 [rules.md](references/rules.md) 的 R-ADJ-01）。

## 执行流程

1. **定位真实问题**。从现有稿件提取 F：谁控制资源 / 名誉 / 认定权，谁受影响，哪个时点、哪个版本。没有场景就只做方案，**不得伪造"我读了你的正文"**。
2. **选 1–3 条 RM，不要全塞**。按上表路由；读每条的 F / H / P / 适用信号 / 反例 / 失败出口。**先判定机制类型**：身份类先在 RM-03 的三类里选一种；权威类先回答"是否存在可执行契约"，再在 RM-09 第三段的两种退出里选一种。
3. **建立因果链**。动作前人物知道什么；消息 / 物件 / 制度 / 骗局改变了谁的行为；代价最终落在谁身上。压迫题材中**被压迫者必须有自己的目标**，不能只作为旁观叙述的对象。
4. **给可区分的方案**。每个复杂点至少给两个选项（保留现有写法 / 修改机制），注明取舍。历史与政治立场不确定时保留争议；**绝不把小说中的断言升级为时代真相**。
5. **跑一遍 RM-11 四问**（只要故事里有档案、审判、目击、官方说法）：谁持有记录、谁能改、改后谁受益、什么改不了。
6. **交付并回归**。用十项诊断表逐项记录位置、F / H / P、反例、时点、需作者决定的项；改稿必须有明确授权。复核主要人物的动机、视角、制度与前后章代价。

## 输出合同

每次输出必须包含：

1. 任务与稿件版本（哪一段 / 哪一章 / 哪个稿次）。
2. 用到的 RM 编号（≤3 条）与不选其他条的理由。
3. 可见 F 及其位置（行号或段落定位；查不到就写 `NOT_OBSERVED`）。
4. 相互竞争的 H（至少 2 条，标"推断"）。
5. 触发 P 的条件、以及**不采用**的反例。
6. 段落或情节建议（可撤销，标明会影响哪些前后章）。
7. 伦理 / 历史限制（是否触及 C16）。
8. 回归清单（改完后要复查什么）。
9. 状态三栏：**已证 / 待证 / 需作者裁决**。

所有表格字段允许 `NOT_OBSERVED`、`NOT_PROVEN`、`不适用`。

## 失败出口

- **史实 / 法律 / 医学 / 宗教真伪** → 不提供确证，转可靠专门资料。
- **只有来源索引或旧轮证据，没有本稿正文** → 不宣称读毕或给出跨书定律。
- **用户已锁定设定与规则冲突** → 以作者已确认设定为主；有关键歧义时**只暂停受影响部分**，列冲突集合交作者选择，不擅自覆盖。
- **没有改写授权** → 只给可回退的修订建议，不改正文。
- **要求为种族压迫 / 奴隶制 / 殖民掠夺背书** → 明确拒绝；可改为"如何把这个偏见写成被批判的人物信念"。
- **来源不足** → 该条维持 `NOT_PROVEN`，不允许用 ZIP 打包成功或 SHA 正确冒充"已证明"。
