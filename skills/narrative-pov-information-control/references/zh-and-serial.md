# 中文写作与网文连载的迁移

返回 [SKILL.md](../SKILL.md)。

本文件是本 skill 把 PV 规则用到中文稿和网文连载时的建议。来源没有讨论中文和网文，这里没有来源和读者数据支持，作为起点使用，按作品调整。例句都是为说明而编写的。

## 1. 称呼就是视点

中文里，称呼最直接地暴露“此刻是谁在看”。

- 同一个人，女儿叫“我爸”，学生叫“周老师”，邻居叫“老周”，叙述者叫“周建国”。视点人物是谁，称呼就跟着谁走。
- 一场之内称呼要稳定。贴身距离下，称呼突然从“我爸”变成“周建国”，读者会感到镜头跳了。
- 切换视点时，称呼也跟着换，这本身就是一个标记：前一场叫“师父”，下一场叫“那个老头”，读者立刻知道换了眼睛。
- 检查方法：把一场戏里所有对其他人物的称呼标出来，看是不是都属于同一个视点人物。

## 2. 没有时态时怎样控制距离

英文靠时态和引语形式区分叙述者的话和人物的念头，中文没有时态变化，“他想”又常被省略，越界因此更隐蔽。

- **问“这句是谁的话”**：每个判断句（“这简直是胡闹”）属于视点人物还是叙述者？贴身距离下属于人物，可以；远距离下突然出现人物的口气，就是距离跳了（PV-07）。
- **语气词和句末标点是距离标记**：“这算什么事啊。”“他凭什么？”这类句子把叙述拉到人物身边。远距离叙述里少用。
- **时间词代替时态**：“那时”“后来”“多年以后”“这时候”承担时态的工作。要压到当下，删掉“后来”；要拉开，用“那时她还不知道”——这是一次提前揭示（PV-15）。
- **“他知道”“他明白”“他意识到”**：中文稿里这类词常常是作者在借人物的嘴交代信息。删掉后句子仍然成立，就删；不成立，检查他是否真的有途径知道（PV-04）。

## 3. 网文里常见的视角做法

| 做法 | 对应规则 | 要注意的 |
|---|---|---|
| 第一人称或第三人称紧贴主角 | PV-03、PV-04 | 主角不在场的事，要通过手下汇报、消息、监控、系统提示进入，不能直接写 |
| “与此同时，千里之外……”切到反派或配角 | PV-05 | 这是一次切换，要有收益。只为告诉读者“反派在谋划”的切换，常常可以改为主角收到的情报 |
| 读者知道主角的底牌，对手不知道（扮猪吃虎、打脸） | PV-09 的“读者在前” | 紧张来自“对手什么时候发现、发现时会怎样”；底牌要提前交代给读者，不能临场新加 |
| 配角和路人的反应（“众人倒吸一口凉气”） | PV-05、PV-07 | 在主角视点里写群体反应是可以的，只写看得见、听得见的；写进路人的内心就是切换，要算账 |
| 群像文、多主角文 | PV-05 | 每个视点的章节在章题或首句标明人物；建切换账本；保留一条主视点线让读者有地方回来 |

## 4. 系统面板、弹幕、群聊、帖子：文件类装置

这些形式和书信、日记、证词一样，是把信息合法地带进书里的装置（PV-04 的合法化装置）。

- 写清规则：谁在写、能不能说谎、主角能看到哪些、读者能看到哪些。规则一旦定下，就是合同的一部分。
- 系统提示是“无名全知”的一种：它知道主角不知道的事。要么给它限度（它只报告数值、不解释原因），要么接受它是全知并保持语气一致。
- 弹幕和评论是群体视点：可以替主角补光（PV-06），也可以制造反讽（观众知道主播不知道的事）。
- 不要让装置成为随叫随到的信息来源：每当剧情需要交代就“叮”一声，读者会感到作者在递纸条。

## 5. 重生、穿越、回溯：时间合同

主角带着未来的信息回来，这是一个时间错位的叙述（PV-09、PV-15）。先写清三件事：

1. 主角知道哪些未来？知道得多细？
2. 叙述会不会提前告诉读者这些未来？什么时候告诉？
3. 主角的行动改变了未来以后，他的信息从什么时候开始失效？

常见问题：主角前文说“前世这时候我还不知道这件事”，后文又突然想起一件前世的关键事件，正好救场。这和“叙述者进了心却装不知道”是同一个问题。修法：把主角记得的关键未来提前交代给读者，让紧张来自“他能不能改变”，而不是“他突然想起来”。

## 6. 日更连载的视角

- **每章开头重新锚定**：读者隔了一天才读下一章，第一段就让读者知道谁在看、在哪里、离上一章过了多久。
- **章末的视角**：章末停在视点人物的一个发现或决定上，比停在一句作者旁白上更有力。章末钩子的做法见 `foreshadowing-and-rhythm` 的 SU-15。
- **长期连载的视点漂移**：连载几十万字后，主视点人物的用词常常慢慢变成作者自己的用词。隔一段时间抽查一章：称呼、口头禅、他会注意的东西，和开头时是否一致；不一致的，确认是人物的成长还是漂移。
- **卷级的视点分配**（哪一卷加入新视点、哪条视点线什么时候收）：转 `serialized-volume-planning`。
