# 改稿与审稿

本文用于润色、去除 AI 味、重写片段和审阅章节。病灶和改写方向见 [expression.md](expression.md)。

## 三层诊断

按从上到下的顺序检查。上层有问题时，下层的修改效果有限。

| 层 | 检查的问题 | 常见问题 | 处理 |
| :--- | :--- | :--- | :--- |
| 推进 | 这一章变了什么？谁付出了代价？读者追的东西给了没有？ | 没有变化；胜利没有代价；换场景后状态清零；信息没有来路或临时出现；每章同一种钩子；最该写足的地方一笔带过 | 涉及改动情节。先向用户说明并给出方案，不自行改故事 |
| 文风 | 口气是否前后一致？视角是否越界？ | 视角漂移；用词忽雅忽俗；人人一个腔调 | 按既定文风统一 |
| 表达 | 是否命中病灶表中的病灶？ | 库存反应、结尾总结、情绪标签、对照句式、模板段落 | 逐处改写 |

推进问题的判断依据见 [progression.md](progression.md)，文风问题见 [style.md](style.md)。

## 改稿步骤

1. **通读，先不改。** 标出命中的原句和它所属的层。
2. **推进层有问题时先报告。** 用户只要求润色时不动情节，把推进层的问题写在说明里。
3. **逐处改写表达层。** 判据成立才改。保持事实和信息量不变。只使用场景中已有的材料；需要新增材料时标明是建议。
4. **复读。** 检查过度纠正：一串碎句、人人说谜语、没有任何情绪、流水账。检查改后的口气是否仍是作者的口气。
5. **交付。** 改后的正文，加几句说明：改了哪几类问题，哪些没有动以及原因。

## 改稿的边界

- 不改作者的风格选择：全知叙述、口语、方言、有意的重复。
- 不把所有句子改短，不把所有情绪改成动作，不删除全部比喻。
- 不抹去人物的说话习惯。
- 用户指定只改某一类问题时，只改那一类。
- 改动幅度按用户要求分三档：只删改命中的句子；重写命中的段落；重写场景。用户没有说明时取前两档。

## 去除 AI 味的检查顺序

按这个顺序可以最快找到大部分问题。每一处按 [expression.md](expression.md) 病灶表中的判据确认后再改。

1. **查位置。** 每场戏和每章的最后三句；每段的最后一句；对白的提示语。
2. **查构式。** “一抹／一丝＋抽象名词”；“不是……而是……”；三连和排比；破折号和冒号的揭示用法。
3. **查形状。** 连续三段的结构是否相同；段落长度是否均匀；是否每段都以短句收尾。
4. **查对白。** 遮住名字能否分出说话的人；是否有人在讲双方都知道的事；是否有人把自己的感受说得过于准确。
5. **查重复。** 动作之后是否又解释了一遍；同一种反应在一章内是否出现第二次。

## 审稿报告

报告包含四部分：

1. **总评。** 两三句，指出最影响阅读的一到三个问题。
2. **问题清单。** 按对读者的影响排序。每一项写成：原句 → 判定依据 → 对读者的影响 → 改法，并给出一处改写示范。
3. **应当保留的写法。** 具体到句，一两处即可。用于防止后续修改把有效的写法改掉。
4. **未能判断的部分。** 缺少上下文而无法确认的问题。

审稿条目示例：

- 原句：章末的“这一刻，她终于明白，有些人注定只是过客。”
- 判定依据：这一句是评论，不是正在发生的事。前文已经用“把杯子放回去，杯口朝下”演出了同一层意思。
- 对读者的影响：读者自己得出的结论被说破，结尾的力量被抵消。
- 改法：删除这一句，章末停在杯子上。

只要求审阅时，交付报告，不改写原文。
