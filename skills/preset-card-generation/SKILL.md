# 预设卡片生成

本 Skill 专注于小说创作提示词预设卡的生成、诊断与修订，按三条轴处理：

- **推进**：这条剧情线靠什么往前走，读者追的是什么。
- **文风**：已经定好的故事，用什么口气写出来。
- **表达**：句子层面的通病，包括常说的 AI 味。

规划、写作、改稿、审稿和写预设卡共用这三条轴。每条轴一份参考资料，按任务读取对应部分，不通读全部资料。

## 通用原则

1. **保留用户的设定。** 题材、人物、视角、已写内容、指定的格式和篇幅都不改。发现问题先指出，不替用户改故事。
2. **判断落在稿面上。** 每个问题指向原句；每条要求能在稿子上数出来、查出来、判出来，或由示例演出来。不以“有 AI 味”“不够高级”作结论。
3. **先推进，后文风，再表达。** 一章里没有任何东西发生变化时，润色句子没有用。按这个顺序诊断和修改。
4. **改根因，不换词。** 删掉一个套话词，相邻的套话会补上来。给那个位置一件只有本场景才有的事来写。
5. **防止过度纠正。** 每收紧一处，检查是否写成了相反的毛病：一串碎句、人人说谜语、没有任何情绪、流水账。
6. **示例和样句原创。** 不使用真实作品的原文、人物和名句。
7. **不确定的事实写明不确定。** 历史、行业、制度类事实无法核实时说明，不编造。

## 规划

开新书或排章纲时，先按 [planning.md](references/planning.md) 完成定位、人物和台账，再按下面七步设计推进。

1. 用一句话写出读者追的是什么：谁，靠什么，得到什么或躲开什么。把这句话换到相邻类型上仍然成立，就重写。
2. 确定小循环：三到五环的因果链，写明跨度（通常一到三章）和一圈的终点。终点用本类型的最小变化单位定义。
3. 确定大循环：一卷从哪里走到哪里，卷末交付什么，下一卷换了什么。
4. 逐章安排开局三章各交付什么，并标出读者第一次尝到甜头的章。
5. 设计加码：每升一档更换一种麻烦，旧办法为什么失效，代价怎样上升。
6. 规定每章落点：封闭清单加下限，章末按本章实际变化选择落点。
7. 列出四到六条本类型特有的崩点，并与前面各项核对，确认不冲突。

各类型的引擎要点、机制条款和示例见 [progression.md](references/progression.md)。

## 写章节

1. 确认输入：本章任务、前文状态、视角、文风。缺少的先从上下文中找，找不到的关键项说明所作假设。
2. 确定本章的变化：章末与章首相比，局面、关系、认知、资源中至少一项不同。
3. 安排场景：每场戏写清谁想要什么、遇到什么、结果改变了什么。从事情开始处进场，变化落定后离场。
4. 按文风写作。视角人物只知道他有途径知道的事。
5. 用 [expression.md](references/expression.md) 的病灶表自查并修改。
6. 核对连续性：伤势、物件、承诺、已知信息与前文一致。

详细做法见 [writing.md](references/writing.md)。

## 改稿与审稿

1. 通读全文，标出命中的原句。
2. 按推进、文风、表达三层归类，先处理上层。
3. 修改时保持事实和信息量不变，只改命中处。
4. 复读修改处，检查是否出现过度纠正。

审稿报告的每一项写成：原句 → 判定依据 → 对读者的影响 → 改法。详细做法见 [revision.md](references/revision.md)。

## 预设卡

预设卡是交给生成模型的提示词。它每次调用都会被读到，并被逐条执行。写卡的方法：

1. 确定卡种和本卡的专属机制。把卡名换成相邻的卡后仍成立的句子删除。
2. 为每条要求选择一种稿面判据：能数、能查、能判、能演。
3. 每条禁令写齐病灶、判据、同位替代、封闭豁免、反向护栏。
4. 示例兑现本卡自己的规则。
5. 让作者也读得懂。禁止的句子带“不要”，要做的带“应当”，放行的带“可以”；冒号后面要出现反转时，这一行不用冒号。做法见 [card-method.md](references/card-method.md) 第 7 节。
6. 按 [card-pitfalls.md](references/card-pitfalls.md) 逐条自查后交付。

三类卡的格式和示例卡分别在 [progression.md](references/progression.md)、[style.md](references/style.md)、[expression.md](references/expression.md) 的“写成卡”一节。用户指定格式时以用户为准。

## 交付前检查

正文类交付：

- 本章有可指认的变化，章末落在实际发生的变化上。
- 视角没有越界，状态与前文一致。
- 没有演完之后再解释一遍的句子，没有结尾的总结和升华。
- 没有出现过度纠正的形态。
- 篇幅、格式符合用户要求。

卡片类交付：

- 每条要求有稿面判据，数量要求带单位和范围。
- 正面要求与禁项、崩点不冲突；示例不违反本卡规则。
- 禁令有替代，豁免不放行被禁对象本身。
- 没有换一张卡名仍然成立的句子，没有越出本卡职责的条款。
- 没有占位符、残句和自我评价；字数在格式规定之内。

## 输出约定

- 用户只要正文或卡片时，直接给出可复制的成品。分析过程、缺陷标识、来源不写入成品。
- 只要求审阅时交付问题和改法，不自动改写文件。
- 改稿以成品为主，必要时用几句话说明净变化。
- 未经实际生成测试的效果不作保证，说明哪些已核对、哪些未验证。
