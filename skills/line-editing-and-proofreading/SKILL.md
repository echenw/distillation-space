# 语言精修与校对

处理句子、段落、用词和标点这一层：让文字更清楚、更有力、更统一。剧情、人物、视角、结构不在这里改。

## 1. 什么时候用

先判负触发，再定接不接。完整演示见 `examples/worked-example.md` 例三「先判负触发」。

### 1.1 触发（接）

- 作者要“润色”“精修”“改得顺一点”“校对一遍”“查错别字和标点”。
- 句子绕、主语对不上、长定语堆在一起、读起来拗口。
- 冗词多、套话多、AI 腔重（“嘴角勾起一抹弧度”“空气仿佛凝固了”）。
- 对白标点、引号、省略号、破折号用法混乱；全角半角混用；数字写法前后不一。
- 人名、称谓、专有名词前后写法不一致。

### 1.2 负触发（不接，先转介或停下）

- 要改剧情、结构、分章分卷、删场，或问题出在人物、视角、场景节奏：不在句子层，转对应的 skill（见 §1.3）。
- 只要梗概或只给一句、却要求逐条改稿：先要正文；看不出上下文的判断写明「缺上下文」，不凭空列错误。
- 要打分、评级、批量自动替换、或裁定「唯一正确」：本 skill 给逐条建议，不打分；批量替换只对确定的错别字和标点做，并先列替换清单。
- 要写成预设卡、约束卡，或要求按「推进／文风／表达」三轴审章节：产物是卡或三轴框架，转 `preset-card-generation`。
- 要整段重写、或改动超出句子层：先问清方向和边界；作者单独授权后也只做点名范围内的有限改写，逐条记台账、不添事实。
- 要核实外部事实、考据或专业断言真伪：本 skill 只标出疑点，转 `fiction-planning-and-diagnosis` 的事实核查流程。
- 作者有意保留的口语、方言、意识流、实验文体：默认保留，只标出可能是笔误的不一致。

### 1.3 转给别的 skill

- 情节、结构、分章分卷、删场 → `story-architecture-and-longform-planning`
- 场景、对白内容、铺垫、悬念和节奏 → `scene-conflict-and-rhythm`
- 人物、视角越界、信息安排、时间顺序 → `character-and-narrative-control`；语言修改会改变人物声口、叙述权限或视角时，停在那一处转过去确认
- 整章该不该这样写、整体诊断、读者反馈 → `fiction-planning-and-diagnosis`；不用润色掩盖因果或结构问题
- 某一题材的写法 → `genre-fiction-craft`；改编成剧本或分场稿 → `cross-media-drama-adaptation`（对白、字幕和界面文字仍可在本 skill 精修，选择逻辑、状态条件和分支结果不动）
- 事实核查、考据：本 skill 只标出疑点，核实转 `fiction-planning-and-diagnosis`
- 生成或修订预设卡、写反 AI 味的约束卡、按三轴审章节 → `preset-card-generation`

从 `genre-fiction-craft` 转入本 skill 的：句子和对白的措辞、标点、校对。
从 `character-and-narrative-control` 转入本 skill 的：句子、对白的措辞、标点、语感、校对。
从 `preset-card-generation` 转入本 skill 的：改具体稿子去 AI 味（产物是改好的文本）、一般性的句子精修与校对。产物是给模型的卡，或要按推进／文风／表达三轴审时，转回 `preset-card-generation`。

## 2. 使用方式

- 宿主任务规定了输出格式时，按宿主格式交付。本文件的表格和字段只在没有规定时使用。
- 普通润色和校对，读完本文件就能做。需要细则时读对应的参考文件（见 §7），只读用得到的部分。
- 判断是中文还是英文。英文稿走 §6 和 §7 列出的四份英文参考文件；中英混排时，中文部分按中文规则，英文引文和专名不改。

## 3. 先定三件事（第 0 轮）

动手前用一两句话确定：

1. **改到什么程度**。轻校对只改确定的错误（错别字、标点、的地得、明显病句）；精修还会调整句子和用词；作者把范围划得更窄时（“只改标点，别的都别动”），按作者的范围执行；改写已经超出本 skill，需要作者单独授权——授权后也只做作者点名范围内的有限改写，逐条记台账、不添事实；开放性的重写先问清方向和边界再动手。
2. **按什么体例**。作者或宿主有体例就照办；没有时，以稿子里占多数的写法为准，全稿统一，不另立一套。人名和专名的写法影响全书，不适用稿内多数：先列出各写法出现的位置，问作者以哪个为准再改。
3. **哪些不能动**。人物对白里的口语、方言、语病和口头禅，作者刻意用的短句、碎句、重复和长句，都是声口，默认保留。

这三件事不清楚、但又不影响确定的错误时，先改确定的错误，把需要作者拿主意的地方列成问题。

## 4. 按层次修改（第 1–6 轮）

从大到小，一层只改一类问题，避免改了上层又打乱下层。短稿可以合并几层；跳过某层时说一句为什么。

| 轮 | 层次 | 只做什么 | 主要规则 |
|---|---|---|---|
| 1 | 段落 | 一段一个动作单元或一个意思；换说话人另起段；过渡和收束是否到位 | SR-01、SR-02 |
| 2 | 句子骨架 | 主语和修饰语对得上；成分不残缺、搭配得当；语序和辖域清楚 | SR-03 至 SR-06 |
| 3 | 强调与节奏 | 重要信息放句末；连续同型句换一换；平行结构外形一致 | SR-07 至 SR-09 |
| 4 | 简洁与用词 | 删不起作用的词；抽象改具体（原文支持时）；套话整句重写 | SR-10 至 SR-12 |
| 5 | 机械校对 | 标点、对白格式、的地得、数字、错别字、全稿体例统一 | SR-13 至 SR-15 |
| 6 | 誊清复核 | 只落定已确认的修改；通读一遍，看改动有没有引入新问题 | SR-16 |

## 5. 核心规则

每条规则先说做什么，再说什么时候不用。完整说明和例句在 `references/zh-sentence-and-wording.md`（SR-01 至 SR-12、SR-16）和 `references/zh-mechanics.md`（SR-13 至 SR-15）。括号里是对应的英文内部规则编号。

**SR-01 一段一事（EN-17、EN-18、EN-20、EN-23）。** 叙事段落以一个动作单元、一个场景焦点或一个意思为单位；一段里混了两件事就拆，被切断的因果就并。不适用：网文的短段、作者用单句段制造停顿，都不必合并。说明性段落才默认要有主题句，叙事段不硬加。

**SR-02 对白换人另起段（EN-21）。** 每换一个说话人就另起一段；说话人的动作和神态跟着他自己的那段。不适用：同一人连续说话中间夹一个动作，通常仍在同一段。

**SR-03 修饰语和主语对得上（EN-11）。** “作为一名医生，病人的安危……”“通过这次谈话，使他明白了……”这类句子，开头短语的施事和主语不一致或缺主语。改主语，或把开头改成完整分句。

**SR-04 成分齐全、搭配得当。** 查缺主语、缺宾语中心词、主谓或动宾不搭配（“改善……水平”“提高……面貌”）。只改确定的病句；人物口语里的不完整句是声口，不改。

**SR-05 语序清楚，副词辖域明确（EN-14）。** “只、都、也、不、又”放在它真正管的成分前面；“我只见过他两次”和“只有我见过他”意思不同。多层长定语（“那个站在门口穿着灰大衣手里攥着信的男人”）拆成两句或把一部分移到后面。

**SR-06 被动按段落主语选择（EN-12）。** 不是见“被”就改。先看这一段谈的是谁，谈谁就让谁作主语。中文“被”字句多带不如意色彩，欧化的“被告知”“被认为”“被视为”通常可以改成“有人告诉他”“大家都觉得”。施事不重要或不知道时，保留被动。

**SR-07 要强调的放句末（EN-15）。** 中文的新信息和重点通常落在句末。句子尾巴是旧信息或虚词时，调序让关键词收尾。不适用：不是每句都要“金句结尾”。段落最后一句给出本段的重要后果时，回扣和强调同时成立，不必二选一；末句不属于本段时才移走（EN-17）。章末或段末的最后一句，落在一个动作、一句台词或一个物件上，常比总结式的感慨更有余味；喜剧的笑点也放在句末或段末，别把包袱提前抖出来（喜剧怎么写转 `genre-fiction-craft`）。

**SR-08 连续同型句要换。** 连着几句“他……。他……。他……。”或一串“……，然后……，接着……”，读起来像流水账。换掉几句的句式就够，不必全改。作者有意的排比和重复保留。节奏要服务张力：紧张时短句和动作动词多一些，舒缓时句子可以长一些；全篇不要只有一种节奏，紧张段也不要全是碎句。

**SR-09 并列的东西外形一致（EN-05）。** 并列词语词性一致；“既……又……”“不仅……而且……”两边结构相同。

**SR-10 删不起作用的词，不是越短越好（EN-24、EN-25）。** 删语义重复（“凯旋归来”“亲眼目睹”“大约……左右”“涉及到”）、空转结构（“进行了讨论”“作出了决定”“开始哭了起来”）和多余的“一个”“的时候”“了”。删之前问：删掉后意思、范围、语气变不变？变了就不删。“只、都、除非、除了”这类限定词不能随手删。

**SR-11 具体、确定、可感，但不添事实（EN-26）。** “他很生气”可以改成能看见的动作，前提是上下文支持；原文没有的细节不能替作者编。不是细节越多越好，只补能改变读者画面的那一个。感官也要选，不要列：每处只用最能代表这一刻的一两种，感官本身是情节线索时可以写细。情绪最重的地方，收着写常比直说更有力：让动作和细节替人物哭，删掉替读者下结论的感叹；这类改动会改变强度，先列为建议（SR-16）。喜剧和儿童文学可以直白。

**SR-12 套话整句重写，不换同义词（EN-27）。** 套话的问题是没说出具体意思，换个说法还是空的。先问这句到底想说什么，再整句重写。常见的 AI 腔：神态模板（“嘴角勾起一抹弧度”“眼中闪过一丝……”）、气氛模板（“空气仿佛凝固了”）、情绪直陈（“心中五味杂陈”）、比喻堆叠（连串“仿佛”“宛如”）、段尾升华（“这一刻，他终于明白了……”）。不适用：人物对白里的套话可能正是人物性格。对白里人物互相讲彼此早就知道的事（“你也知道，……”），是在说给读者听：语言层只删掉这类提示语；信息该怎么交代，转 `scene-conflict-and-rhythm`。宣誓、审判这类仪式性场合，重述本身有功能，不动。

**SR-13 标点按国家标准（GB/T 15834-2011）。** 中文用全角标点；引号用“”，引号里再用‘’；省略号“……”、破折号“——”各占两格；并列的书名号、引号之间通常不加顿号；相邻数字表示概数（“三四个”）不加顿号。细则见 `references/zh-mechanics.md`。

**SR-14 对白格式全稿统一。** 提示语在前用冒号：他说：“……”。说话动词插在中间：“……，”他说，“……。”中间是动作而不是“说”时，前后各自成句：“你来了。”他放下杯子。“坐吧。”提示语在后时，“……。”他说。和“……，”他说。两种写法都常见，选一种全稿统一。说话动词多用“说”，或用动作带出说话人；少用“咆哮道”“冷笑道”这类自带情绪的动词，情绪交给台词和动作。这类改动会改变语气，先列为建议；童书和喜剧可以写得更夸张。

**SR-15 的地得、数字、错别字、体例统一。** 的接名词，地接动词，得引出补语。叙述里的数量、年龄、时间通常用汉字数字，统计、编号、计量用阿拉伯数字，同一稿统一（GB/T 15835-2011）。人名、称谓、地名、招式、组织名，全稿写法一致。年龄、日期、行程时间、金额、距离记进全稿体例表，改一处要连带检查其他地方。常见错别字、易混词和体例表见 `references/zh-mechanics.md`。

**SR-16 改动可回退，作者有最后决定权（流程见 `references/workflow.md`）。** 每处修改都能对回原句；改变语气、强度或意思的修改先列为建议。两种改法各有道理时，给出两版和代价，由作者选。

## 8. 交付

没有宿主格式时，按下面交付：

- **要求直接改的**（“帮我润色”“改一版”）：给改好的文本，后面附简短的改动说明：改变了句子结构、语气或用词的逐条列，标点和错别字合并成一句。只要正文时，只给正文和一两句说明。拿不准的地方保留用户稿件原句，列在最后问作者。
- **要求审阅的**（“看看哪里有问题”）：逐条列出 `位置 | 问题 | 改法 | 依据 | 风险或需作者确认`。位置具体到段、句或词，不写“全文有点啰嗦”。按影响排序：先列影响理解和追读的问题（意思不清、指代错、事实疑点），再列句子和用词，最后列标点和体例；确定的校对错误可以直接改，不必等排序。
- 每项实质修改都能对回原文位置；原稿、未决的改法和作者拒绝的修改都要留着，可以恢复。
- 没有给原文时，说明需要哪一段文字，不凭空举“稿子里的错”。只给一句时，先改这一句里能确定的错误，依赖上下文的判断写明“缺上下文”。

### 8.1 交付状态词

对作者交付只用三个状态词，不写审计词或状态码；依据不是状态词，作附件逐项附上：

| 状态词 | 什么时候用 |
|---|---|
| 已完成 | 检查已执行，且有稿件内可核的证据支持 |
| 未能核实 | 检查已执行，但结论依赖未核实的判断、设计假设或缺失的输入，不能记作已完成 |
| 待作者决定 | 存在冲突、取舍或锁定内容矛盾，由作者裁决，不擅自覆盖 |

依据随每项附证据或稿件内可核位置（不是固定答案，也不是来源背书）。

三个状态词也用于逐条台账的「状态」列，依据填在同一行的「稿件证据位置」；「未知」是状态列的合法值，但不得把未知写成已完成。

### 8.2 失败出口

遇到下面情况不再改，列问题清单交作者；具体停手信号见 `references/workflow.md` 的「停手情形」：

| 情形 | 出口 |
|---|---|
| 没有原文、只有一句 | 请作者给出要改的文字；先改能确定的错误，其余写明「缺上下文」 |
| 口语、方言、意识流、实验文体 | 只标出可能是笔误的不一致，其余不动 |
| 两条要求互相矛盾、指代或从句两可 | 给 A／B 两版和各自代价，停在待作者决定，其余修改照做 |
| 需要补写事实，或问题出在剧情、人物、视角 | 停在语言层；具体化不能补写事实，把问题转给对应 skill |
| 体例分歧、没有体例要求 | 列体例选项请作者定，或按稿内多数统一；各半分不出多数时先不改 |
| 要打分、批量自动替换、裁定唯一正确 | 说明本 skill 给逐条建议，不打分；批量替换先列清单，只对确定的错别字和标点做 |
| 生成或修订预设卡、按三轴审章节 | 转 `preset-card-generation` |
| 作者不回答或只回「你看着办」 | 按最小改动处理，逐条列出所做的假设，不擅自扩大改动范围 |

## 9. 适用边界与事实核查

- 这些规则是编辑检查工具，不是评分标准。是否采纳由作者决定。
- 本 Skill 不替作者核实外部事实；发现事实疑点时标出原句与待核问题，交给相应的事实核查流程。哪些内容算专业事实没有固定清单：句子涉及医疗、法律、科技、考据等专门领域的说法而真实性拿不准时，一律按疑点标出转核查，宁可多标。
- 语言建议不得改变事实、情节、人物目标与立场、人物关系、叙述权限、视角、时间结构或作者有意保留的声口。
