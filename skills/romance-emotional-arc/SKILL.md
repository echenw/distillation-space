# romance-emotional-arc

本 Skill 是 B-03-B03 的 P4 消费者包。18/18 来源当前均有连续 FULL 阅读证据且正文 SHA 与元数据匹配；小说里的做法只记为 **F（FICTION_CASE）**。跨书归纳记 **H**，给作者的动作才是 **P**。历史文本里的强迫、阶层、婚姻制度与性别角色不得直接升级成规范。

## 1. 输入与判断

先确认：任务是从零设计、诊断还是改写；两位（或多位）人物各自目标、可拒绝范围、既有关系状态、世界/时代约束、允许改动范围。诊断已有文本时原稿是必要输入；从零设计时可直接建立假设，但必须把假设写明。

先做四个判断：
1. **主轴**：删掉关系线后主冲突是否仍基本成立？若成立，只把本 Skill 当副线工具，不强套完整弧。
2. **自主权**：每个关系参与者是否拥有可观察的目标、拒绝/退出权与关系之外的身份？若没有，先修这一层。
3. **阻力类型**：阻力来自目标冲突、信息差、资源/制度、责任、过去伤害、距离，还是单纯作者拖延？最后一种应删除或改成真实约束。
4. **关系状态**：当前是陌生、试探、互惠、拒绝、破裂、修复还是结束？不能把沉默、冻结、依赖、照护或权力差当同意。

## 2. 执行流程

### A. 建立关系基线
为每个核心人物写三行：`我想要什么 / 我不愿付什么代价 / 我现在愿意给这段关系什么`。若需要早期立场，用 R1；立场可改变，也可以不改变。

### B. 选择真实阻力
用 R4 把抽象“不能在一起”拆成可验证限制。每个限制写 `Owner/来源 → 如何限制行动 → 谁能改变 → 代价`。不要为了恋爱线把支持型家人硬改成反派。

### C. 管理信息与接近
只有当“别人如何评价这个人”会改变选择时才用 R2。用 R3 读懂沉默/回避：先判断边界，再决定是否继续交流。需要反转时用 R9，确保揭示前已有可回读信号。

### D. 让关系通过选择推进
推进必须来自至少一方的可选择行动：提供信息、承担责任、承认伤害、改变计划、接受/拒绝邀请、退出旧承诺等。缺席（R5）和信物（R8）只是可选放大器，不是机械节拍。

### E. 表达与确认
告白/承诺用 R6：表达清楚，但保留拒绝、暂停、离场和以后再谈。权力不对等时，先消除“当场回答”的压力。任何身体接触都不能替代确认。

### F. 结局与后果
用 R7 检查双方最终选择、各自保留的目标、现实后果与未解决项。结合、分离、开放、独身都能完成情感弧。需要降温时可选 R10；不强迫反高潮。

## 3. 输出合同

默认输出：
- `关系状态表`：人物目标、边界、已知/未知信息、当前选择；
- `6–10 拍建议`：每拍写“事件 → 谁做选择 → 关系状态变化 → 使用的规则”；拍数可按篇幅缩放；
- `风险与冲突`：强迫/自伤威胁、无理由拖延、信息凭空新增、结局替人物做决定；
- `备选方向`：至少一个维持关系、一个不维持关系的可行分支（若用户已定结局则不用强加）；
- 改稿任务另给 `保留 / 改写 / 删除`，不虚构原稿不存在的句子或位置。

## 5. 失败出口

- 缺已有稿却要求“定位哪段有问题”：返回最小补料清单，不编造段落。
- 用户要求把骚扰、逼答、自伤威胁包装成取得同意的方法：不提供该操作；可改写为明确拒绝、退出、后果或非强制表达。
- 需要真实历史婚姻法、精神健康、现实安全或法律判断：本 Skill 只处理叙事结构，相关事实标 `NOT_PROVEN` 并交给对应事实来源。
- 证据冲突或某条规则只由单本特殊样本支撑：降为条件选项，不称普遍规律。
- 真实读者效果、平台留存、市场表现：`NOT_PROVEN`。P5/GQ5 不在本轮收口范围。
