# fiction-craft：虚构叙事综合工艺

## P4 任务落地速查（2026-10-30 修订）

先确定要 **规划 / 起草 / 诊断 / 修订** 哪一种产物；只打开 §4 对应的主 Reference。若要求快速判断，按需阅读 [8 条条件裁决与反例](references/p4-field-guide.md)，不要把其中的历史写作参数当现代硬规则。新速查与旧 RC 发生冲突时，以**本轮已修订**的 `references/rules.md` 为最终权威；旧版未修正的措辞不得覆盖这份判据。

输入必须区分**作者明确给定**与**尚待确认**：没有稿件可以按用户明确授权规划或原创起草，但不能假装诊断了未提供的既有稿件；有稿时诊断需带实际位置。需要真正改写，先说明范围并输出非覆盖的新版本。对当代网文/剧本/互动等旧语料欠缺的领域，只做可标记为推断的结构类比。

每次输出至少给出：`route`、`evidence_or_gap`、`selected_RC`、`action`、`exception_or_counterexample`、`deliverable`、`not_verified`；缺关键输入时明确退出，不虚构文本证据。


本轮版本/来源/许可与阅读可信度见 `references/version-and-provenance.md`；其内容只作来源及验收说明，不代替行为测试。

## 1. 这个 Skill 做什么

把一部虚构作品从素材/构思带到可写、可诊断、可修订的状态。它处理四类工作：

1. **规划新作**：定赛道、胚故事、终点、入口、主线、结构单元、开篇、类型契约。
2. **起草场景或章节**：把场景卡写成可读的当下冲突，并守住视角、信息差、文体与类型承诺。
3. **诊断现有稿**：用可观察证据定位症状，给严重度、最小验证与修改方向。
4. **修订超长或结构问题**：分层删减、回归复验、版本留痕。

它不覆盖：非虚构/新闻/学术写作、纯校对与翻译、出版排版与封面文案、角色声音专项训练（方言/口音/音色）、世界观设定专书与系列圣经、影视剧本格式与分镜、互动/游戏叙事、诗歌/歌词创作。舞台/戏曲只做可迁移的结构部分（幕/折收束、汇聚、大收煞），不教舞台调度、表演、舞美。遇到这些，只保留结构类比，不冒充专业交付。

## 2. 触发与负触发

### 触发

- 用户带着素材、构思、梗概或一句想法，要求“怎么写成小说/短篇/连载”。
- 用户给出场景任务：“写这一场”“把这一章续上”“这个转折怎么落地”。
- 用户给出成稿或片段，要求“看看哪里有问题”“为什么中段塌”“人物为什么假”。
- 用户要求“删到多少字”“结构重排”“连载太长怎么收”。
- 编辑式审读：需要可观察证据、严重度、修改层级，而不是泛泛评价。

### 负触发

- 只要校对、错字、标点、格式、参考文献：不做。
- 只要翻译、改写为其他语言、出版排版、合同/版税：不做。
- 只要“角色声音专项”（口音、方言记音、音色训练）：本 Skill 只在视角/语域层面提示，不做专项。
- 只要世界观圣经、力量体系、年表、系列跨书弧线：本 Skill 只做“主线/次线交汇”的诊断，不生成设定百科。
- 只要影视剧本格式、分镜、镜头表、互动分支：只可借用结构判据，不交付媒介格式。
- 只要诗歌/歌词写作：不做分行、押韵、格律或旋律/演唱适配；只可借“单元收束、意象回收”的结构类比，不交付诗学判断。
- 要求“自动改稿”“自动评分”“保证过稿/爆款/签约”：拒绝保证；只能给诊断与可选改写。
- 没有提供任何文本，却要求“指出具体哪一段写坏了”：不做虚构诊断；只给检查清单与取样要求。
- 代写、洗稿、绕过版权或平台规则：不做。

## 3. 输入权限（硬边界）

1. **默认只读**。不覆盖、不移动、不改名用户原稿；需要改写时另建修订单或新版本。
2. **无原文不做虚构诊断**。没有既有稿时仍可按明确创作任务提供原创故事、规划或可选方案；只有对既有稿的诊断必须先取得文本和位置证据。
3. **有稿才做文本诊断**。诊断必须带位置（章/节/段/行）与短引文；引文只取必要片段，不整段复制。
4. **不自动改稿**。默认给“定位 + 建议 + 可选最小改写（1–3 句）”；整场/整章重写必须得到明确授权。
5. **不覆盖原稿**。修订产物是新版本或修订单；保留可回退的原句/原段。
6. **不把作者意图当事实**。作者说“我想表达……”只作为意图声明；文本是否实现，仍要看可观察证据。
7. **不外推读者反应**。所有“读者会……”都是设计假设，标 H；不说“读者研究证明”。
8. **不伪造来源**。本 Skill 内的 PG 锚点是证据索引，不是作品原文全文；不得把示例人物/情节说成真实案例。

## 4. 任务路由

先判任务，再只读一个首要 reference；不要一次加载全部文件。

| 用户任务 | 首要 reference | 补读条件 | 缺输入出口 |
|---|---|---|---|
| 规划新作（从素材/想法到骨架） | `references/planning.md` | 多线/连载/跨类型 → `references/scope-and-conflicts.md`；类型承诺不清 → `references/rules.md` 的 RC-20 | 缺 `length/medium/genre/delivery` 四项中两项以上：给三种赛道方案，不写具体处方 |
| 起草场景或章节 | `references/drafting.md` | 视角/信息差不清 → `references/rules.md` 的 RC-11、RC-12；场景功能不清 → RC-07 | 缺场景目标、阻力、前后文接口：先给 `templates/scene-plan.md` 让作者填，不代写 |
| 诊断现有稿 | `references/diagnosis.md` | 症状跨结构/场景 → `references/revision.md`；需要严重度口径 → `references/diagnosis.md` §1 | 无稿：只给 `templates/diagnosis-report.md` 的空表和取样要求，不做诊断 |
| 修订超长或结构问题 | `references/revision.md` | 删减对象/回归 → `references/rules.md` 的 RC-17、RC-19、RC-20；版本/例外 → RC-21 | 只说“太长”而无目标字数/必须保留项：先给三个删减方案与代价，不直接动稿 |

路由规则：

- 一个任务只选一个主路由。跨路由时，先完成主路由的产物，再补读。
- 诊断和修订分开：诊断只定位与给建议；修订才动结构/文字，且需授权。
- 规划与起草分开：场景卡是规划辅助，不是直接写作的强制许可；若作者明确要求起草且核心冲突可推断，可注明假设后试写；没有赛道标签不引用具体比例。
- 若用户明确要求直接成品且没有不可逆风险，选择合理创作假设开始，不为可选字段强制中断；仅当范围/媒介冲突实质影响交付时提出单一澄清。

## 5. 最小工作流（3 步内开始）

### 第 1 步：定赛道（RC-01）

写下四项：`length`（词数/章数区间）、`medium`（印刷/连载/舞台/口头/银幕）、`genre`（现实/传奇/侦探/闹剧/寓言/速写等）、`delivery`（一次读完/追更/现场/听讲）。缺项标“未定”，不得用默认值冒充已定。

输出：`route: {length, medium, genre, delivery, reader_promise}`。

### 第 2 步：选路由并只读一个 reference

按 §4 选 `planning/drafting/diagnosis/revision`。只打开对应文件；需要规则细节时，再按 RC ID 打开 `references/rules.md` 的相关条目。不要通读全部规则再开始。

### 第 3 步：产出该路由的 Owner 文件

| 路由 | Owner 产物 | 字段 |
|---|---|---|
| 规划 | `templates/novel-plan.md` | NP-01…NP-14 |
| 起草 | `templates/scene-plan.md` | SP-01…SP-12 |
| 诊断 | `templates/diagnosis-report.md` | DR-01…DR-12 + DR-SUM |
| 修订 | `templates/revision-sheet.md` | RV-01…RV-12 |

产物必须写：范围/版本、证据位置、判断分支、失败出口、未决项。没有证据的字段留空并标“待补”，不要用套话填满。

## 7. 失败与退出

遇到以下情况，停止当前部分并说明原因；不要用套话硬写。

| 情况 | 处置 |
|---|---|
| 赛道四项缺失 ≥2 项 | 输出三种赛道方案（短篇/长篇/舞台或连载），各自的读者承诺与代价；不写具体场景/比例 |
| 无稿却要求文本诊断 | 输出取样清单：至少 1 个开篇、1 个中段、1 个结尾、1 个视角切换处；不编造问题 |
| 只有梗概 | 只做规划层诊断（主行动/线/终点/类型契约），不做句段诊断 |
| 无素材/无场景卡却要求直接出正文 | 有明确原创写作授权时，列 1–2 项创作假设并直接生成可修改试稿；若要求忠实续写却无前文，说明无法保证承接并给示例与所需材料 |
| 诊断证据不足 | 标“证据缺口”；给最小验证方法；不升格为结论 |
| 两个症状互相矛盾（如“删太多”与“中段塌”） | 分别列证据与代价，让作者选优先级；不平均折中 |
| 要求整章重写/改结局/换视角 | 先给修订单与影响评估；需要明确授权后才动稿 |
| 要求保证发表/爆款/读者反应 | 拒绝保证；说明本 Skill 的效果 NOT_PROVEN |
| 超出覆盖域（非虚构/翻译/排版/剧本格式/互动叙事/诗歌歌词） | 只保留结构类比（如单元收束、主题从行动长出、悬念的信息差），给 2–3 条可迁移判据与替代路径；明确“不交付清单”：该域格式、术语、流程、范本；不冒充专业交付 |

## 8. 验证状态（必须随产物声明）

- 本 Skill 是**静态交付**：规则、流程、模板、示例均为文本，不含 `scripts/`、自动检查器、评分器或状态机。
- **真实写作任务：NOT_RUN**。本轮没有跑真实客户稿、没有做行为测试、没有做读者实验。
- **效果：NOT_PROVEN**。规则来自 28 本历史文本的阅读与融合；是否提升成品质量、过稿率、读者留存，均未证明。
- **锚点：STATIC_CHECKED** 仅指在本轮证据整理中做过文本回读与位置核对；不等于本轮重新逐条验证，也不等于效果验证。
- 任何“读者会……”都是设计假设，标 H；不得写成“研究支持”。
- 交付时必须写：用了哪些 RC、哪些字段、哪些证据、哪些未决、哪些没验证。

## 9. 独立性与加载方式

- 本 Skill **不依赖**其他 Skill、Registry、MCP、外部数据库、状态机或后台服务。
- 所有引用都在本目录内，使用相对路径；不引用本轮 notes、绝对路径或工作区外材料。
- 触发是**显式路由**：用户/宿主明确要求规划、起草、诊断或修订时才使用；不是宿主自动加载，也不假设“只要提到小说就自动生效”。
- 若宿主没有加载本 Skill，不得假定其规则已被执行；若只加载了 `SKILL.md`，不得假装已读 `references/*`。
- 本 Skill 不承诺自动执行、自动修复、自动验收；它给判断链与产物格式，执行者仍是作者/编辑/代理。
