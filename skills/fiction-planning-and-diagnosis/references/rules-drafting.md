# FC-11 至 FC-16：视角、信息、可信度、细节、文体与主题

返回 [SKILL.md](../SKILL.md)。FC 规则的正文分在四个文件里：[rules-premise-and-structure.md](rules-premise-and-structure.md)（FC-01 至 FC-06）、[rules-units-and-endings.md](rules-units-and-endings.md)（FC-07 至 FC-10）、[rules-drafting.md](rules-drafting.md)（FC-11 至 FC-16）、[rules-revision-and-method.md](rules-revision-and-method.md)（FC-17 至 FC-21）。SKILL.md 和流程文件只引用 FC 编号，不复制完整的规则；说法不一致时，以这四个文件为准。

读法：
- 每条规则包含：层级、规则、适用场景、观察信号、分支与反信号、操作步骤、交付、反例、适用范围、卡住时的处理和验证边界。不要把一条规则压成一句口号。
- 规则是诊断与练习工具，不是成功保证；真实写作效果和读者反应仍需在具体作品中验证。
- 范围：28 本材料标称 1808–1929 年，主体是 1888–1928 年英美印刷市场的小说作法、短篇工艺、舞台和戏曲，加上古典文论；非西方的现代小说、当代的类型工业、网络长篇和系列、影视和互动叙事、读者实验都没有覆盖。越出这个范围的，标为推断或未证实。
- 规则的效果尚未通过真实写作任务或受控读者测试验证；把它们作为可检验的工作假设，不当作效果保证。

## FC-11 视角：信息合同 + 距离稳定 + 切换代价

- **层级**：结构（信息权限）+ 文体（距离/语域）；两层不能混判。
- **规则**：视角不是“禁止切换”，而是三件事：信息获取权限必须一致（合同）、叙述距离要可辨且重新锚定、每次故意切换都要有触发/收益/标记/代价。
- **用在**：限知视角突然写出人物不可能知道的事；全知与限知混用；多人视角切换生硬；第一人称写着写着变成作者；编辑说“视角乱了”；为了传信息临时换到配角脑子里。
- **看什么**：
  - 叙述者此刻能知道什么、不能知道什么；
  - 是否存在“越界知识”（别人的内心、远处发生的事、尚未发生的结局）；
  - 语域/距离是否与视角人物匹配；
  - 切换处是否有场景/章节/排版标记；
  - 切换买回了什么（范围、反讽、对照、信息）。
- **分支**：
  - **A 限知/单一 reflector（短篇默认）**：区分信号 = 一个意识可承载全部信息、读者跟着他/她受限；反信号 = 需要多人内心/跨地同时发生、单视角必须靠巧合传信。
  - **B 多 reflector（长篇默认 2–3，非硬门）**：区分信号 = 单一意识无法知道/反应、每条视角有独立的信息与欲望；反信号 = 为了省事而切、切过去只为传一句话。
  - **C 全知/群像/史诗**：区分信号 = 需要社会全景/多线对照、叙述者可自由进出但仍有选择原则；反信号 = 全知变成“作者想说什么就说什么”、同一场景无标记滑入多人内心。
  - **D 故意混合/元叙述**：区分信号 = 混合本身产生效果（反讽、不可靠、间离）、读者被要求注意叙述行为；反信号 = 混合只是控制不住、作者没有设计标记。
  - **三层区分**：第一层“能不能知道”（合同，近硬）；第二层“距离/语域”（可调，须重新锚定）；第三层“故意切换”（交易，须四件套）。不要用第三层的“切换自由”去掩盖第一层的越界。
- **怎么做**：
  1. 写 `视角约定`：叙述者能知道什么、不能知道什么、能进入谁的意识。
  2. 写 `距离表`：每章/每场的叙述距离（贴身/中距/远距）；变化处标“为什么变”。
  3. 建 `切换账本`：每次切换写 `触发`（当前 reflector 不可能知道/无法反应）、`收益`（单视角拿不到的东西）、`标记`（场景/章节/排版）、`代价`（重新定向/认同转移）。
  4. 逐场审计：越界知识若无 marker/benefit，判为缺陷；有 benefit 但无 marker，判为读者会迷路。
  5. 短篇：默认一个 reflector；若必须切换，优先用框架/书信/档案，而不是中途换脑。
  6. 长篇：默认 2–3 个（操作默认，不是统计法则）；超过时检查是否群像/史诗，并确保每次切换都“买回”东西。
  7. 完稿：朗读切换段；若读者被弹出，补强度或改回同一意识过滤（“bounce”检验：读者是否被弹出这段意识）。
- **交付**：`视角约定`、`距离表`、`切换账本`（trigger/benefit/marker/cost）、`视角越界`。
- **反例**：
  1. **宏大群像多视点频繁切换**：说明单一视点一致性不是绝对禁令；处置：C/D 分支允许在宏大群像中频繁切换视点，但每次仍要有 trigger/benefit/marker/cost。
  2. **视点人物只为传递信息而造**：行为不可信；切换的代价高于收益。处置：若切换只为传信息，改回主视角，用动作/对白让信息自然出现。
  3. **叙述者可以公开现身，只要作品建立了叙述者位置与可靠性**：不是所有时代都禁“叙述者现身”。处置：D 分支允许，但须标清叙述者位置与可靠性；不把“作者退场”当绝对禁令。
  4. **-14243 第一人称的使用边界**：是逐篇选择，不是一刀切；处置：第一人称可用，但要检查“是否只能靠自述解释”“是否掩盖了场景缺失”“是否让读者无法验证”。
- **适用范围**：短篇/悬疑强（一个 reflector）；长篇 2–3（默认）；群像/史诗可多；19 世纪全知合法；后现代元叙述是 D；舞台没有严格视角，只有“观众知道多少”；影视的镜头视角是另一套，不直接换算。
- **卡住时**：写不出 `视角约定`（能知道/不能知道）→ 先选一个 reflector，把所有信息限制在他/她可见范围内；若故事必须跨地同时发生，改多 reflector 或全知，并在 `切换账本` 逐次记账。切换无 benefit → 不切；改由当前视角人物目击/听说/推断。
- **冲突处理**：按 [scope-and-conflicts.md](scope-and-conflicts.md) §2 的 K-04 条件分流；未定时保留选项与代价。

## FC-12 读者已知度：先画知识矩阵，再配悬念

- **层级**：结构（信息设计）；效果层全部是推断。
- **规则**：先确定“读者/人物/作者”各自知道什么，再选悬念模式（悬疑=读者少知、反讽=读者多知、惊奇=同步后揭晓）；所有读者主张标为推断。
- **用在**：悬念不成立；读者早就猜到；揭秘时读者失望；舞台/小说同一场戏效果相反；改编时不知道哪些信息该提前给。
- **看什么**：
  - 读者进入时知道什么；
  - 人物知道什么；
  - 作者/叙述者知道什么；
  - 揭晓点在哪；揭晓后还剩什么；
  - 读者是否已从类型惯例预知。
- **分支**：
  - **A 悬疑（读者少于人物）**：区分信号 = 读者不知道秘密/结局、人物知道但不说；反信号 = 读者已从类型惯例/副标题/章名预知、保密只靠人物不肯说。
  - **B 反讽（读者多于人物）**：区分信号 = 读者知道人物不知道的事，产生优越/恐惧/同情；反信号 = 读者知道后只剩等待、人物迟迟不发现且没有新代价。
  - **C 惊奇（读者与人物同步）**：区分信号 = 揭晓即转折、读者与人物同时获得信息；反信号 = 揭晓只是补常识、没有改变人物处境/读者理解。
  - **D 普通叙事（分层）**：区分信号 = 不同场景对不同人保密、知识状态随场景变化；反信号 = 全篇一个知识状态、所有角色共享作者脑。
  - **A/B 区分**：问“读者知道后，紧张感来自‘他会不会发现’（B）还是‘他能不能解决’（A）？”；两者不能混成“读者都知道但人物装不知道”。
- **怎么做**：
  1. 画 `知识表`：行=读者/主角/对手/配角，列=关键信息。
  2. 选 `悬念方式`：A/B/C/D；写一句“读者此刻最想知道什么”。
  3. 定 `揭示点`：每个秘密何时说、由谁说、说完改变什么。
  4. A：检查读者是否已从类型惯例预知；若已预知，改冲突使读者知情仍紧张。
  5. B：检查“读者知道”是否产生持续张力；若只是等待，缩短或改揭晓。
  6. C：检查揭晓是否改变人物处境/读者理解；若只是补信息，前移或删。
  7. 所有“读者会……”的句子都标为推断；不得写“研究支持”。
- **交付**：`知识表`、`悬念方式`、`揭示点`、`读者的问题`。
- **反例**：
  1. **舞台要求观众全程知道秘密**：侦探若照搬会泄底。处置：B 分支只用于舞台/戏剧反讽；A 分支（悬疑）不得用“观众预知”规则。
  2. **悬念不应依赖读者健忘**：这是市场观察，不是正面方法。处置：不要把读者健忘当设计前提；关键信息该埋则埋，不靠读者健忘。
  3. **-8269 趣味是目标之一，但不能替代因果和人物选择**：不能拿“读者会不懂”当删减借口，也不能拿“读者会懂”当免解释理由。处置：以知识矩阵为准，不以读者猜测为准。
  4. **侦探读者默认“会有答案”**：类型惯例本身是知识状态的一部分；处置：A 分支必须与类型惯例配合，不能把“读者知道类型”当“读者知道真相”。
- **适用范围**：舞台/商业短篇/悬疑/侦探强；文学长篇/实验叙事弱；儿童/成人读者模型不同；1900–1920 的“读者健忘”是历史观察，不是普遍心理；互动/游戏叙事未覆盖。
- **卡住时**：填不满 `知识表` → 先只填“读者/主角/对手”三行；仍填不满，说明信息设计未定，不要写揭晓。A 分支发现读者已预知 → 改 B（让读者知道人物不知道）或改冲突；不要靠隐藏信息硬撑。
- **冲突处理**：按 [scope-and-conflicts.md](scope-and-conflicts.md) §2 的 K-14 条件分流；未定时保留选项与代价。

## FC-13 可信度审计：似真、巧合、类型豁免

- **层级**：结构（因果可信度）。
- **规则**：先定作品的“可信度契约”（写实/传奇/幻想/闹剧），再审计巧合：巧合可作前提/起点，不可作危机解结；类型放弃逼真时，仍须内部逻辑。
- **用在**：读者说“太巧了”；真实事件改编被嫌假；幻想/闹剧被要求“合理”；侦探靠巧合破案；人物在关键时刻突然得到恰好需要的东西。
- **看什么**：
  - 作品承诺的是“可能发生”还是“不可能但自洽”/“夸张取笑”；
  - 巧合出现在前提、转折还是解结；
  - 巧合是否直接决定胜负/生死/婚配；
  - 是否有前文铺垫/人物因果可替代；
  - 类型内部规则是否前后一致。
- **分支**：
  - **A 写实/悲剧/侦探**：区分信号 = 承诺“可能发生”、因果可追、人物选择能解释结果；反信号 = 用巧合解决核心危机、关键证据/人物恰好出现。
  - **B 传奇/幻想/童话/闹剧**：区分信号 = 明确放弃逼真、内部规则自洽、读者被承诺“奇迹/夸张”；反信号 = 用“类型”掩盖任意转折、人物动机突变。
  - **C 真实事件改编**：区分信号 = 事件确实发生、作者选择“按实”呈现；反信号 = 以“真事”为由跳过铺垫、把真实当免罪符。
  - **A/B 区分**：问“这个巧合如果删掉，危机是否仍能由人物/前史解决？”能 → 巧合可留；不能 → 它承担了解结，按 A 改写。
- **怎么做**：
  1. 写 `可信度约定`：读者被承诺的是“可能”、“不可能但自洽”还是“夸张取笑”。
  2. 列 `巧合`：每个偶然相遇/误递/同时到达；标它出现在前提/转折/解结。
  3. A：与危机重合的巧合改写为由人物意志/前史因果驱动。
  4. C：把真事当奇事写，让人物也惊讶；补双倍铺垫（-2110）。
  5. B：保留奇迹，但检查内部规则是否前后一致；不能用“类型”解释人物动机突变。
  6. 完稿：问“读者会不会停下来怀疑”；会，则补因或换事件。
- **交付**：`可信度约定`、`巧合清单`（位置/作用/替代方案）、`铺垫记录`。
- **反例**：
  1. **Oedipus 的巧合是悲剧前提，不是解结**：命运框架可豁免；处置：把巧合放在前提/起点，不放在危机解决处；若放在解结，改写为人物选择。
  2. **传奇、幻想或闹剧可以容许不现实的巧合**；要求按 farce 评：闹剧/传奇可容偶然。处置：B 分支保留，但内部规则要一致；不把“好笑”当所有类型的通行证。
  3. **-4841 纯奇作品可以放弃现实概率**：仍要求 magnificence/splendor/magic 的内部一致；处置：B 分支检查“世界规则是否自洽”，不检查“现实概率”。
  4. **通俗类型可以采用更高的夸张程度**：这是类型契约，不是写实规则；处置：先判类型，再定巧合配额；不把通俗类型的容忍度搬到写实/侦探。
- **适用范围**：写实/悲剧/侦探最严；传奇/幻想/童话/闹剧放宽；真实事件改编须补铺垫；新闻/史传另按“按实”标准（-621）；当代类型/影视契约未覆盖。
- **卡住时**：说不清 `可信度约定` → 先按 genre 选“写实/不可能但自洽/夸张取笑”三选一；选不出，按最严的写实处理，标“契约未定”。巧合在解结且改不出人物因 → 换事件/换解结方式；不要用“命运/天意”解释，除非前文已建立命运框架。
- **冲突处理**：按 [scope-and-conflicts.md](scope-and-conflicts.md) §2 的 K-05、K-08 条件分流；未定时保留选项与代价。

## FC-14 具体化与细节剂量：少而准，按视角过滤

- **层级**：文体（描写/细节）；选择逻辑接近结构。
- **规则**：具体化不是细节堆量；选 3–5 个能暗示整体的具体细节（操作默认，非硬门），按视角人物“此刻会注意什么”过滤，删掉真实但无用的细节。
- **用在**：描写像清单；读者记不住场景；细节很真但不推动；视角人物是农妇却写出地质学细节；每个物件都被同等用力描写。
- **看什么**：
  - 每个细节是否可归到一个主导印象；
  - 是否是该视角人物会注意的；
  - 删掉后读者是否还能重建空间/气氛；
  - 细节是否彼此抵消/重复；
  - 细节是否只是作者查资料的证明。
- **分支**：
  - **A 现实主义/地方色彩/氛围**：区分信号 = 细节承载真实感/文化/命运、可暗示整体；反信号 = 细节只是作者查资料、没有选择、每个都同等重要。
  - **B 情节驱动/快节奏**：区分信号 = 细节只用于定位/推进、一句可成像；反信号 = 长段静态描写、细节不改变行动。
  - **C 速写/印象主义**：区分信号 = 细节即 tone、彼此同调；反信号 = 细节彼此不同调、破坏单一印象。
  - **A/B 区分**：问“删掉这个细节，读者是否还能知道在哪/发生什么？”能 → B 可删；不能 → A 保留，但仍要按视角过滤。
- **怎么做**：
  1. 写 `主导印象`：这场戏要让读者记住的一个印象。
  2. 列 `细节`：每个细节标功能（定位/人物/气氛/象征/信息）。
  3. 按视角过滤：问“他/她此刻会注意这个吗”；不会则删，即使很生动（Hardy 反例）。
  4. A：保留 3–5 个能暗示整体的细节（操作默认）；用一个具体物承载抽象（“具体名词”法，迁到小说是推断）。
  5. B：把细节压到一句可成像；删掉不影响行动的描写。
  6. C：所有细节必须同调；不同调者删（-3790 氛围=严格筛选同质细节）。
  7. 完稿：做“一次成图”测试；读者能否在脑中一次成形。
- **交付**：`主导印象`、`细节表`（细节/功能/是否视角可见）、`删减记录`。
- **反例**：
  1. **有 6 人主张全描写**：在特定读者/类型中成立；处置：A 分支允许高密度，但必须有主导印象与视角过滤，不把“全描写”当普遍法则。
  2. **动作短篇可以采用极简描写，但其他题材按信息和节奏调整**：快节奏动作短篇成立；处置：B 分支可极简，但不把“一句上限”搬到现实主义/氛围文本。
  3. **真实但无用的细节要求删去**：不能以“我查过资料”为由保留；处置：真实但无功能 → 删/压；若它服务 tone，按 C 分支保留并检查同调。
  4. **-818 允许技术说明的细节段（沉思体是推断）**：此时“一次成图”不适用；处置：先判类型/文体，不拿本条的剂量当硬门。
- **适用范围**：现实主义/地方色彩/氛围强；情节驱动短篇“少而准”；速写/印象主义细节即效果；技术/说明文另论；电影/口头媒介是另一套“看”的规则；3–5 个是操作默认，不是统计结论。
- **卡住时**：写不出 `主导印象` → 先不写描写，回到场景目标（FC-07）；若场景没有目标，描写必然散。细节都“很重要” → 强制排序：只能留三个，删掉的放进 `删减记录`，看是否真的损失。
- **冲突处理**：按 [scope-and-conflicts.md](scope-and-conflicts.md) §2 的 K-03 条件分流；未定时保留选项与代价。

## FC-15 文体：清晰得体是底线，节奏是耳朵的事

- **层级**：文体（句段/语域）；“什么是好文体”部分属 talent，不可立法。
- **规则**：文体底线是清晰、得体、可朗读；在此之上按类型调音高（朴素/华丽），不把“短词”“简洁”当成唯一法则。
- **用在**：句子绕、名词化、套语多；描写词大于事件；朗读拗口；类型需要华丽但被要求“简洁”；作者用长句掩盖空洞。
- **看什么**：
  - 主语/主动词是否清楚；
  - 抽象名词是否可换成具体物；
  - 词级是否与事件相称；
  - 朗读是否拗口/单调；
  - 是否有“漂亮但可删”的句子。
- **分支**：
  - **A 说明/叙事散文**：区分信号 = 以传达为主、读者要跟上事件；反信号 = 以声音/气氛为主、句子主要用来展示作者。
  - **B 类型/浪漫/纯奇**：区分信号 = 文体本身是效果、华丽与事件相称；反信号 = 华丽掩盖空洞、形容词多于动作。
  - **C 人物口语/方言**：区分信号 = 语域服务人物、可听可说；反信号 = 作者炫技/记音过度、读者需要注释才能懂。
  - **A/B 区分**：问“把这段改成平实句，事件是否受损？”受损 → B 可华丽；不受损 → A 应平实。
- **怎么做**：
  1. 朗读一段；标出拗口、换气困难、重音落错处。
  2. 找每句的主语与主动词；名词化改成动词，抽象名词换成可触物（-2742）。
  3. 做“音高检查”：用一句话复述这段发生了什么；比较词级是否高于事件（按 appropriate 即“得体”标准；转成步骤属推断）。
  4. 删套语、同页换称呼、装饰性形容词；删“得意句”前先判断它是否承担转折/揭示（“Murder your darlings”）。
  5. B：允许华丽，但每一处华丽必须服务事件/人物；否则降调。
  6. C：方言只暗示、不记音；语域须与人物教养/场景一致。
- **交付**：`文体底线`（clear/appropriate/readable）、`句子记录`（原句/改句/理由）、`语域检查`。
- **反例**：
  1. **短词或特定词源不是唯一标准**：“I think them false in theory and likely to be fatal in practice.” 处置：不把“短词”当唯一标准；按得体/准确/可读选词。
  2. **-288 节奏无法完全用固定数字规定**：节奏无法完全立法；处置：给诊断问题与朗读检查，不给“每句不超过 X 词”的硬门。
  3. **-4841 纯奇故事文体可从极朴到极华丽**：不能一刀切；处置：B 分支允许华丽，但用“是否服务事件/人物”验收。
  4. **风格包含个人判断成分**：风格不可教；处置：本 Skill 只改可诊断的清晰/得体/节奏问题，不承诺“造音感”。
- **适用范围**：书面叙事以清晰/得体为底；舞台/口头以可听/可说为底；类型允许华丽；翻译/方言/时代语另论；“简洁是唯一好文体”是推断，不是本规则。
- **卡住时**：朗读仍拗口且改不动 → 标“风格问题”，不要继续在句层打转；回到结构/场景，确认是否在用华丽掩盖缺失的冲突。语域与人物不符 → 先写人物三行小传（处境/欲望/教养），再改台词，不直接“加方言”。
- **冲突处理**：按 [scope-and-conflicts.md](scope-and-conflicts.md) §2 的 K-19、K-07 条件分流；未定时保留选项与代价。

## FC-16 主题/道德：从行动长出，类型例外明示

- **层级**：结构（主题承载）；价值判断部分不可立法。
- **规则**：小说/短篇的主题应从人物选择与后果中长出；寓言/道德故事/宣传可以明示教训，但必须按该类型的契约验收。
- **用在**：结尾突然说教；人物替作者讲道理；主题正确但故事无聊；寓言被要求“藏起来”；讽刺被误读成宣传。
- **看什么**：
  - 主题能否写成一个问题而非口号；
  - 人物是否在关键处做出体现主题的选择；
  - 删掉点题句，行动是否仍成立；
  - 类型是否本来承诺“教训”；
  - 反讽标记是否足够。
- **分支**：
  - **A 小说/短篇**：区分信号 = 主题通过选择/后果呈现、读者可自己得出结论；反信号 = 人物口播作者结论、结尾加 moral、行动与主题脱节。
  - **B 寓言/道德故事/宣传/教育**：区分信号 = 类型契约明确要教、教训由行动兑现；反信号 = 教训与行动脱节、只靠口号。
  - **C 讽刺/反讽**：区分信号 = 表面直陈、实则拆解、有足够标记；反信号 = 读者误读为真诚说教、标记不足。
  - **A/B 区分**：问“这个类型的读者是否被承诺‘教训’？”是 → B 可明示；否 → A 须隐；不确定 → 按 A 处理，标“类型未定”。
- **怎么做**：
  1. 写 `主题问题`（不是 `主题句`）：故事在问什么。
  2. 找 `证明场`：哪一场的选择/后果最能回答这个问题；没有则补或改。
  3. 标 `声明`：所有直接点题的句子；逐句删，读行动是否仍成立。
  4. A：删掉或改为人物在压力下的选择；保留最少必要说明。
  5. B：允许明示，但教训必须由行动兑现；否则改行动，不改口号。
  6. C：检查反讽标记是否足够；否则读者会当成宣传。
- **交付**：`主题问题`、`证明场`、`声明记录`、`类型例外`。
- **反例**：
  1. **-11172 当作品明确承诺教训时，主题可以明示**：作品明确承诺教训；此时“藏主题”反而失败。处置：B 分支允许明示，但教训必须由行动兑现。
  2. **-3465 有道德立场不自动等于说教**：只是反对把故事当伦理真理的载体；处置：不把“说教必败”当绝对律，也不把“有道德倾向”当缺陷。
  3. **-2947 主张小说塑造时代道德**：这是价值立场，不是事实；处置：不写成“小说必须无道德”，也不写成“小说必须有用”。
  4. **讽刺表面直陈可能是有意反讽**：不能一律删；处置：C 分支先检查标记与上下文，再判断是否说教。
- **适用范围**：小说/短篇取 A；寓言/道德故事/宣传取 B；讽刺取 C；儿童文学/教育叙事另有权衡；1900–1920 的道德审查语境不等于普遍法则；当代类型/影视的价值契约未覆盖。
- **卡住时**：写不出 `主题问题` → 先不写主题；从 `证明场` 反推“这场选择在回答什么”。删掉点题句后行动仍成立 → 点题句可删；若删后主题消失，说明主题没有落在行动里，回到 FC-05/FC-06 补选择与后果。
- **冲突处理**：按 [scope-and-conflicts.md](scope-and-conflicts.md) §2 的 K-09 条件分流；未定时保留选项与代价。
