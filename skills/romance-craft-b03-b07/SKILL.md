# 言情爱情小说：关系机制诊断与写作

## 0. 这个 Skill 的证据边界（先读，再决定要不要用）

- 证据基础：**18 部英美原著全文实读台账**（PG11901、PG15402、PG1621、PG177、PG22002、PG25001、PG26001、PG2870、PG39865、PG44374、PG4600、PG57099、PG700、PG78710、PG79505、PG805、PG8203、PG9182）。全部为 **1830–1925 年**作品。
- 因此：**不回答现代类型言情（出版市场、读者期待、分卷节奏、甜宠/虐恋标签、字数与更新节奏）**。这类问题一律按第 7 节的失败出口处理，不要猜。
- 只回答**关系机制**问题：阻挡力、追求与拒绝、中间人、信息差、牺牲、结局形态。
- 每条建议都能给出来源行号；给不出就说 NOT_PROVEN。

---

## 1. 触发 / 负触发

**触发**（满足任一）：
- 用户给出一段恋爱关系或爱情线，问"卡在哪""下一步怎么走""能不能复合""这个追求者可信吗"。
- 用户要求设计/改写一条爱情线的阻碍、拒绝、重逢或结尾。
- 用户拿成品爱情片段求诊断：为什么读起来假、为什么张力不够、为什么结局敷衍。

**负触发**（不要用，直接说明原因并转出）：
- 问的是当代类型小说市场/读者/平台规则、甜宠虐恋标签、连载字数与更新节奏 → 本 Skill 无证据（见第 7 节）。
- 问的是非虚构恋爱建议、情感咨询、人际关系处理 → 本 Skill 讲的是虚构叙事机制。
- 问的是纯语言润色、校对、排版 → 转语言精修类 Skill。
- 爱情线只是作品里无关紧要的支线，且用户问的不是它 → 不要主动把一切问题都读成爱情问题。

---

## 2. 输入合同（缺什么先问什么）

开始工作前确认以下五项；缺的就问，不要替用户假设：

1. **文本或设定**：已有草稿/片段，还是只有人物与设定？（两者走不同步骤）
2. **主负荷关系**：这部作品真正承重的关系是什么？（见步骤 1）
3. **当前要解决的一个问题**：不要一次问"帮我整体看看"。
4. **读者的已知范围**：读者目前知道哪些信息、人物各知道哪些（决定信息差怎么摆）。
5. **目标结局形态**：封闭 / 停止 / 悬置——用户想要哪一种（见步骤 6）。

## 3. 任务路由

| 用户问题类型 | 走哪条 |
|---|---|
| "这条线卡住了 / 张力不够" | 路由 A：阻挡力体检 |
| "这个追求者/告白/拒绝写得假" | 路由 B：追求与拒绝场景改写 |
| "要不要让他们复合 / 结局怎么收" | 路由 C：结局形态选择 |
| "要不要加个撮合者 / 信息传递者" | 路由 D：中间人动机设定 |
| "帮我从零设计一条爱情线" | 先做步骤 1–2，再依次走 A → B → C |

## 4. 执行步骤

### 步骤 1：先确认"主负荷关系"，再决定爱情线占多少篇幅
不要默认作品的核心就是男女主角。本批证据里，PG700 承重的是祖孙逃亡（`L433-434`），爱情线只在次要位置收尾（`L23526-23527`）；PG4600 承重的是办杂志与阶层（`L148-149`）。
**判定动作**：问"如果删掉爱情线，这本书还剩什么"。剩不下什么 → 爱情线是主干；仍能成立 → 它是支线，按支线篇幅写。
**P1**

### 步骤 2：给每段关系配至少两条阻挡力，一条外部、一条内在
- **外部**：制度 / 身份 / 家族 / 法律地位。样例：PG1621（ marriage 身份不明，书名即问句）、PG177（家族门第）、PG22002（监护人兼教职的禁忌身份，`L168-170`）、PG2870（父亲的遗嘱威胁，`L6912-6923`）。
- **内在**：主角自己的取舍、性格、自我评估。样例：PG25001 的阻挡源是年龄落差与"老先生很少无缘无故动心"的自我评估（`L273-278`）；PG9182 的阻挡是叙述者自身的封闭与宗教差异。
- **只有外部反对者、没有内在取舍，结局会失去说服力**（本轮归纳 H2，非原文断言）。
- **反对者要写得自洽**：PG2870 里父亲连反对的荒谬后果都算准了（`L6789-6792`），他的准确与他的冷酷同在——不要只给反对者一个"他就是不同意"。
**P2**

### 步骤 3：追求与拒绝场景——拒绝分三层写
追求侧可用装置：**一见倾心**（PG15402 `L140-174`：窗口一瞥→追踪→追丢→只留一顶蕾丝小帽作锚点；PG78710 `L217-227`），或**从困境中开场**（PG2870 / PG9182 / PG57099 都是）。两者都是可选手法，不是必须。

拒绝/告白场景按三层输出，缺层就补：

| 层 | 要写什么 | 证据样例 |
|---|---|---|
| 礼节层 | 不给座位、不给话题、不接话——拒绝先从礼节做起 | PG2870 `L7321`："I think we had better not"；`L7334`："I don't think it is necessary" |
| 理由层 | 给出可检验的标准，而不是"我感觉不合适" | PG57099 `L3443-3444`：夫妻应当有"the best kind of love, and nothing else, because nothing else will fill its place" |
| 动机自陈层 | 拒绝者承认自己也不干净 | PG57099 `L3491-3493`："perhaps I was too proud and jealous… not fond enough to take your half-loaf" |

另有两个可直接复用的动作：
- **被追求者替追求者把话说完**（PG57099 `L3408-3409`），先识别再回应，比直接答应有力。
- **让对手先离场、再写评价**：PG2870 `L7454-7458` 出门后立刻换脸，是让读者自己下判断的写法。
**P3**

### 步骤 4：信息差必须握在有权改变它的人手里
信息不对称是主要引擎（PG2870 父亲永远不知真相是他自己的惩罚 `L6702-6705`；PG1621 身份不明；PG39865 隐瞒出身与信仰 `L332-340`；PG9182 第一人称隐藏 `L392-395`）。
**判定动作**：指出手握信息的人。若这个人无权也无意改变它，这个信息差只是作者拖延，删掉或改写。
**P8（前置）**

### 步骤 5：中间人——先定动机归属，再决定是否促成
不要先问"要不要加个撮合者"，先问这个人的动机属于哪一类：
- **服务当事人的判断** → 可促成。PG22002 里 Sandford 用"缓赴召"让父女养成相处习惯（`L12541-12542`）。
- **满足自己的戏剧感** → 会造成伤害。PG2870 里 Mrs Penniman 擅自安排相见，被当场抓住（`L7258-7269`），事后被埋怨（`L7454-7458`）。
本批两类都有且都成立，**不强行统一**。选定后贯彻到底。
**P4**

### 步骤 6：结局——在三种形态里显式选一种，不选默认

| 形态 | 特征 | 证据 |
|---|---|---|
| 封闭 | 逐人交代下落 | PG700 `L23424-23588`、PG78710 |
| 停止 | 明令不再叙述 | PG9182 `L21186`："Here pause: pause at once. There is enough said." |
| 悬置 | 判断留白 | PG8203 `L16394-16395`："only be loss,--deterioration,--lapse from the ideal" |

**复合判定（最关键的一条）**：问"伤害是否改变了当事人的自我理解"，而不是"误会是否解开"。
- PG2870 `L7413-7418`：Catherine 已知全部来龙去脉，仍说"Everything is dead and buried"。
- PG8203：离婚、男主在西部被枪杀（`L16283-16300`），复合被旁人判为堕落。
- PG177 `L14566-14570`：放弃复仇不等于复合。
→ **信息透明不构成复合条件。**
**P7 / P8**

---

## 5. 输出合同

每次回答必须包含：

1. **判定**：一句话给出结论（属于哪个路由、核心问题是什么）。
2. **证据**：至少 1 条 `PG号 + 行号 + 原文里发生了什么`，可回源核验。不要引用原文没有的话。
3. **动作**：按 P1–P9 编号给出可执行动作，写明改哪里。
4. **边界声明**：若问题涉及第 7 节的不可用范围，明确写出 NOT_PROVEN 与理由。
5. **保留的冲突**：若所问之处存在本批内部矛盾（见 `references/conflicts-and-anti-patterns.md`），把双方都给出来，替用户选但不假装只有一种写法。

不要输出：流派口号、无来源的行话、把单部小说的情节当作所有作品都必须遵守的规则。

## 7. 失败出口

出现以下任一情况，**停止给建议，按下面处理**：

- 问题落在现代类型市场 / 读者期待 / 标签 / 节奏规范 → 回："本 Skill 的证据全部来自 1830–1925 年作品，此项 NOT_PROVEN。"不要猜。
- 手上的材料不足以判断主负荷关系 → 先问第 2 节的第 2 项，拿到再动手。
- 用户要的是"让所有人都能接受的写法" → 本批在中间人、结局形态、欺骗代价、牺牲评价四点上都存在不可调和的分歧；把 `references/conflicts-and-anti-patterns.md` 的双方摆出来让他选，不要伪造共识。
- 用户要的是非虚构情感建议 → 转出，本 Skill 不适用。
- 任何一条建议找不到来源行号 → 不写。改为 NOT_PROVEN。
