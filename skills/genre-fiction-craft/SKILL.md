# 类型小说创作

把题材当作需要解决的一组叙事问题。先确定用户要的作品、诊断或改稿，再读取相应题材的方法与条件；不因题材标签就强迫固定结局、角色身份、情节数量或价值判断。十四类可以独立使用或按实际需要合用。

## 执行流程

1. **确定当前产物。** 从请求与已给材料取得题材、阶段、文本范围、想保留的功能、已有正典及允许修改的范围。创作请求可以从一句设定起步；只读概要不能报告已审全文。
2. **按问题选择主模块。** 使用下表的叙事对象路由。主模块负责当前交付，辅助模块只补它实际解决的机制；不设最多几个题材的配额，也不把某类来源的缺失当禁写理由。
3. **读实际规则。** 先读题材入口，再读被选规则的完整条件、例子、反例和模板。资料不足则标注假设，继续能做的部分；不能只凭目录名或摘要造规则。
4. **建一份共享事实表。** 同一事件只记一次：世界内发生什么、人物各自知道什么、叙述者披露什么、读者已知什么、谁可选择或执行、资源与关系改变什么。不同题材使用同一事件ID和版本，避免各建一套互相矛盾的正典。
5. **裁决规则。** 比较对象、条件、动作、限制和预期结果。完全等价的动作只执行一次；不同条件分支保留；真实冲突按作者目标和锁定事实选择。文学作品中出现某事，只证明其被如此叙述，不证明现实规律或现代行业规范。
6. **交付实际作品或修订。** 用户要正文就写正文，要大纲就给可写结构，要诊断就给位置、问题、证据、竞争解释及修法。授权改稿时实际修改相应文本；表格服务作品，不替代作品。
7. **复核受影响部分。** 核因果、知情权限、资源与物件、关系、世界制度、主题与读者承诺。仅检查局部时说明范围；无真实读者测试不宣称恐惧、幽默、情感或商业效果已得到证明。

## 混合题材怎样选择

| 请求 | 主任务与辅助任务 | 需要分别维护的条件 |
|---|---|---|
| 宫廷谋杀与政治复仇 | 推理模块处理证据/推断；权谋模块处理承认权/联盟/资源 | 有权裁决不等于有证据证明，逻辑识凶不等于能执行惩罚 |
| 爱情与恐怖 | 按用户当前要写的关系转变或恐惧场面选主模块 | 亲密关系的可选性与异常威胁的限制不可互相替代；解释留白不等于关系动机可随意断裂 |
| 穿越到历史社会 | 穿越模块处理进入/返回与优势；历史模块处理时代条件 | 旅行机制与史料真实分别标记；架空分岔后的后果不能仍冒称真实史实 |
| 科幻灾变求生 | 科幻模块处理假设及系统后果；求生模块处理资源和协作 | 作品世界的技术假设与真实生存建议区分；数量、单位和时间账本一致 |
| 少年体育或职业故事 | 儿童青少年模块处理可知、选择和成长；职业竞技模块处理训练、制度与竞争 | 不把儿童承担成人责任当必需成长，不以专业名词代替实际行动 |
| 幽默探险 | 探险模块处理目的、路线和发现；喜剧模块处理叙述站位及节拍 | 幽默可以改变解释，不自动免除已建立的物理和资源后果；荒诞契约另行明确 |

这些组合是操作示例，不是穷尽分类。相同物件可以同时是线索、关系象征和资源；分别记录其作用，不为“跨题材”复制成三个不同设定。

## 输出和证据身份

需要解释时使用：观察F → 解释H与反证 → 所选条件 → 创作动作P → 实际改文 → 回归结果/未决。F应区分作品内事件、人物话语、论著作者意见、编者说明和未完成笔记。

各题材使用的证据标签写法不同，语义按下表对应；同一事件汇入共享事实表时按此表归一：

| 统一语义 | 题材中的写法 | 边界 |
|---|---|---|
| 来源观察（SOURCE_OBSERVATION） | F（定义为文本观察处）、F-S、F_SOURCE、F-SOURCE、F-SCENE、F_literary、“正文已出现” | 人物话语是“说了”的观察，不是可靠叙述事实；小说历史描写不是外部史实 |
| 用户正典（USER_CANON） | F_CANON、F-U（窄义）、USER_CANON、“作者已确认”、注记“用户正典” | 用户确认的正典可指导创作，不自动成为外部事实 |
| 用户输入（USER_INPUT） | F-INPUT | 用户提供的稿件≠确认其中所有事实 |
| 用户要求（USER_REQUIREMENT） | USER_REQUIREMENT | 用户要求≠用户正典 |
| 人物信念（POV_BELIEF） | POV_BELIEF；部分题材以“角色说法/人物证言”注记 | 不可升格为叙述事实 |
| 外部史实（HISTORICAL_FACT） | F_historical | 需外部史料依据；本包材料不替代史实考据 |

H 均为解释与机制推断，P 均为可选创作动作；字母相同不代表证据契约相同，以各题材定义句为准。

原作案例、反例和完整操作例保留在题材内；自拟内容标DESIGN_EXAMPLE。证据缺失写NOT_PROVEN或NOT_OBSERVED，指出缺的是事实、来源、权限、上下文还是效果数据，不能用模糊标签替代可执行下一步。

## 与六个通用 Skill 的接口

本包拥有题材特定的机制、证据习惯、反例与选择。项目定位、研究和评论判断可深化到01；全书/多卷组织到02；单场节奏和动作到03；全篇人物、叙述权限与时间模型到04；英文语言校对到06；媒介转换到07。它们是可选的深化服务，本包完成题材任务所需的方法、模板与来源在本目录中，不以安装其他Skill为前提。

真实法律、医学、技术参数或当代行业规则，不能由历史文学案例直接推出。请求仍属虚构创作时可依明确世界设定继续；确需现实结论时仅暂停依赖该事实的部分并核实适格来源，不把题材边界变成整项拒绝。
