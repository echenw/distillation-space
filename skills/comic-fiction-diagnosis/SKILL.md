# Comic Fiction Diagnosis（喜剧叙事诊断）

## 0. 这是什么

一份**人工填表 + 条件判断**的诊断/设计 workflow，不是自动化系统，也不含 scripts。

- **输入**：作者的喜剧设定、已有稿、或一句"这段为什么不好笑／为什么读着累"；可选：目标读者预期（动作型/陈述型/混合）。
- **输出**：`引擎配置表` + `包袱调度表`（模板见 §7）+ 一张按场景的 `笑点归属表` + 明确的边界结论（哪些不能写、哪些只能带注记引用）。
- **不做**：不写正文；不预测笑点命中率；不声称"用了就更好笑"（无读者数据）。

- 版本：`1.0.0`，生成于轮次 `16-类型小说专项/07-喜剧幽默/批次-01/rounds/round-p4-final-2026-10-30`，任务 ID `B-04-B01`。
- 来源：24 部原始作品，全部为 Gutenberg 公共领域英语文本（含英、俄、美作者），正文路径 `distill/有原始正文/16-类型小说专项/07-喜剧幽默/PG<id>-*/整本阅读版.txt`，只读不写。
- 身份核验（本轮实跑）：24/24 的 SHA-256 与 `批次来源清单.json` 的 `sha256_reading` 一致。
- 覆盖核验（本轮实跑）：官方 `kd32_coverage_check.py` 判 `coverage_full` 24/24；`kd32_ledger_gate.py` 逐本回源门禁无 NOT_FOUND。逐本明细见 [04 来源索引](references/04-source-index.md)。
- **族去重（硬要求）**：24 本里有 14 本属于两个族——Wodehouse 族 10 本、Twain 族 4 本（其中 PG7104/PG7105 是同一本《Huckleberry Finn》的两个分册选本，合计只算 0.5 族）。**一族只算一份证据。**凡是只有 Wodehouse 族或只有 Twain 族支撑的断言，本 Skill 一律显式标注"仅 X 族证据"，不得当作普适规则输出。
- **覆盖偏斜（必须告知使用者）**：本批对 Wodehouse／Twain 之外的喜剧传统覆盖很薄（18 世纪英法讽刺、东亚幽默、当代喜剧几乎为零）。给非英语传统或非 1880–1935 年段的作品下判断时，要声明这是外推。
- **替代关系**：本 Skill **不替代**、**不继承**同父类别 `批次-04` 的 `comic-engine-craft`（C1–C10）。那是另一组来源的产物，其可信口径为 12/24 TRUSTED_FULL。本文件 §5 的迁移裁决表说明了哪些 C 条在本批仍成立、哪些被改写、哪些在本批找不到支撑。两者可并读，但不得互相引用为证据。
- 标记约定：**F** = 来源观察（可给行号回源）／**H** = 机制推导（未验证）／**P** = 可执行动作。所有 H 在 references 里单独成行，不得写成"读者一定会笑"。

## 2. 触发 / 负触发

### 触发
- 设计喜剧长篇或连作短篇："笑点从谁身上出、靠什么机制持续供给"。
- 已有稿"写得出来但不成立"：误会撑不住、谎话一戳就破、包袱重复到读者疲劳。
- 讽刺作品：宣言与兑现的调度、公开版与私下版的落差、讽刺该在何处停手。
- 已有稿"看着累"或"笑点密度够但没有一个记得住的"。
- 想把某位经典作家的具体技法迁到自己的稿子上（此时必须先过 §6 的族去重与禁止项）。

### 负触发
- 单句笑话／段子集／梗百科：无引擎需求。
- 情景剧、脱口秀、短视频脚本（对笑点密度与反馈回路的要求属另一种媒介）。
- 纯恶搞／戏仿（本体是靶文本，机制不同）。
- 要求"保证读者笑"或给出笑点命中率：超证据边界，直接走 §8 失败出口。
- 要求把来源里的种族/地域/身体类笑点原样迁移：走 §8，B1-12 是硬规则。

## 4. 最短执行路径（4 个门，按顺序过）

**G1　用户要什么**：设计 / 诊断已有稿 / 迁移某技法 / 核对来源？→ 对应 §3 路由。

**G2　笑点归属**（B1-01）：逐场景标 `搭档 / 叙述者 / 世界 / 无`。
- 标"无"的场景超过三分之一 → 这本书的喜剧引擎可能不存在，先谈要不要加，不要硬填。
- 同一场景同时出现两个归属 → 记下来，这是疲劳主因之一（见 [01 §1](references/01-attribution-and-evidence.md)）。

**G3　体裁预期**（K-3）：确认读者预期是**动作型**（笑点来自可见动作/物件）还是**陈述型**（笑点来自句子本身）。
- 动作型走 [01](references/01-attribution-and-evidence.md)；陈述型走 [03 §2](references/03-repetition-openings-payoff.md) 的 B1-09。
- 判不出来就按"混合"处理，两条都跑一遍，不要替作者决定。

**G4　边界检查**（B1-08 / B1-12，硬门）：
- 稿子里有没有连作者自己都不同情的段落？有 → 必须切"不逗笑模式"并给读者落点。
- 有没有依赖角色天生属性（种族、地域、身体、性别）的笑点？有 → 先回答"批判还是邀请共嘲"，答不上就删。

过完 G1–G4 才允许给建议；任何一条没过，走 §8。

## 6. 禁止项（违反即输出无效）

1. **禁止按本数累计证据**：必须按族（见 §1 与 [04](references/04-source-index.md)）。
2. **禁止把单部小说的情节设计升格为所有作品都必须遵守的规则**：本批每一条规则都标了族与反例；反例列在 [05](references/05-conflicts-and-anti-patterns.md)。
3. **禁止输出"每 N 章必换一次机制""每 X 段必须有一个笑点"这类定量命令**：本批没有任何数据支撑阈值（B1-05）。
4. **禁止把 Jeeves 式解法输出到没有 Jeeves 的设定里**（B1-06）。
5. **禁止迁移带时代印记的表述**：来源里的种族蔑称、按方言书写的角色对白、"更文明"式比较只能带时代注记引用，不可作当代模板（B1-12）。
6. **禁止声称"用了就更好笑"或给出笑点命中率**：无读者数据。
7. **禁止强行统一无法统一的冲突**（K-1～K-4，见 [05](references/05-conflicts-and-anti-patterns.md)），必须并列并交给作者选。
8. **不得伪造共识**：若两个来源给出相反处方，写"两条互斥路线，由作者目标决定"。
9. **不得把 H 写成 F**：references 里标 H 的句子必须保持 H 标记。

## 7. 三张最小模板（空列一律写"未知"，不得留空、不得编）

- **笑点归属表**：`场景 | 归属（搭档/叙述者/世界/无） | 启用的机制（B1-01…B1-12） | 上一场同机制? | 疲劳风险 | 待作者决定`
- **引擎配置表**：`章节 | 主线机制 | 维持误会的可见物（B1-04） | 谎话/宣言是否自洽（B1-11 / B1-07） | 让位点（B1-08） | 回收的口号（B1-10）`
- **包袱调度表**：`设置/宣言 | 兑现位置（同场反转/跨场回响/不兑现留白） | 变化维度（对象/代价/语气/主动权） | 已兑现?`

## 8. 失败出口

| 情况 | 能做的 | 不能做 |
|---|---|---|
| 用户没有喜剧定位、G2 标不出归属 | 退回 G1，给一张机制清单让他选 | 不替他编笑点、不硬填归属 |
| 包袱重复导致疲劳 | 用调度表查"上一场同机制"，给轮换方案（换对象/代价/语气/主动权） | 不给"几章必换"的数字 |
| 讽刺目标涉及真实人群或历史事件 | 走 B1-12：先判"批判还是共嘲"，给出时代注记义务 | 不代作者决定靶子；不输出原样迁移的笑点 |
| 用户要笑点命中率／"保证好笑" | 明确说明无读者数据，交付诊断结论与可选 A/B 稿 | 不编命中率、不用"读者一定会笑"的措辞 |
| 用户想迁移本批之外的传统 | 声明覆盖偏斜（§1），把结论标为外推 | 不把本批规则说成跨语种/跨时代通用 |
| 来源对某个机制给出相反处方 | 并列两条路线 + 各自的样本与代价，交作者选 | 不合并成"适度即可"这类伪共识 |
| 需要回源核对某条 F | 用 `distill/_tools/kd32_ledger_gate.py --book <台账> --src <整本阅读版.txt> --pg <PG> --start <起> --end <止>` 复核 | 不复述记忆中的行号；查不到就写"未回源" |
