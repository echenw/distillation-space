# 推理悬疑刑侦情节装置锻造箱

## P4 快速执行：先校核读者能否公平推断

收到虚构故事的点子、章节大纲或正文时，标注已读范围，判别「设计谜面 / 诊断已写稿 / 有授权的结构修订」。仅输出文学结构，不提供现实犯罪、伪证或规避侦查的操作指导。

**案例：第 20 章已揭动机，第 30–45 章重复盘问。** 先按 [failure-modes.md](references/failure-modes.md) 定位中段塌陷，再按 [references/detection-and-process.md](references/detection-and-process.md) 的 I 族，逐场写「读者已知事实 → 被排除的假说 → 新问题」。若场景只重述已知信息，建议并场或删除；若未给原文，不能诊断具体章节。

**输出字段**：任务类型；已读文本/版本及缺口；谜面与读者已知；选用规则 ID；来源类型 F/H；候选 A/B 的代价；证据定位；失败或未决出口。只给一句点子时，提供线索表空白版，不虚构原稿事实。灵异真实、自然解释、留白是三种互斥的故事契约，须由作者选择，不自行硬判一种。所有小说案例 F 只证明作品现象，转化为通用技法必须标 H，不等于作者方法宣言。



29 部类型源书全文实读蒸馏（Collins/Poe/Christie/Hume/Speight/Fletcher/Capes/Camp/Oakley 等，19 世纪后期至 20 世纪初英语推理，共约 2.83M o200k Token）得到 22 个规则族、113 条可执行规则。每条规则含触发情境→判断信号→操作步骤→输出→失效条件，来源锚点见 `references/source-index.md`。

## 返工后的强制证据/叙事决策（优先）

执行前读 [failure-modes.md](references/failure-modes.md) 的证据分层和两个示例。原 `impossible-crime.md` A1 与 A4 已直接修正“解案前不能出现真线索”的读者不公平设计。**先证明读者已知的线索，再判推断是否成立；不得用同一引文既证明现场事实又证明唯一解答**。对灵异、程序、历史法医只做文学结构，不提供现实作案步骤。历史元数据见 [historical-provenance.md](references/historical-provenance.md)。

## 输入权限（何时可用/不可用）

- **可用**：长篇/中篇推理小说的规划、诊断、改稿；谜题结构设计（密室/alibi/诡计/红鲱鱼）；侦探与反派人物工程；结案方式选型。
- **禁用**：现实罪案、真实侦查/法证技术、对真人的侦查指导——本 Skill 只覆盖 19 世纪后期至 20 世纪初英语推理小说的**虚构技法**，其法证/程序细节是 19-20 世纪之交的文学装置，不可当现实知识使用。
- **禁用**：把源文本的时代偏见（排华/反德/反犹/殖民主义）迁移进新作品——见 `references/motive-and-justice.md` O5 条。

## 触发与负触发

- **触发**：用户要"设计密室/诡计/不在场证明""写侦探小说""推理大纲诊断""凶手动机设计""红鲱鱼布线""结局反转设计""侦探人物方法论"。
- **负触发（应排除并说明）**：
  - "真实密室凶案怎么破/现实刑侦技术"→ 拒绝，指向表 1 权限声明；
  - "恐怖氛围写作（无谜题）"→ 本 Skill 的灵异档可参考 P 族，但谜题结构类规则不适用；
  - "言情主线+罪案背景"→ 只用 S 族情感收束与 O4 房号消毒等背景规则，核心谜题族不启用。

## 分支路由（按任务类型）

1. **从头规划**：先表 1 定灵异档 → 表 2 选核心诡计 → 表 3 定动机 → `references/impossible-crime.md` + `references/identity-and-mastermind.md` 逐条布线 → 用 O1-O4（`references/motive-and-justice.md`）搭结构句法。
2. **诊断已有稿**：先跑 `references/failure-modes.md` 六问 → 命中哪族失效条件 → 跳到对应 references 的"失效"栏取修法。
3. **单点设计**（只要一个装置）：按表 2 直达规则条目，规则内含触发/操作/输出/失效四件套。
4. **人物工程**：侦探走 I 族（`detection-and-process.md`）；反派走 G 族（`identity-and-mastermind.md`）；女性角色走 Q 族（`atmosphere-and-cast.md`）。

## 输出契约

- 每次应用须交付：**选用的规则 ID 列表 + 每条规则在本作中的具体化（触发事件/操作改写/失效规避）+ 剩余风险（该规则的失效条件在本作设定下是否闭合）**。
- 设计新诡计时必须回答 A1 的判断信号问题："读者能否复述'为什么不可能'"。

## 失败出口

- 新案例无法归入任何族 → 标注"族外案例"，不得硬套规则；记录到本项目 notes 供下轮蒸馏。
- 两书规则冲突（如真灵异 vs 伪灵异）→ 先明确作者选择的**最终解释**，允许前文制造另一档的可疑表象；不能靠“不能混档”否定合理转折；冲突明细见 `references/counterexamples.md`。
- 单源规则（仅一本书支撑）→ 使用时在输出中标注"[单源]"，不得作为普适规律断言。
- 用户请求超出虚构技法边界 → 触发"禁用"出口并说明（见输入权限节）。
