# 互动叙事改编

本文件处理**已有小说、短篇、舞台剧本或影视文本改编为互动叙事**时的叙事层决策。它不把互动改编等同于“增加选项”，也不负责完整游戏设计。

## 1. 先固定改编不变量

开始拆分支前，先写清楚：

- **核心承诺**：原作最重要的情感、悬念、关系或主题体验是什么。
- **不可随意改写的因果**：哪些事件必须发生，哪些只是原媒介的表达方式。
- **人物约束**：人物目标、底线、已知信息、关系状态及不可无依据改变的选择。
- **玩家位置**：玩家扮演谁、能影响谁、不能控制什么；玩家知道的内容与角色知道的内容是否不同。

把“原作必须保留的结果”与“原作采用的表达手段”分开。前者需要说明保留理由；后者可以因互动媒介重组。

## 2. 先分类选择，再写分支

每个选择先标记类型：

| 类型 | 实际变化 | 适用处理 |
|---|---|---|
| 表达型 | 改变语气、态度或玩家表达，不改变后续状态 | 明确它是角色表达或关系色彩，不承诺路线变化 |
| 状态型 | 改变信任、资源、承诺、知识或关系状态 | 写出状态变化、可观察反馈和后续影响 |
| 路线型 | 改变事件顺序、可访问节点或结局条件 | 明确入口条件、分支路径、回收点或独立结局 |

不要把没有后续影响的选项包装成重大分歧。若多个选项最终汇合，说明它们分别改变了什么；如果只改变措辞，就按表达型处理。

## 3. 定义状态与后果

每个状态变量至少写清：

1. 名称和含义，避免两个变量表达同一事实。
2. 初始值或初始条件。
3. 哪个选择或事件可以改变它。
4. 改变后由哪个节点读取，以及产生什么可见后果。
5. 何时重置、保持或失效。

同一叙事事实只保留一个权威状态。不要在多个节点分别维护互相矛盾的“信任值”“是否知情”等副本。状态只在确实影响后续叙事时才建立；不需要的变量不创建。

## 4. 画分支图，明确回收与终止

每个节点记录入口条件、触发事件、玩家选择、状态变化、即时后果、延迟后果，以及下一节点。分支可以回收，但回收前必须处理分支已经造成的关系、知识和承诺差异；不能在回收时无解释地抹平。

每条路线至少检查：

- 是否有入口，是否可从起点到达。
- 是否有明确的下一步，是否出现无出口节点。
- 是否存在永远无法满足的结局条件。
- 回收后人物是否仍记得已发生的事。
- 同一时间点是否出现互相排斥的状态。

检查结果用 `templates/interactive-branch-sheet.md` 的四个状态记录：

- **VERIFIED**：检查已执行，结论有分支表或文本证据支持，可以当作已验证交付。
- **NOT_PROVEN**：检查已执行，但结论依赖标明的设计假设或尚未核实的判断，不能记作 VERIFIED。
- **NOT_RUN**：本轮还没有执行该项检查；材料齐了就能做。
- **BLOCKED**：该项检查因缺少决定性输入而暂时无法执行，例如作者未定结局、平台规范未确认或需要外部专业核验；先补输入，再做检查。

NOT_RUN 与 BLOCKED 的区别：前者是还没轮到做，后者是现在做会被缺失的输入挡住。凡不是 VERIFIED 的项，在分支表「证据或限制」列写明原因和影响。

路线图用于表达叙事因果，不代替工程实现图或关卡流程图。

## 5. 分开玩家知识与人物知识

互动叙事至少有两条信息轨：

- **玩家知识**：玩家从文本、界面、提示、已走路线和先前选择中获得的信息。
- **角色知识**：角色在当前路线、当前时间点实际知道或合理推断的信息。

玩家知道秘密，不代表角色可以直接使用秘密；角色知道某事，也不代表玩家已经得到足够提示。对白、选项和反馈不得让人物使用尚未获得的信息。涉及视角、叙述权限、关系变化或时间连续性时，调用 `character-and-narrative-control` 做角色层回归；本 Skill 负责分支结构，不重复定义人物知识规则。

## 6. 反馈要对应真实变化

选择后用对白、动作、场景变化、可访问信息或后续事件反馈结果。反馈可以延迟，但要让玩家有机会理解“选择造成了什么”。如果后果暂时不可见，在设计表中标明延迟触发条件，不把无反馈误当成有意义的选择。

不要为了制造分支而让人物做出违背既有目标、知识或关系的选择。玩家 agency 受人物设定和世界规则约束；无法控制的事件应通过叙事说明，而不是伪装成玩家选择。

## 7. 从其他媒介迁移时的重点

- **小说到互动**：把内心活动拆成可执行行动、可观察线索或明确保留的内心文本；不要把所有内心句机械改成对白或选项。
- **舞台到互动**：把场面调度、现场压力和演员可见行动转为节点条件、行动窗口或关系状态；不要把舞台提示直接当作游戏机制。
- **影视到互动**：把镜头揭示、剪辑省略和声音提示转为玩家可获得的信息或节点反馈；不要默认玩家能看到角色未经历的镜头信息。
- **互动到其他媒介**：先找出关键选择实际改变的关系、承诺、信息或结局，再决定用场景、动作、对白或剪辑承载；不要把选项列表原样搬进线性文本。

## 8. 交付与职责边界

本 Skill 可交付：改编不变量表、玩家位置说明、选择分类表、状态表、分支/回收图、路线验证清单，以及需要改写的对白或场景清单。

本 Skill **不交付**：战斗与经济系统、数值平衡、关卡设计、成长曲线、商业化、引擎实现、界面交互规范、可访问性评估或制作预算。需要这些内容时，明确列为外部依赖，交由游戏系统设计、UX、技术或制作负责人；不得用叙事改编结果冒充这些专业交付。

职责交接：`fiction-planning-and-diagnosis` 负责原创故事的规划与诊断；本 Skill 负责既有文本的媒介转换；`character-and-narrative-control` 负责人物视角、知识权限、关系和时间连续性回归；`line-editing-and-proofreading` 负责对白、字幕和界面文本的语言编辑，不改选择逻辑。
