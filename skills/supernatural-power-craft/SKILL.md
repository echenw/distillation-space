# Supernatural Power Craft（超自然力量机制）

## P4 直接执行示例（优先读）

**例：用户说"我写了一主角戴戒指能心想事成，帮我看看有没有问题，别改稿"。**
这是**诊断**任务（有稿）。先填 `templates/diagnosis-report.md` 的 DR-01（已读范围）。
戒指属**权属型**（RC-08）。打开 `references/rules.md` RC-08，按顺序追问四件事：
① 权属的唯一绑定者是谁；② 离开主人是否失效（对照 PG496 L1186-1188）；
③ 是否需要**组合件**（对照 PG66196 L465-491 的 sigil + ring）；
④ 有没有**不可撤销的关闭键**（PG3536 L1085-1096 的"解除一切魔法的搭扣"）。
四问里只要有两问答不出，就判"力量尚未成形，只能被情节推着走"，
给 DR-02 的严重度与最小验证动作，**不在未授权时改稿**。

**例：用户说"我要给女主的法力加个限制，别让她太强"。**
这是**规划**任务。先按 RC-01 给体系的**类型**分类（授予/权属/获得/血统），
类型不定就不许谈限制——因为四种类型的书写负担完全不同（见 CC-01）。
定完类型再走 `references/design-and-diagnosis.md` §2 的四要件。

**例：用户说"我的仙侠稿要分九个大境界，每境三层，怎么排？"**
**走失败出口**：本批 25 本来源里没有任何一本支持"境界分层/金丹/渡劫/宗门制"，
它们是 19 世纪中叶—1930 年前后的英文公版幻想、童话与冒险小说（RC-10）。
如实回答"超出本批证据"，转出；不得把收藏夹式的类型常识说成来源支持的规律。

操作顺序：**文本证据 → 类型分型 → 补哪一条要件 → 填表 → 失败出口**。
证据底座一句话：25 部 Project Gutenberg 英文/英译虚构作品（1850 年前后—1930 年代），
全部为 `FICTION_CASE`（作品现象），不是作者教诲；由它们上升的规则一律标 **H**。

## 0. 这是什么

一个**人工填表 + 条件判断**的 workflow，不是自动引擎。

- 输入：用户提供的真实文本、设定、大纲或明确口述的构想。
- 输出：机制类型判定、缺失要件的定位、可选补法与其代价、可回读的两张表。
- 不做：不写整段正文、不评分、不预测读者/市场、不自动改稿、不含 scripts、不建状态机。
- 不能替代：作者对力量体系与道德立场的选择、编辑对市场的判断、真实读者数据。

**证据底座（务必先读）**：本包的来源是任务 **A-05-B03**（`16-类型小说专项/04-武侠仙侠玄幻/批次-03`）
的 25 部公版作品。任务元数据明确写着
`batch_is_workload_partition_not_new_semantic_genre: true`、
`no_semantic_genre_reclassification: true`——**"批次-03"是工作量切分，不是亚类型**。
实际书目为 Undine、The Well at the World's End、Twenty-Two Goblins、Flower Fables、
The Little Lame Prince、The Wonderful Visit、Fifty-One Tales、Ayesha、四部 Tarzan、
The Enchanted Crusade、The Blue Star 等英文文本。**其中没有任何中文原文、没有当代网络连载。**

## 1. 触发 / 负触发

**触发是给显式调用的路由，不是宿主自动加载。** 宿主是否加载、何时加载由宿主决定；
`agents/openai.yaml` 声明 `allow_implicit_invocation: false`。下列"满足任一"只用于
用户或宿主**已经调用本 Skill 之后**的任务分流。

### 触发（满足任一）

- 设计一个力量体系：法力/修炼/血脉/器物驱动的能力，需要定边界、定代价、定失效条件。
- 已有的设定或稿子里，**力量被写得越来越强、问题却越来越少**（万能化）。
- 稿子里出现的人物每回合都能用近乎无限的能力脱困，紧张感消失。
- 需要判断：这个能力是一次性授予、绑定器物、还是伴随身份变化而取得。
- 要写：禁忌/不能做的事及其后果；诅咒与解除；变身/变形的识别；起死回生；长生；
  两个世界（或显/隐两界）的接触规则。
- 师徒传承、宗门/家族/教团的授受，需要写"传失败会怎样"。
- 已经写了一大段，发现前面的承诺（承诺过的代价/禁制）在后面没兑现，需要核账。

### 负触发（不要用）

- **爽点设计、读者留存、市场/销量预测**：本批无一教诲文献支持，不覆盖。
- **节奏、章节结构分量、章末钩子的取舍**：属情节架构类，请转相关 Skill。
- **纯世界观设定集（地理、历史、种族、货币）的编纂**：本 Skill 只处理"力"的条款。
- **影视分镜、镜头语言、游戏数值/关卡/状态机**：无样本，不覆盖。
- **句段润色、校对、翻译**：不覆盖。
- **要求用本包证明"读者一定会买单""这样写一定更爽"**：直接说做不到。
- **把单部小说的情节设计说成通用规则**：这是本 Skill 的红线，见 RC-10 与 §7。

## 2. 输入权限

| 用户给了什么 | 可以做什么 | 不可以做什么 |
|---|---|---|
| 真实文本 + 范围 | 诊断、核账、给严重度与最小验证动作 | 诊断未读部分；把推测写成文本事实 |
| 设定/大纲/能力清单 | 类型判定、要件补缺、分支建议 | 假装读过正文；替作者写完套路 |
| 只有一句构想 | RC-01 类型问句 + 空白画布 | 虚构人物、事件、代价；声称"已设计完成" |
| 只有"把这个改强/改弱" | 先要范围与目标；给代价—收益对照 | 直接改设定而不说代价由谁付 |

- **没有原文时**：只给检查问句与空白模板（`templates/`），不虚构诊断。
- **不自动改稿**：默认输出"定位 + 可选补法 + 代价"。改整段设定/整条线需明确范围与目标。
- **不覆盖原稿**：任何试改只在副本；原稿只读。

## 3. 任务路由

先判任务类型，只读对应文件；**不要一次读完所有 reference**。

| 任务 | 首要 reference | 补读条件 | 缺少输入时的出口 |
|---|---|---|---|
| **规划**（还没有稿） | [design-and-diagnosis.md](references/design-and-diagnosis.md) §2 | 分型难 → `rules.md` RC-01；要写冲突 → `scope-and-conflicts.md` | 只填 `PS-01` 类型判定 + 空白画布；不编设定 |
| **诊断**（有稿/有设定） | [design-and-diagnosis.md](references/design-and-diagnosis.md) §3 | 按症状查 `rules.md` 对应 RC；填 `templates/diagnosis-report.md` | 只给检查问句；不诊断未读部分 |
| **核账**（前有承诺后未兑现） | [design-and-diagnosis.md](references/design-and-diagnosis.md) §4 | 代价类 → RC-02；禁忌类 → RC-03；复活类 → RC-06 | 只列未兑现项清单，不替作者圆 |
| **边界判断**（这是不是本 Skill 的事） | [scope-and-conflicts.md](references/scope-and-conflicts.md) §1 | 直接读 RC-10 | 说明边界并转出 |

**任务判据**（避免把"诊断"做成"重写"）：

- **规划**：还没有本稿，只有构想/素材；输出表与问句，不评判还没写的文字。
- **诊断**：有已写文本；先证伪（找 already 写过的条款）再判，给严重度，不改稿。
- **核账**：已有前后文本；只列"承诺 vs 兑现"的差额，不替作者补写。
- **边界判断**：不确定该不该用本 Skill；先读 RC-10，再决定是否转出。

## 4. 最小工作流（3 步内开始）

1. **判任务**：规划 / 诊断 / 核账 / 边界判断（上表）。任务不清 → 先做诊断。
2. **收范围**：文本标识、版本、章节/行、**未读范围**、目标。缺范围 → 严重度降级。
3. **打开首要 reference 的第一张表，填第一行**：
   - 规划：`PS-01` 类型 + `PS-02` 四要件第一行；
   - 诊断：`DR-01` 范围 + `DR-02` 第一条文本证据；
   - 核账：`DR-06` 第一笔未兑现账。

之后按 reference 顺序走。**不从"给角色加个更酷的能力"开始**，
也不在机制未定时讨论它在某一场里好不好看。

## 5. 输出与 Owner

### 本 Skill 负责

- 类型判定：这套力量是授予型 / 权属型 / 获得型 / 血统型（RC-01）。
- 要件核对：能力清单与关闭开关（RC-01）、代价记账（RC-02）、禁忌三件套（RC-03）、
  变形的识别与不可变标记（RC-04）、传承连带责任（RC-05）、复活/不死的分型与代价（RC-06）、
  双世界接触的三段式（RC-07）、权属与伪造（RC-08）、社会再分类（RC-09）。
- 边界声明：哪些问题本批证据不能答（RC-10）。
- 可回读的两张表：`power-system-canvas`、`diagnosis-report`。

### 本 Skill 不负责（交回用户/其他流程）

- 作者要"爽"还是要"悲"的整体取向；读者的实际反应与市场份额。
- 章节结构、钩子、节奏、视角与声音设计。
- 地理/历史/货币/种族设定集的编纂。
- 数值平衡、影视/游戏实现。

**Owner**：条款草案与表由本 Skill 产出；**取舍决定权在作者**。
本 Skill 不替作者决定"这套力量最后要表达什么"。

**接口**：本 Skill **不依赖其他 Skill、Registry 或状态机**，也没有 provider/回调接口；
§5 的"交回"只是转介建议，不是自动调用。所有表由人填写，结论可被作者/编辑推翻。

## 7. 失败 / 退出

| 情况 | 能做的 | 不能做 / 退回 |
|---|---|---|
| **材料不足**（无文本，只有一句构想） | 给类型问句 + 空白画布 | 不虚构诊断、不代编设定、不声称已设计 |
| **类型分不出**（既像权属又像血统） | 列为"类型未定"，停在这一步；写出两条路的代价 | 不平均、不偷偷替作者选类型 |
| **目标冲突**（又要万能又要代价重） | 列两方案 + 代价，让作者选 | 不淡化其中一侧 |
| **冲突未决**（CC-01 力量是否被社会承认；CC-02 后果可否免除） | 给双向分支与安全出口 | 不压成一条"通用规律" |
| **权限不足**（未授权改稿/改设定） | 只给定位、可选补法、代价 | 不重写、不覆盖原稿 |
| **证据范围外**（中文网络连载、境界分层/金丹/渡劫/宗门、影视/游戏、市场预测） | 标 H / NOT_PROVEN，说明边界并转出 | 不假装有覆盖、不把类型常识写成来源支持 |
| **用户只要爽感不在意机制** | 明说本 Skill 帮不上；不硬套条款 | 不伪装成"也能帮你变爽" |

**冲突时的默认顺序**（只在没有硬约束时）：
**已向读者做出的承诺 > 机制自洽 > 场面好看 > 数值强弱 > 局部文采**。
若两方案都可行，输出"方案 A / B + 代价"，让作者选。

## 8. 证据边界与验证状态

- **来源规模**：25 部 Project Gutenberg 文本，阅读版合计 **178,848 行**；本轮核验：
  25/25 `整本阅读版.txt` 存在且 **sha256 与清单 `sha256_reading` 逐字一致**。
- **语言/年代**：英文原文或英译（含梵文、德语转译），1850 年前后—1930 年代；
  **无中文原文、无 1945 年后材料、无当代网络连载样本**。
- **来源类型**：`material_role` 均为 `FICTION_CASE`。**它们证明"作品里发生了什么"，
  不证明"作者主张应当怎么写"**。所有规则标 **H**（推导），无一条可标 F 直接升格。
- **取证深度**：本轮 L1 全文复核 5 本（PG496/PG163/PG33913/PG2825/PG10441），
  L2 定向取证 20 本（见 `source-index.md` §0）。L2 证据只用于说明"书中确有该机制"，
  不声称本轮逐块读完该书。
- **强的一条 / 弱的一条**：PG169 L14573-14590 的"不可长生、怕饮者成为 earthly gods
  而虐政"是本批最硬的代价论据；PG71195 的政治线与 PG7838 的多数篇目对本 Skill
  **不适用**（不合的气氛/讽刺小品），它们只列入 `source-index.md` 的不适用清单，不进规则证据。
- **验证状态**：本包为**静态交付**；真实稿件**未运行（NOT_RUN）**，
  规则效果**未证明（NOT_PROVEN）**。没有 scripts、没有自动校验、没有状态机。
