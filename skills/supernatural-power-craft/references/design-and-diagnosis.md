# 工作流：规划 / 诊断 / 核账

三条工作流共用同一批 RC；本文件只写**步骤顺序与停下来的条件**，
规则正文一律回 `references/rules.md`，不在这里复制第二版。

## 0. 通用 preamble（三条都要做）

1. 记下**範囲**：用户给了什么标识、哪些读过、哪些没读。**没读过的一律不诊断**。
2. 在输出开头写一句："本结论来自 25 部 1850–1930 年代英文虚构作品的现象归纳"（RC-10）。
3. 先做 RC-01 的类型判定。**类型不定就不许谈限制**。

## 1. 边界判断（不到 1 分钟）

读一遍下面的清单，命中任意一条就**停**，走 SKILL.md §7 的失败出口，
不要硬往下做：

- 用户问的是爽点设计、读者留存、市场/销量预测 → 转出。
- 用户问的是章节结构分量、节奏、钩子、视角、声音 → 转情节/叙事类流程。
- 用户要编地理/历史/货币/种族设定集 → 转世界观类流程。
- 用户问"境界怎么分层/金丹渡劫/宗门怎么排" → 按 RC-10 明说超出本批证据，转出。
- 用户给的是真实非虚构材料（新闻、史料）→ 转出。
- 只有一句"帮我变强/变爽"，且不愿谈代价 → 只能给 §2 的检查问句，不给答案。

## 2. 规划（还没有稿）

适用：有构想、有人设、有简介，还没有成型段落。

**顺序**：RC-01 → RC-02 → RC-08 → （涉及时）RC-03 / RC-04 / RC-05 / RC-06 / RC-07 → RC-09。

1. **PS-01 类型**：这套力量是授予 / 权属 / 获得 / 血统？（RC-01 的表格）
   - 分不出 → 停。把两条路各自的书写负担写给作者，请他选。**不得替他选。**
2. **PS-02 四要件**：能做什么（逐条）/ 不能做什么（至少一条）/ 怎么关掉 / 谁来重启。（RC-01）
3. **PS-03 记账方式**：四选一（RC-02）。
   - 选了"可还清的钱"→ 提醒作者：**它不产生悲剧强制力**，别指望第三幕从这里出张力。
4. **PS-04 关闭开关**：至少一件可解除它的东西（RC-08）。
5. **PS-05 禁忌三件套**（若作品打算写禁制）：条款 / 后果 / 谁发现（RC-03）。
6. **PS-06 变形识别** / **PS-07 传承连带** / **PS-08 生死分型** / **PS-09 两边界触**：
   用到哪块填哪块；不用的留空，**不要为了填满而编**。
7. **PS-10 社会命名权**：谁有权定义这种力量？他们把它归进哪一类？（RC-09）
8. 交回作者：**只交问句与画布**，不交"标准答案"。任何 PS 行写不出，
   就如实写成"该项未定"，并在最后汇总成一张缺口清单。

## 3. 诊断（有稿/有成稿设定）

适用：有真实文本或已写成的设定，用户想知道机制是否站得住。

**原则：先证伪，再判。** 先在文本里找"这个其实已经写掉了"的证据，找不到才算缺口。

1. **DR-01 范围**：读过哪几段/第几章，哪些没读。**未读部分不诊断。**
2. **DR-02 证据**：逐条抄下有行号或章节定位的原文片段（至少 1 条/判定的 RC）。
3. 按症状选 RC：

| 症状（用户说的或你看到的） | 走哪条 RC | 常见缺口 |
|---|---|---|
| "感觉他越来越无敌" | RC-01（先看有没有关闭开关）→ RC-02 | 没有"不能做什么"这一栏 |
| "代价写了，但读者不紧张" | RC-02 | 选了可还清的钱，却期待悲剧感 |
| "禁制没人当回事" | RC-03 | 缺"谁能发现" |
| "变身之后谁都认不出，太方便" | RC-04 | 看穿者名单为空 |
| "师父传功那段很水" | RC-05 | 没有连带责任 |
| "复活之后一切照旧" | RC-06 | 分型混写；关系被默认复原 |
| "外来者那段说不清楚" | RC-07 | 缺硬不相容，或退场靠解说 |
| "拿到神器就赢了" | RC-08 | 没写权属条款，等于谁拿都能用 |
| "超自然出现后世界毫无反应" | RC-09 | 没有命名权的归属方 |

4. **DR-03 严重度**：`blocking`（机制不成立，情节会塌）/ `major`（明显万能化）/
   `minor`（细节不严谨）/ `n/a`（不适用）。
5. **DR-04 最小验证动作**：给一个**能在下一次通读时直接完成**的动作，
   例如"只看第三到第五章，数出他一共动用了几次能力，看有没有一次失败"。
6. **不做的**：不改稿、不替作者补写机制、不把"未读"当成"没写"。

## 4. 核账（前有承诺，后未兑现）

适用：已经写了相当篇幅，用户怀疑前面答应的条件后面没算数。

1. **DR-05 账目表**：把文本里出现过的每一条实质条款列一行——
   能力边界、代价、禁忌、赠与、誓言、所有权、不许碰的东西、不许说的话。
2. **DR-06 兑现情况**：逐行标 已兑现 / 未兑现 / 反向发生（做了相反的事）。
3. **DR-07 归因**：未兑现是因为**忘了**，还是因为**作者中途换了契约类型**
   （比如开头是权属型，写着写着变成了授予型）。后者要按 RC-01 重新分型，
   不要以为补一句就能圆回去。
4. **DR-08 最小改法**：给 1–3 个可选补法，**各自写明代价**
   （补一处条款通常要牺牲另一处的场面）。
5. **DR-09 不改的选项**：也让作者看见"就让它未兑现，并在文本里承认它有漏洞"这一路。
6. **DR-10 出口**：若用户拒绝任何改动，只留账目表，标`未解决`。

## 5. 三条共用的收尾

- 每次输出必须以一句**未做的事**结尾（未读范围 / 未解决的问题 / 未证明的规则）。
- 任何一处引用都要能回原文核对；**转述的句子不许加引号**。
- 规则效果 NOT_PROVEN；不要写"这样改读者一定会买账"。
