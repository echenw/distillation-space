# Diagnosis Report（诊断报告）

**用法**：一份报告只针对一个稿/一个版本、一个明确范围。先填 §1 的 `DR-01`–`DR-10` 与 `DR-SUM` 字段行（每个 ID 独占一行），再把明细填进 §2–§5。每个症状一行；没有文本证据的判断不写进结论。`UNKNOWN` / `UNREAD` / `UNVERIFIED` 必须照实标，不得留空或猜。本表是人工工作纸，不含脚本、不自动评分。

## 1. 字段清单（DR-01–DR-10 + DR-SUM，每 ID 一行）

| 字段 ID | 字段 | 填写口径 | 所属表 |
|---|---|---|---|
| DR-01 | 范围与版本 | 作品/稿名、版本/日期、总长度、实际读过范围、未读范围、交付方式、诊断目的、报告人/日期 | §2 范围表 |
| DR-02 | 文本证据 | 章/场/行、原文短引（≤40 词）或准确转述、结构事实、证据类型；每条发现至少一条 | §3 证据表 |
| DR-03 | 症状 | 用 `diagnosis.md` 的八类之一，可加子症状；同一段文本只报一次 | §4 发现表第 2 列 |
| DR-04 | 适用规则 | 写 `RC-xx`，不写书名；一条发现最多 3 条主规则，其余放“同时检查” | §4 发现表第 3 列 |
| DR-05 | 分支判断（含先证伪） | 必须写“我试过哪种非缺陷解释、为什么排除”，或“撤销该症状” | §4 发现表第 4 列 |
| DR-06 | 严重度 | 阻断＝不修则不可读/不可信；重要＝结构成立但明显失效；建议＝局部效率；连续三次/开篇/结尾/主线可升级 | §4 发现表第 5 列 |
| DR-07 | 最小验证动作 | 人工可执行、能证伪判断的动作（写一句主行动、删场试读、列巧合清单、并排两场）；不写“再改改看” | §4 发现表第 6 列 |
| DR-08 | 建议修改 | 定位 + 改什么结构关系 + 不动什么；不写整段重写；需要改写时另走 `revision.md` 并标“可选最小改写” | §4 发现表第 7 列 |
| DR-09 | 回归检查 | 改后必须重跑哪张表/哪条规则；至少写 RC-07/RC-05（若动了结构）；做了删场测试的回写 `ST-20`–`ST-24` 结论 | §4 发现表第 8 列 |
| DR-10 | 未决项（发现级） | 该条发现缺文本/缺版本/缺读者数据/需作者决定的价值问题；不得把未决项写成“已修” | §4 发现表第 9 列 |
| DR-SUM | 未决项与证据缺口（报告级） | 跨发现的未读范围、版本不明、读者转述、需作者定夺的价值问题；报告级汇总专用，不与发现级 DR-10 混用 | §5 汇总表 |

> 报告级的未决项与证据缺口不用 `DR-10`，统一填 §5 的 `DR-SUM`；`DR-10` 只记“这一条发现”自身的未决项。

## 7. 报告完成检查

- `DR-01`–`DR-10` 每行有值；没有空白冒充“无问题”。
- 每条发现至少一条 `E-xx` 文本证据；没有证据的只放“待验证”，不进结论。
- 每条发现都写了“先证伪”的结果（撤销/仍判/UNRESOLVED）。
- 严重度不是按“读起来爽不爽”给；按“不修会失去什么”给。
- 没有把类型惯例（喜剧巧合/童话奇迹/连载钩子/单行本收束）判成缺陷。
- 没有把单来源参数（3/4、中点照面）当硬指标。
- 未读范围、版本不明、读者转述，全部进 `DR-SUM`，不混进结论。
- 本报告不等于修改；改写需另走 `revision.md` 并取得范围授权。
