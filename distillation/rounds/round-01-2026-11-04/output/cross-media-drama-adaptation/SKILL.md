# 跨媒介戏剧改编

把改编当成一次有边界的功能转换：先确定必须保留什么，再判断原作的表达功能在目标媒介中怎样实现。不能把文字逐句搬成镜头或舞台动作，也不能因为媒介不同就擅自改变作者已经锁定的事实、关系和结局。

## 1. 适用与转介

适用：

- 把小说、故事、已有剧本或其他叙事材料改成舞台、影视、音频或表演形式。
- 检查现有改编稿的分场、场景单位、时间连续性、信息披露、画面和表演。
- 为一个关键场景比较直接呈现、转述、物件、字幕、声音或其他载体。

不接（负触发，先说明或转介）：

- 漫画、图像小说或分镜稿的格序、页面节奏与画面语言设计：本 Skill 处理改到舞台、影视、音频和互动叙事的路径，不产出漫画分镜。
- 某个制式剧本软件或拍摄软件的行业排版规范（字体、页边距、行距这类）：按交付方给出的格式要求办，本 Skill 不存这类规范。
- 按平台算法或流量数据调节奏、做运营优化：本 Skill 按作品承诺和媒介条件设计，不按流量指标设计。
- 只要市场预测、票房或流量判断，不要文本分析：给不了；依据只能来自当前文本的分析和标明的设计假设。
- 照抄某个现成改编版、借用受保护的具体表达：按 AD-29 和 `examples/adaptation-cases.md` 用例 D 处理，可继续分析其结构功能，不直接复制。
- 生成／修订／诊断预设卡（推进卡、文风卡、表达约束卡），或把改编方案写成给模型用的卡 → 转 `preset-card-generation`。

转给其他 Skill：

| 问题 | 转给 |
|---|---|
| 原作的读者契约、人物和事实核验 | `fiction-planning-and-diagnosis` |
| 全书主线、多线、分卷与长篇结构 | `story-architecture-and-longform-planning` |
| 单场冲突、悬念、节奏与章末 | `scene-conflict-and-rhythm` |
| 人物动机、叙述视角、信息控制和时间模型 | `character-and-narrative-control` |
| 句子、对白、标点和校对 | `line-editing-and-proofreading` |
| 生成或修订推进模式卡、文风卡、表达约束卡，按三轴审章节，把改编方案写成给模型用的卡 | `preset-card-generation` |

这些转介是深化路径，不是完成改编任务的前提；本 Skill 内已有的合同、检查表和规则可以独立使用。

不在范围：现实法律意见、版权许可结论、医学或技术参数认证、市场预测。涉及这些内容时，标明需要的专业核验，不把整个改编任务停掉。

## 2. 使用方式

- 宿主规定了输出格式，就按宿主格式交付。
- 普通任务先读本文件和 `templates/adaptation-workbook.md`；需要某个问题的条件和反例时，再读对应参考文件。
- 只有梗概时，只分析梗概，不声称完成改编诊断；没有完整剧本，不编造场次或镜头问题。需要创作交付时，可以标明假设往下做，并在交付清单列明尚未核实的项。
- 用户锁定的事实、关系和结局不擅自改变；允许改写的部分要说明改动目的。
- 现实中的专业事实需要独立核验；虚构世界的规则则检查内部一致性。
- 自建例子要明确标记，不把它们说成用户原稿或真实制作案例。
- 没有真实观众测试时，不说悬念、笑点、恐惧或情绪效果已经验证。
- 复杂操作（媒介取舍、结局形态、多线并行、互动分支）的判断标准与裁决走 `references/conflicts.md` 的五个分歧和裁决备忘；完整自创难例见 `examples/adaptation-cases.md` 用例 E；交付状态词与失败出口见 §10、§11。

## 3. 最短路径

1. **确定材料和授权。** 取得原作范围、目标媒介、受众、原作的版本、必须保留的功能、允许修改的部分和制作条件。
2. **写改编合同。** 明确必须保留、可以改变、不可擅自新增和最终要让观众理解或感受到什么。
3. **按问题选规则。** 先判断是功能转换、分场连续性、信息载体、情节结局、舞台实现还是画面设计。
4. **做最小转换。** 选择动作、物件、对白、字幕、声音、转述或结构重排；不要为使用某个媒介手段而强加它。
5. **回看受影响的部分。** 检查因果、人物知情、空间位置、时间、资源、关系和观众承诺。
6. **交付实际改编。** 要正文就写正文，要分场就给分场，要诊断就给位置、问题、证据、替代方案和修改建议。

### 交付清单

改编合同；采用的规则编号；具体改写或方案；保留和改变的内容；尚未核实的专业事实；需要作者决定的取舍；改后连续性回看。

## 5. 规则卡

完整说明、适用条件、反例和操作步骤在参考文件里；AD 编号是本 Skill 的内部规则编号。

### 能不能转（`references/transferability.md`）

- **AD-01 先写改编合同**：必须保留的行动、人物关系和情绪目标；目标媒介及其叙事单位；允许改变的内容；受众和已知制作条件。
- **AD-02 抽掉台词，看还剩什么**：检查场景靠语言还是靠可见行动成立；依赖语言的作品需要保留语言通道或重构功能，不等于不能改。
- **AD-03 侦探故事检查证据路径**：分别检查推理是否依赖解释、关键事件是否缺少上下文、按时间顺序是否提前泄露信息、揭晓是否依赖观众无法接触的证据。
- **AD-04 要让观众看见的时刻**：列出关键行动和它需要传达的信息，检查目标媒介是否让观众直接体验到。
- **AD-05 幻想题材要让规则可感知**：若变化本身是观众需要体验的部分，呈现触发条件、变化过程和代价；刻意神秘时可以保留不确定性。
- **AD-06 能演出来，不一定要演**：关键事件可通过后果、物件、声音、证词或转述成立；是否直接展示取决于观众需要判断什么。

### 分场、编号与连续性（`references/scenes-and-continuity.md`）

- **AD-07 定义本项目的“场”**：区分戏剧场景、舞台场面、镜头/拍摄单位和剪辑段。
- **AD-08 同一人物换地点要交代**：检查移动过程、经过时间或转场线索；不同人物在两地同时行动属于并行线。
- **AD-09 交替推进，回切不当跑题**：每次回切写明回到哪条线、当前目标和离开期间发生的变化。
- **AD-10 现在进行不等于时间顺序**：分开记录故事时间、人物经历和观众接收信息的顺序。
- **AD-11 时间跳跃要看得懂**：用字幕、物件、服装、声音、季节或场景变化提示，不重复解释已经清楚的信息。
- **AD-12 片长和场数不是历史门槛**：按目标媒介、平台、预算、体裁和场景功能确定。

### 信息载体（`references/information-carriers.md`）

- **AD-13 文字是辅助**：文字可以标时间、地点或必要信息，但不能自动取代场景。
- **AD-14 文字插入的功能**：标记时间、解释画面表达不了的信息、分隔段落或建立语气；没有功能的删去。
- **AD-15 文字要一次看懂**：一条只说一个主要事实，按目标媒介测试可读性和显示时长。
- **AD-16 信件、消息和文件**：让它们成为行动的一部分，记录谁写、谁送、谁能看到、何时收到以及收到后发生什么。
- **AD-17 声音要有接收者或后果**：检查谁听见、如何反应、声音改变了什么；区分听见的事实和人物推断。

### 情节、高潮、结局与同情（`references/plot-and-ending.md`）

- **AD-18 情节是一份因果工作计划**：把准备、纠葛和收束映射到场景；作品有意采用其他结构时不强造中心冲突。
- **AD-19 先找高潮，再安排递进**：检查信息、风险、代价和选择如何变化；允许缓解、多峰和循环结构。
- **AD-20 结局形态**：圆满、悲剧、人物变形和开放结尾都可用，按作品承诺和因果选择。
- **AD-21 悬念与信息量**：分开故事因果、披露顺序和公平推理承诺；延迟必须增加信息、风险或改变解释。
- **AD-22 兴趣中心与同情**：让观众知道当前场景由谁的目标或行动主导；理解人物动机不等于替其行为开脱。

### 舞台落地（`references/stage-realization.md`）

- **AD-23 先读透文本**：区分必须执行的机械信息、氛围建议和可供导演选择的解释。
- **AD-24 走位要有理由**：人物意图、关系、节奏、视线或构图；静止也可以是有效调度。
- **AD-25 群众按舞台条件分组**：结合场地、演员、可见性、排练时间和安全，不设固定人数。
- **AD-26 布景和灯光暗示或复制**：按戏剧功能、场地、成本和换景条件选择。
- **AD-27 旁白（aside）是媒介约定**：舞台 aside 靠约定成立，转换媒介时保留功能、不机械保留形式；叙述性旁白（画外音、解说）不归这条管，按 AD-02 与信息载体的选载体步骤处理。
- **AD-28 排练按复杂度安排**：为转场、节奏、层次和高潮留出时间，不设固定周数。
- **AD-29 权利与许可**：确认权利归属、授权范围和合同限制；本 Skill 不提供法律意见。

### 画面检查（`references/pictorial-checks.md`）

- **AD-30 构图优先级**：写明观众第一眼应该注意什么。
- **AD-31 运动与方向**：检查无关运动是否抢注意、相邻镜头方向是否自洽。
- **AD-32 重复和地点**：重复元素要带来变化；地点数量按功能决定。
- **AD-33 视觉警示**：前景背景竞争、只靠表情表演、把意象解释得太满，都是需要检查的风险，不是硬禁令。
- **AD-34 氛围效果**：先写目标效果，再选择写实、风格化或混合。

## 7. 冲突时的顺序

规则互相打架、又没有作者明确要求时，按这个顺序取舍：改编合同与权利（AD-01、AD-29）→ 目标媒介中观众能否感知（AD-02、AD-06、AD-13 至 AD-17）→ 因果和高潮（AD-18 至 AD-22）→ 连续性（AD-07 至 AD-11）→ 实现条件（片长 AD-12、舞台 AD-23 至 AD-28、画面 AD-30 至 AD-34）→ 操作默认值和个人偏好。五组主要取舍见 `references/conflicts.md`。目标媒介是互动叙事时，AD-35 至 AD-40 不另设一层，按性质并入上述各层：玩家位置与不变量（AD-35）随改编合同层先定，选择与状态（AD-36、AD-37）随因果层，分支回收与玩家/角色知识（AD-38、AD-39）随连续性层，反馈与路线验证（AD-40）随实现条件层。

## 8. 适用边界与验证

- 历史媒介规范、设备限制、制作数字和空间约定不能直接当作当前平台规则；迁移时先核对目标媒介的实际条件。
- 所有关于观众反应的判断都是设计假设。没有真实观众测试时，不宣称效果已验证。
- 本 Skill 提供改编分析和创作方法，不提供法律意见、市场预测或版权授权。是否采纳由作者决定。

## 9. 互动叙事改编（AD-35–40）

当目标媒介是互动叙事，先读取 `references/interactive-adaptation.md`，并使用 `templates/interactive-branch-sheet.md` 记录叙事层分支。不得把“增加选项”当作完整改编。

- **AD-35 玩家位置**：明确玩家扮演者、可控制对象、不可控制事项，以及玩家知识与角色知识的差异。
- **AD-36 选择分类**：区分表达型、状态型和路线型选择；无后续影响的选项不得包装成重大分歧。
- **AD-37 状态单一归属**：每个叙事状态有明确含义、初始条件、写入事件、读取节点、失效或重置条件；不建立无后续作用的变量。
- **AD-38 分支与回收**：记录入口、选择、后果、回收点或结局；回收不得无解释地抹平关系、知识和承诺差异。
- **AD-39 信息与时间回归**：分开玩家知识和角色知识，逐节点核对时间顺序、人物已知信息和选择前提；需要时调用 `character-and-narrative-control`。
- **AD-40 反馈与路线验证**：每个有实质后果的选择要有即时或延迟反馈；检查节点可达、结局条件可满足、无孤立路线和无解释的状态冲突。

本 Skill 只负责既有文本改编的叙事层，不负责游戏系统、数值平衡、关卡、UX、引擎或制作管理。对白、字幕和界面文本的语言修订交给 `line-editing-and-proofreading`；原创故事规划与诊断交给 `fiction-planning-and-diagnosis`。

## 10. 交付状态词

对作者交付只用这四个词，逐项给依据：

| 状态词 | 什么时候用 |
|---|---|
| 已完成 | 检查已执行，且有稿件内可核的证据支持 |
| 依据 | 交付时附的证据或稿件内可核位置（不是固定答案，也不是来源背书） |
| 未能核实 | 检查已执行，但结论依赖未核实的判断、设计假设或缺失的输入，或检查未执行；两者都不能记作已完成 |
| 待作者决定 | 存在冲突、取舍或锁定内容矛盾，由作者裁决，不擅自覆盖 |

§10 是包内交付状态词的唯一定义处。四词用于逐编号台账（`templates/adaptation-workbook.md` §7）与互动分支表（`templates/interactive-branch-sheet.md`）的状态列；两列都允许填「未知」作占位，但「未知」不是状态词，不得写成「已完成」。本轮未执行的检查归「未能核实」，并注明未执行及所缺输入。不把未验证的效果判断写成通过。

## 11. 失败出口

| 情形 | 出口 |
|---|---|
| 只有梗概，没有原作文本 | 只出方案草稿和梗概层分析；依赖原文的项标「未能核实」，写明需要补的输入；不编造场次或镜头问题 |
| 目标媒介未定 | 并列给出两套媒介的检查和各自代价，不替作者选；两套都不落稿 |
| 规则或取舍冲突、作者未裁决 | 按 `references/conflicts.md` 交付裁决备忘，停在「怎么判」的默认处理，标「待作者决定」，不替作者合并两案 |
| 缺版本、缺授权信息、缺目标平台规范 | 列出缺口清单与各自影响；能继续的部分标明假设往下做，被挡住的检查标「待作者决定」 |
| 要求照抄现成改编版或借用受保护表达 | 说明权利边界（AD-29），不复制具体表达；可继续分析结构功能，按作者的原作与授权范围独立设计 |
| 作者不答或只回「你看着办」 | 按最小改动处理，逐条列出所做的假设，不擅自扩大改动范围 |
| 问题出在原作的规划、结构、人物或句子层 | 停在改编层，按 §1 转介表转对应 skill |
| 生成或修订预设卡、按三轴审章节 | 转 `preset-card-generation` |

整条路径无法判定时（材料、目标媒介、授权三项都缺），改为交付问题清单和需要补的输入，不擅自改稿或出成品稿。

## 12. 适用与转介（按套件合同）

本 Skill 负责改编为舞台、影视、音频和互动形式；不负责小说本身的创作，也不负责预设卡。§1 列出全部转介去向，本节写重叠请求的分法和双向转介。

### 12.1 重叠请求怎么分（与本 Skill 相关的行）

套件合同的重叠请求表没有直接点名改编的行；与请求走向相关的是产物判断——产物是改编文档（改编合同、分场表、载体方案、裁决备忘）时留在本 Skill，产物是「给模型的卡」（推进卡、文风卡、表达约束卡）时转 `preset-card-generation`。

### 12.2 与 preset-card-generation 的双向转介

- 本 Skill → `preset-card-generation`：生成／修订／诊断推进模式卡、文风卡、表达约束卡；把改编的推进安排或表达约束写成推进卡给模型用；按推进／文风／表达三轴审章节。
- `preset-card-generation` → 本 Skill：改编为舞台／影视／音频／互动这类不写成卡、也不用三轴的请求。
- `character-and-narrative-control` → 本 Skill：改成舞台方案、分场稿、镜头。

### 12.3 双向对照

A 说转给 B 的地方，B 都要说接收什么；本 Skill 的转介行与 §12.2 两表互为逆关系。发现改编改动会推翻原作锁定的事实、关系或结局时，暂停该处并交作者确认。

### 12.4 与 genre-fiction-craft 的双向转介

- 本 Skill → `genre-fiction-craft`：改编中要回到某类题材的成立条件与桥段取舍时（这类题材内该不该兑现、禁忌怎么绕、读者预期是什么），交对方按题材规则判。
- `genre-fiction-craft` → 本 Skill：把作品改成舞台方案、分场稿或其他媒体形态的请求；对方只给题材规则，不给舞台形态。
