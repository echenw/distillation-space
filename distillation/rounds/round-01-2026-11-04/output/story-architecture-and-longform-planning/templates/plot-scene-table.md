# Scene Table（场景功能表）

**用法**：先看 §1 的字段清单（每个 ID 独占一行），再把事实填进 §2–§5 的工作表：每场/每章一行；先填事实，再判处置。`ST-06` 功能类型必须能指出 `ST-07` 后文调用点；指不出就不是“有功能”。不知道写 “未知”，不要留空。本表是人工工作纸，不含脚本、不自动判定。§1 各行的「填写」栏在对应工作表填完后回填该字段的结论摘要（或标 “未知”）；「状态」按 “已完成 / 依据 / 未能核实 / 待作者决定” 填，允许 “未知”，但不得把未知写成已完成；「稿件证据位置」只填用户当前稿件内的可核位置（如 “第 5 章第 3 场”），没有就填 “未知”，不指向来源编号或包外路径。

**作品/版本**：__________｜**范围**：第 __ 章–第 __ 章 / 第 __ 场–第 __ 场｜**填写人/日期**：__________

## 6. 功能类型图例（对应 ST-06）

| 代码 | 功能 | 判据 | 常见误判 |
|---|---|---|---|
| A 推进 | 场末局面与场初不同 | 有决定/揭示/关系变化/损失/获得 | 把“发生了动作”当推进；没有变化不算 |
| B1 铺垫 | 后文要用的物件/能力/信息 | ST-07 有明确调用点 | 埋了但后文不用 → 不是铺垫，是余赘 |
| B2 揭示 | 人物/世界信息 | 揭示后读者理解发生变化 | 重复读者已知信息 → 不是揭示 |
| B3 松气 | 高压后的缓解 | 前有高压、后有新压力 | 连续三场松气 → 节奏塌 |
| B4 主题回声 | 主题/意象/关系复现 | 后文有对应回声 | 只有作者觉得美 → 不是结构功能 |
| B5 时间跨越 | 压缩时间/空间 | 后文时间线需要 | 用总结代替场景 → 可能无戏 |
| B6 氛围 | 只提供情绪/感官 | 必须说明为什么不可删、后文是否调用 | 连续三场只有氛围 → C 类风险 |
| C 无功能 | 删掉后无一处需补写 | 删场测试通过 | 把“写得美”当功能 |

**完成检查**：`ST-01`–`ST-08` 每场有值；功能类型不是空白；后文调用点指不出的场已标 C 或“待定”；没有连续三场只写“氛围”；没有把“删掉后需要补写”误判为余赘；做了删场测试的场已进 §5 而不是只留在记忆里；`ST-01`–`ST-24` 各行的「填写／状态／稿件证据位置」已按 §1 口径回填或标 “未知”。
