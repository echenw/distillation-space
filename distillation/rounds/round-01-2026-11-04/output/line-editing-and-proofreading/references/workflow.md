# 多轮精修流程、台账与停手情形

返回 [SKILL.md](../SKILL.md)。中英文通用。

这套分轮流程是本 skill 的结构化编排，将各类语言规范划分为递进的执行轮次。

## 总则

1. **不覆盖原稿。** 在副本上改，或者给出修改建议；直接交付改稿时附改动清单。
2. **一轮一层。** 段落轮不顺手改标点，句子轮不顺手换词，标点轮不再动语序。混着改，出了问题就无法回退。
3. **每条修改说得出依据。** 依据是本 skill 的规则编号（SR 或 EN），或者明确写“编辑判断”。不把个人语感说成规则。
4. **拿不准就不改。** 两种读法都成立、作者意图不明时，保留原文并提问。“更顺”“更现代”不是充分理由。
5. **可以跳轮，但要说明。** 短稿可以合并第 1、2 轮；轻校对只做第 5 轮和明显的病句。
6. **停手是正常结果。** 作者对文本的决定权高于规则。

## 第 0 轮：定范围，建台账

1. 确认改动级别：只改错 / 句级精修 / 段级调整。整段重写超出本 skill，需要作者单独授权。
2. 确认体例：作者或宿主给了体例就照办；没有就采用“稿内统一”：以稿子里占多数的写法为准，体例分歧只列选项，不判对错（人名和专名除外，先问作者以哪个为准）。长稿先建体例表（见 [zh-mechanics.md](zh-mechanics.md)）。
3. 圈出不碰的部分：引文、专名、人物的口语和口头禅、作者刻意的破格写法。
4. 需要逐条审阅时建台账。**每个编号独占一行**，三列齐全，允许填「未知」：

   | 编号 | 值 | 状态 | 稿件证据位置 |
   |---|---|---|---|
   | `<规则编号，如 SR-10 / EN-27>` | `<这一项的值或待办>` | 已完成 / 依据 / 未能核实 / 待作者决定 / 未知 | `<当前稿件内可核位置，如「第 1 段第 2 句」；无则填「未知」>` |

   - 编号与规则一一对应，不合为一行；三列每行都在。
   - 「未知」是合法值，但不得把未知写成已完成。
   - 「稿件证据位置」只指向用户当前稿件，不指向来源编号或包外路径。
   - 表格必须有分隔行；有数据行却缺分隔行视为交付格式不合要求。
   - 填好的样例见 [worked-example.md](../examples/worked-example.md) 例三第 3 步。

5. 作者要保留的破格照留。可以说明它的代价（比如读者可能当成笔误），但不因为作者没有解释就改回去。

## 第 1 轮：段落

1. 给每段写一个短语，概括它讲什么（不是抄首句）。
2. 标出离题的句子和被切断的因果。
3. 按意思拆段或并段，不按字数。说明性段落缺主题句时再补；叙事段不强加。
4. 对白按说话人分段。
5. 单句段只在过渡、对白、制造停顿时保留；孤立的细节合并到相邻段落。

## 第 2 轮：句子骨架

中文按这几项检查：
1. **施事**：句首短语的施事和主语一致吗？（SR-03）
2. **成分**：缺不缺主语、宾语中心词？搭配对不对？有没有句式杂糅？（SR-04）
3. **辖域**：“只、都、不、也”管的是哪一部分？代词指谁？长定语要不要拆？（SR-05）
4. **语态**：被动是否符合这一段的主语？有没有双重被动？（SR-06）

英文按 EN-01–EN-04、EN-11 的五个测试：逗号成对、两侧能否独立成句、碎片是否回接、句首修饰语的施动者、关系从句删掉后指称变不变。EN-05 的并列检查在第 3 轮做。

## 第 3 轮：强调与节奏

1. 读每句最后几个字：是不是要读者记住的？不是就调序。（SR-07、EN-15）
2. 连续同型句只改一两句，改到单调消失为止。（SR-08、EN-38）
3. 并列结构补齐或删去重复的成分。（SR-09、EN-05）

## 第 4 轮：简洁与用词

1. 每删一处都问：意思、范围、语气变不变？不变才删。（SR-10、EN-24）
2. 固定冗语先替换，再检查有没有改掉限定或语气；对照表见 `en-word-choice-and-concision.md` EN-25。（SR-10、EN-25）
3. 抽象改具体只在原文支持时做；需要新事实时提问，不替作者编。具体化不能补写事实。（SR-11、EN-26、EN-27）
4. 套话按三类分别处理：错误的标出来，属确定错误的直接改，成语误用等先请作者确认（见 zh-mechanics.md）；不建议的列为建议，作者同意前不落稿；能用但陈旧的不必一律清除，作者要动时整句重写，重写后再过一遍第 2 轮的检查。（SR-12、EN-27）
5. 历史词形只作校勘候选；现代稿按项目当代词典与 style sheet 处理（EN-29）。

## 第 5 轮：机械校对

1. 先看体例；没有体例，就列体例选项。
2. 中文：全角半角、引号、对白格式、省略号、破折号、顿号、问叹号、书名号、的地得、数字、错别字、异形词，人名专名前后一致。（SR-13 至 SR-15）
3. 英文：插入语逗号、系列逗号、所有格、括号、引号、拼写变体、并列连词与括注的标点。（EN-01–EN-10、EN-34、EN-35）
4. 把“只是体例不同”的项单独列出，不算作错误。

## 第 6 轮：誊清与复核

1. 只落定作者接受的修改；拒绝的保留用户原句，待定的留在问题清单里。
2. 改动清单每条写：`位置 | 问题 | 改法 | 依据 | 风险或需作者确认`。
3. 通读一遍，检查意思、范围、人名、术语、数字、引文有没有被改动，改动有没有引入新的标点问题。
4. 按作者要的详略交付：只要正文就给正文，加一两句说明改了哪几类、还有哪些待定；要审阅就给逐条清单。

## 冲突裁决

先排除看起来冲突、其实有条件的情况：

- **被动**：EN-12 说嵌套被动可拆成主动结构，边界条款又说这不是“所有句子都改主动”，施事未知、无关或刻意隐藏时保留被动。执行“按段落主语选择”和“拆开双重被动”，不需要作者裁决。（EN-12、SR-06）
- **段落最后一句**：末句给出本段主题的重要后果，同时满足 EN-17 的段落中心和 EN-15 的句末强调。只有末句不属于本段主题时才要处理：说明性段落移走或改成过渡，叙事和高潮段按作者的效果目标。（EN-17、EN-15、SR-07、EN-40）

真正要作者决定的是这几类：作者的两条要求互相矛盾；指代或限制性从句两种理解都说得通；否定改肯定会改变强度（“不重要”≠“微不足道”）；没有房规的体例选择。处理方法：

1. 写冲突卡：`议题 | 规则 A | 规则 B | 为什么冲突 | A 版 | B 版 | 各自代价`。
2. 两版都是可以回退的最小改动；作者确认之前，哪一版都不落到正文里。只暂停这一项，其余修改照做。
3. 作者选定后，在台账里写“作者决定”，不写“规则要求”。作者已经选过的，不再重复问。

## 复杂操作：判断标准、步骤、诊断到修订的闭环

适用：多轮精修、冲突裁决、跨层改动这类不能一眼看出答案的操作。简单而没有分支的需求按对应轮次做即可，不走这一节。完整难例（含 A／B 分支、失败出口、负面回归）见 [worked-example.md](../examples/worked-example.md) 例三。

### 判断标准

动笔前先判三件事，任一判不出就停在问题清单，不开始改：

1. **落在哪一层**：句子层由本 skill 做；结构、场景、人物、视角、卡片请求判为负触发（SKILL.md §1.2、§10）。
2. **输入够不够**：有没有正文、体例、作者划的范围；缺哪样就先要，不凭空补。
3. **有没有冲突或取舍**：两条要求互相矛盾、两读都成立、需要补写事实，都算冲突，走 A／B 分支。

### 步骤

1. 先判负触发 → 2. 定范围（第 0 轮三件事）→ 3. 建逐编号台账 → 4. 按第 1–6 轮逐层改，一层一类 → 5. 每条改完立刻复查 → 6. 冲突项走 A／B 两版，停在待作者决定 → 7. 按四词状态交付 → 8. 负面回归。

### 诊断 → 修订闭环

每条修改都走一圈：`诊断（位置 + 问题 + 依据）` → `修订（最小可回退改动）` → `复查（意思 / 范围 / 语气 / 声口 / 事实 / 标点六项）` → `不通过就回退，改为建议`。任一项说不清，不进入下一层，也不带着疑问落稿。台账里每条写「改了什么 / 依据哪条 / 复查了哪几项」，复查项不齐全的不落稿。

### 负面回归

- 通读所有改过的句子，确认没有把口语、方言、意识流改成书面语，没有给断裂段补主语，没有添出天气、动作、物件或人物反应。
- 把不碰区遮住，确认本轮所有改动都落在允许改的句子里；落进去的撤销。
- 逐条核对「未能核实」「待作者决定」没有被写成「已完成」，每处改动都能对回原句，没有引入新的标点问题。
- 把这一轮暴露出来的新误判写进下一轮的复查项，避免重复出现；没有依据的地方写「没有依据，按作者判断」。

## 停手情形

遇到下面的情况，不再改，列出问题清单：`停在哪 | 为什么不能改 | 需要作者提供什么`。

| 情形 | 信号 | 处理 |
|---|---|---|
| 没有原文 | 只有要求，没有文字 | 请作者给出要改的文字；不凭空列错误 |
| 只有一句 | 看不出段落主题、指代和语气 | 先改这一句里能确定的错误；依赖上下文的判断写明“缺上下文” |
| 口语、方言、意识流、实验文体 | 作者要保留；对白里的碎句是节奏 | 只标出可能是笔误的不一致，其余不动 |
| 真正的冲突 | 见上面的冲突裁决 | 给两版，交作者选；其余照改 |
| 歧义 | 两种理解都说得通（英文的限制性从句也属此类） | 列出两种理解，请作者确认 |
| 体例分歧，没有体例要求 | 数字、对白标点、异形词、拼写变体写法不一 | 列体例选项，请作者定，或按稿内多数统一；各半分不出多数时先不改（总则 4）。人名和专名不适用“稿内多数”，一律先问作者 |
| 需要核实事实或改剧情 | 具体化需要原文没有的事实；问题出在人物、情节、视角 | 停在语言层；把问题转给对应的 skill |
| 要求打分、批量自动替换、裁定“唯一正确” | 作者要分数或全文自动改 | 说明本 skill 给的是逐条建议，不打分；批量替换只对确定的错别字和标点做，并先列出替换清单 |
