### D1 四个 `en-*.md` 的「规则与区分条件」怎么找回

## 二、S01 校准样例与写法口径（W3 全体复用）

> 本节是本轮核心交付。W3 其余 5 个代理处理各自 skill 的 P3 五件事时，以本节格式为准，可直接复用。成品里不出现本节的元说明，只出现按本节写出来的规则、例子、模板与状态词。

### §0 总原则（先记住这五条）

1. **只找回规则本体**：区分条件、反例、检查项、失败出口、模板字段。缩减幅度是盘点信号，**不是应补回的量**。
2. **三类不算丢失**：后版有意的口径调整、后版已改正的事实错误、只属于某一部作品的情节和史实。逐条排除并在分片记录写理由。
3. **出处只留 notes**：书名、作者、作品人物／情节／设定、原句、来源编号、年代、篇数、包外路径一律不进成品；出处只写在决策链的「来源」小项与分片记录。
4. **例子一律自创、通用**；自创例子要与来源案例比情节骨架（人物关系 + 关键事件 + 时代地点），三项有两项以上对得上就重写。
5. **没有依据就写「没有依据，按作者判断」**，不编造阈值、数字或成体系的反例；不在没有决定记录的情况下删基线版本的内容。

### §1 找回一条规则时的通用改写格式

**标准条目模板**（照抄这个骨架，填入本 skill 的规则编号）：

```
## <规则编号> <规则名>

- **规则**：一句话说做什么；不提来源、年代、「书里说」。
- **用于**：2–4 个适用信号，每个都能肉眼判断。
- **怎么做**：2–4 步，每步有判断动作，并写明「什么时候停」。
- **不用**：2–4 个区分条件／例外，写清「为什么不该改」。
- **反例**：1–2 个自创例子，指出错在哪、怎么判（不是只列错句）。
- **检查**：改完复查哪几项；复查项不齐全不落稿。
- **自拟例**：1 个自创正例。
- **出口**：拿不准 / 缺料 / 冲突时停下、问作者或转介，写清停在哪。
```

**改写口径**：

- 保留基线版本现有的编号与行标签，**在现有条目后补缺失小块**，不从更早版本搬编号回来；删除或改号都要在分片记录里有决定。
- 更早版本里的「断言 / 用于 / 不用 / 做法 / 记录 / 反例 / 可信度」→ 通用化为「规则 / 用于 / 怎么做 / 不用 / 反例 / 检查 / 自拟例 / 出口」。
- **必须删掉**：可信度、置信、书中明说 / 书里未提、两说、未证实、不采纳、来源编号与行号、年代词表、条目表、出处链接、「按某书」的背书句。
- **优先合并，其次新增**：确实丢了一整条规则主题、合并会走样时才新增条目，编号接现有序列往后排，逐条写决定；不要为了凑数新增。
- 成品里**不解释编号来历**：不写「补回的条目」「编号续排」「已有编号不变」「旧版 / 本版 / 更正 / 融合版」「不是任何作品的原文」。这些是改动痕迹，附录 B #8 与红线都禁。
- 每条规则都要有「不用」和「出口」；只有「怎么做」没有区分条件的，等于没找回。

**校准正例**（本轮实际写法，见 `en-mechanics-and-punctuation.md` EN-01）：规则一句 → 用于（同位语、短评插入语、日期年份、单边逗号）→ 怎么做（删除测试 + 选标记 + 句首句尾不机械补逗号）→ 不用（限定从句误判、停顿不等于插入语）→ 反例（自拟单边逗号句 + 错在哪）→ 检查 → 自拟例 → 出口（两版停在待作者决定）。

**校准反例**：把更早版本的 `**断言**：……（L948–949）` 直接改成 `**规则**：书内紧接着说……` —— 既留了出处，又留了背书；必须整句重写成不带主语来源的通用陈述。

### §2 自创例子的写法

- **自创的定义**：自己编的通用情境，人物、物件、场景都普通；不出现书名、作者、作品人物／情节／设定、原句、来源编号、年代、篇数。
- **骨架比对**：人物关系 + 关键事件 + 时代地点三项，与来源案例有两项以上对得上就重写（附录 B.3）。
- **英文例句**：用单个自拟人名（避免连续两个首字母大写词，会命中 #5b）、日常名词、普通动作；**不抄来源书里的原句**（如带具体人名、船名、城市名、剧名的整句）。
- **反例要写「错在哪 + 怎么判」**：`自拟 X。错在……；应为……`。只列错句不算反例。
- **固定对照表**：每一行都自创，表头注明「表中表达都是为说明而自创的通用搭配」；要恢复的是「可压缩 + 采用前复检」这条规则，不是抄具体搭配。
- **具体化例子必须带证据前提**：写「前提：原稿前文已给出……」；证据不足时标「未能核实」，并写「**具体化不能补写事实**」。整句重写改变的是观察角度，不是事实清单。
- **每个自创例都要能回答三问**：改完有没有添事实？有没有改声口？有没有添出天气／动作／物件／人物反应？
- **不编造阈值、数字或成体系的反例**：「连着几句」「只改一两句」是提示，不是硬指标；不写「不超过 N 词」「必须 N 句」。

### §3 负触发示例的写法（L-1 口径）

完整示例的**七步结构**（见 `examples/worked-example.md` 例三）：

1. **第 1 步：先判负触发**（必须在动笔之前）。用表格逐条判请求里的每一句：`请求里的一句 | 判成什么 | 依据 | 处理`。把「不接、转介、停下」写在最前面。
2. **第 2 步：定范围**（第 0 轮三件事：改到什么程度 / 按什么体例 / 哪些不能动）。
3. **第 3 步：逐编号台账**（§4 的模板行）。
4. **第 4 步：诊断 → 修订闭环**（`诊断 → 修订 → 复查 → 不通过就回退`）。
5. **第 5 步：A／B 分支与失败出口**。
6. **第 6 步：交付**（四词状态，逐项给依据）。
7. **第 7 步：负面回归**。

**判负触发三问**：落在哪一层（句子层才接）／输入够不够（正文、体例、范围）／有没有冲突或取舍。

**必写要素**：

- 转介要写全**会转去的兄弟 skill 名**，含 `preset-card-generation`；`description` 也要写全同一批名字。
- **失败出口**不能只写「问作者」：要写「作者不答或只回『你看着办』时，按最小改动处理，逐条列出所做的假设，不擅自扩大改动范围」。
- A/B 两版都是可回退的最小改动，**作者选定前哪一版都不落稿**，其余不冲突的修改照做。
- 示例里不出现真实作品、审计词、状态码、分档词。
- SKILL.md 里也要有对应的**负触发清单**和**失败出口表**，并用路由表指向完整示例。

### §4 状态词与模板行的用法

**四词状态词**（对作者交付只用这四个，逐项给依据）：

| 状态词 | 什么时候用 |
|---|---|
| 已完成 | 检查已执行，且有稿件内可核的证据支持 |
| 依据 | 交付时附的证据或稿件内可核位置（不是固定答案，也不是来源背书） |
| 未能核实 | 检查已执行，但结论依赖未核实的判断、设计假设或缺失的输入，不能记作已完成 |
| 待作者决定 | 存在冲突、取舍或锁定内容矛盾，由作者裁决，不擅自覆盖 |

- **只留 notes、不进成品**：`PASS/FAIL/NOT_PROVEN/STATIC_CHECKED/NOT_RUN/DESIGN_EXAMPLE/OBSERVED/BLOCKED/NOT_APPLICABLE`、`GQ1–5`、`R17/R18`、`F/H/P`。
- **不进成品的措辞**：「硬规则」「用户明确要求」「融合版」、分档／评级词、旧版／本版／更正等改动痕迹、「经典做法是……」「很多名作都……」这类借来源背书。
- 不把「未能核实」「待作者决定」写成「已完成」；不把未验证项写成通过。

**模板行（R18 §2a）**：每个编号独占一行，四列齐全，允许「未知」。

```
| 编号 | 值 | 状态 | 稿件证据位置 |
|---|---|---|---|
| <规则编号，如 SU-02 / EN-27> | <这一项的值或待办> | 已完成 / 依据 / 未能核实 / 待作者决定 / 未知 | <当前稿件内可核位置，如「第 1 段第 2 句」；无则填「未知」> |
```

- 编号与规则一一对应，**不合为一行**；三列每行都在；「未知」合法，但不得把未知写成已完成。
- 「稿件证据位置」只指向**用户当前稿件**，不指向来源编号、包外路径或批次。
- 表格必须有 **GFM 分隔行**；有数据行却缺分隔行视为交付格式不合要求。
- 填好的最小样例：

| 编号 | 值 | 状态 | 稿件证据位置 |
|---|---|---|---|
| SR-10 | 「……的时候」冗余，删 | 已完成 | 第 1 段第 1 句 |
| EN-27 | 「每句都更有力」是否覆盖方言段 | 待作者决定 | 作者要求与原稿第 2 句 |
| SR-11 | 是否补一处可见细节 | 未能核实 | 未知 |

### §5 去来源后如何通读改过的句子

**顺序**：先把规则改写成通用陈述，再删出处 → **删完逐句通读** → 跑附录 B 全 11 类正则（`/usr/bin/grep -rnE`，本机 grep 是 ugrep，中文长模式会报错）→ 命中逐条判断 → B.3 人工回读 → 复扫 → 相对链接与表格分隔行校验。

**通读四查**：

1. **主语／宾语有没有悬空**：删掉「书里说」「据……」之后，句子还通不通；有没有只剩半句。
2. **有没有删除残迹**：空括号 `（）`、悬空的「见，」「据，」、表格空列、只剩连线的行。
3. **背书有没有改成条件**：「经典做法是……」「很多名作都……」改成「适用条件与限制」；「书中明说」改成不带主语的规则陈述。
4. **例子有没有换干净**：自创例子里有没有混入来源案例的人名、物件、场景、原句。

**命中不等于违规**（本轮实测）：

- 正则固有误报：「依据，」「证据。」「常见，」会命中 #10 的 `据[，。；]` / `见[，。；]`；讲标点用法时列举的 `（）` 会命中 #10 的空括号；自创英文直接引语（引号内 5 词以上）会命中 #6。逐条读原句、写明理由、按 B.3 判允许，**不要为了零命中而改坏语义**。
- B.2 允许情形必须写明理由：用户自己的稿件「原文／原稿／原作／原著」、用户稿件版本号（`v1→v2`）、本包内部编号、自创例子里的年份、事实核验场景里的「来源／出处／引语」。
- 可以顺手消除的命中（元说明里的「出自」「批次」、禁用词列举句、连续首字母大写词的自创人名）改掉更干净，但**「没有依据，按作者判断」这类固定说法不能为躲正则而改写**。

**收尾四条**：

1. 附录 B 复扫零违规（或每条命中都有允许理由）。
2. 成品里零改动痕迹（不写补回／续排／已有编号／本版／旧版／更正／融合版）。
3. 所有相对链接能解析，含数据的表格都有分隔行。
4. 结果写进**自己的分片记录**，摘要回传 Agent 1 汇总进 `desourcing-ledger.md`；**不写公共 ledger**，不写 `log.md`（由 Agent 1 统一追加）。
