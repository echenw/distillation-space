承载位置：本文件同时是 R18 §2 的行为合同与 R18 §4 的六问表（唯一权威，不另建平行文件；落位裁定见 `checklist.md` §二十三）。成品包＝`output/cross-media-drama-adaptation/`，13 文件 897 行。

## 一、四个任务群的最小可执行行为合同

### 1. 改编可行性判断与改编合同（AD-01 至 AD-06）

- **触发**：作者给出原作文本或范围＋目标媒介，问「能不能改」「改成这样要不要丢什么」。
- **负触发**：漫画格序与页面节奏、制式软件的排版规范、按平台流量调节奏、只要票房或流量判断（`SKILL.md:23-26`）；产物是给模型用的卡（`SKILL.md:28`）→ 转 `preset-card-generation`。
- **输入权限**：F＝作者确认的原作范围、目标媒介、必须保留项、授权与制作条件；H＝由文本推断的观众感知通道与功能转换方案；P＝媒介通道两可时的并列两套方案（`SKILL.md:158`）。三者在交付里分开标，作者锁定的事实、关系和结局不得由 H 覆盖（`SKILL.md:50`）。
- **步骤**：`SKILL.md:58-63` 六步（定材料与授权 → 写改编合同 → 按问题选规则 → 最小转换 → 回看受影响部分 → 交付实际改编）；判断某场景是否依赖语言走 AD-02（`SKILL.md:105`），关键事件能否不直接演出走 AD-06（`SKILL.md:109`）。
- **输出与归属**：改编合同、采用的规则编号、保留与改变的内容（`SKILL.md:67`）；模板＝`templates/adaptation-workbook.md` §1（`:5`）。
- **失败出口**：只有梗概时只做梗概层判断，不声称完成改编诊断（`SKILL.md:49`、`SKILL.md:210`）；媒介未定时并列两套代价、两套都不落稿（`SKILL.md:211`）。
- **证据**：AD-01 至 AD-06 的条件与反例在 `references/transferability.md`；「需要时补读」两列见 `SKILL.md:158`。

### 2. 分场、连续性与信息载体诊断（AD-07 至 AD-22）

- **触发**：作者给出分场稿或剧本，指出场景单位混淆、换地点像瞬移、回切跑题、字幕过多、信件进不去、结局生硬。
- **步骤**：先定本项目的「场」定义（AD-07，`SKILL.md:113`）→ 逐场核对移动、时间、回切（AD-08 至 AD-11）→ 再判信息载体（AD-13 至 AD-17，选载体步骤在 `references/information-carriers.md`）→ 最后回到因果与高潮（AD-18 至 AD-22）。片长与场数不是历史门槛，按媒介、平台、预算、体裁和场景功能定（AD-12，`SKILL.md:118`；`SKILL.md:176` 禁止把历史制作数字当现行规则）。
- **判断标准**：地点是否保留取决于它是否带来新信息、关系或行动条件；节奏能压多快取决于该场景要成立的效果需要多少停留（喜剧看笑点有无反应时间、悬念看关键信息有没有被看见、抒情看情绪有无落点），三条见 `references/conflicts.md:21`。这不是抽象口号，是可观察事实：同一场里快切与停留冲突时试排两版，比较信息是否看得懂、空间是否连贯、情绪是否成立。
- **输出**：问题与修改单（workbook §4，`templates/adaptation-workbook.md:31`）、分场表（§3，`:23`）、逐编号台账（§7，`:51`）。
- **失败出口**：场类定不下来时列两种定义各自的结果，停在待作者决定（`SKILL.md:159`）；缺正文不判连续性错误（同处）；载体都承担不了时提结构调整方案（`SKILL.md:160`）。

### 3. 舞台与画面落地（AD-23 至 AD-34）

- **触发**：作者要排练可行性、走位、群众调度、布景灯光成本、构图与运动方向。
- **边界**：先区分必须执行的机械信息、氛围建议、可供导演选择的解释三类文本（AD-23，`SKILL.md:138`）；静止也可以是有效调度（AD-24，`:139`）；不设固定人数与固定周数（AD-25 `:140`、AD-28 `:143`）；视觉警示是风险清单不是硬禁令（AD-33，`:151`）。
- **失败出口**：排练与制作条件未知时只给与文本相关的部分，其余标需核验（`SKILL.md:162`）；镜头执行参数属现实制作事实，标需专业核验、不在本包下结论（`SKILL.md:163`）；法律与许可不给结论（AD-29，`SKILL.md:144`；`SKILL.md:178`）。

### 4. 互动叙事改编（AD-35 至 AD-40）

- **触发**：目标媒介是互动叙事。开工先整篇读 `references/interactive-adaptation.md` 并用 `templates/interactive-branch-sheet.md`（`SKILL.md:182`）。
- **步骤与依赖事实**：先固定不变量（核心承诺、不可随意改写的因果、人物约束、玩家位置，`interactive-adaptation.md:5-14`）→ 每个选择先分类（表达型／状态型／路线型，`:20-25`）→ 状态变量五要素（含义、初始条件、写入事件、读取节点、失效或重置，`:30-38`）→ 分支图与回收（入口、触发、选择、状态变化、即时与延迟后果、下一节点，`:42`）→ 玩家知识与角色知识分两轨（`:65-70`）→ 反馈对应真实变化（`:74`）。
- **判断标准**：无后续影响的选项不得包装成重大分歧（`:26`）；同一叙事事实只保留一个权威状态，不在多节点维护互相矛盾的「信任值」「是否知情」副本（`:38`）；回收前必须处理分支已造成的关系、知识和承诺差异，不得无解释抹平（`:42`）。
- **负边界**：不交付战斗与经济系统、数值平衡、关卡、成长曲线、商业化、引擎、界面规范、可访问性与制作预算（`:89`）；这些列为外部依赖。
- **失败出口**：平台规范或结局未定时，被挡住的检查标「待作者决定」，先补输入（`SKILL.md:165`）；「没执行」与「被缺失输入挡住」是两种情形，区别写进「证据或限制」列（`interactive-adaptation.md:59`）。

## 二、会失败的真实输入、保护分支与后续验证

1. **只有梗概，要求「逐场列出镜头问题」**。失败形态＝编造场次与镜头号填满交付。保护分支＝`SKILL.md:49` 与 §11 首行 `SKILL.md:210`：只出梗概层分析与方案草稿，依赖原文的项标「未能核实」并写明需补的输入。后续验证＝K4 隔离回读时检查交付里是否出现稿件里不存在的场号或镜头号；出现即 FAIL。
2. **要求照抄某个现成改编版**。失败形态＝逐镜头复制受保护表达。保护分支＝`SKILL.md:27`（AD-29）＋ `examples/adaptation-cases.md:42`：先确认权利与授权范围，授权不明确就不复制具体表达，可继续分析其结构功能并按作者提供的原作与授权独立设计。后续验证＝交付里若含逐句对应现成版本的段落即 FAIL；本 Skill 不给法律结论（`SKILL.md:178`）。
3. **「改成互动叙事，多加几个选项」**。失败形态＝把选项数量当改编完成，且为造分支让人物违背既有目标或知识。保护分支＝`SKILL.md:182`「不得把增加选项当作完整改编」＋ `interactive-adaptation.md:26`（无后续影响的选项不得包装成重大分歧）＋ `:76`（agency 受人物与世界规则约束）。后续验证＝逐条看每个选项能否指出状态变化或路线后果；指不出的应降级为表达型，仍包装成分歧即 FAIL。
4. **作者已锁定结局，又要求「结尾更震撼」**。失败形态＝临时加灾难或把悲剧当更高级的结尾。保护分支＝`references/conflicts.md:28`（悲剧或失去须前文已建立代价，不能只为冲击临时增加灾难）＋ 裁决备忘默认处理与「两案不合并、不替作者各取一半」（`conflicts.md:68`）＋ 冲突顺序把改编合同与权利排在个人偏好之前（`SKILL.md:172`）。后续验证＝交付应含裁决备忘八项（`conflicts.md:57-66`）与「待作者决定」，且只暂停该冲突及其直接依赖部分，其余照改。
5. **要求「内心独白全部保留，又不许用旁白」**（`examples/adaptation-cases.md:44` 用例 E）。失败形态＝机械保留形式或悄悄塞画外音。保护分支＝AD-27 只约束舞台 aside 且叙述性旁白不归它管（`SKILL.md:142`），叠加 `SKILL.md:212`（作者未裁决时停在「怎么判」的默认处理）。后续验证＝A／B 两案是否都写明条件、收益、代价与被暂停范围。
